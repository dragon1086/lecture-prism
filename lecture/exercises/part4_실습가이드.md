## 사전과제 (파트 3 수강 후 준비)

```
나의 매매 이론 3줄:
1. 진입 조건: _______________________________
2. 청산/목표가: ______________________________
3. 리스크 관리: _____________________________

예시)
1. 진입: RSI 30 이하 + 거래량 3배 이상 동시 충족
2. 청산: +15% 목표가 또는 -7% 손절
3. 리스크: 최대 5종목, 현금 50% 유지, 매수 점수 6점 이상
```

전략을 잘 정리하지 못해도 괜찮습니다. `MY_STRATEGY.md`에 대충 적거나, 코딩 에이전트에게 말로 설명한 뒤 아래 프롬프트를 입력하세요.

```text
MY_STRATEGY.md를 읽고 내 전략을 lecture-prism에 반영해줘.
내 설명이 부족하면 네가 먼저 합리적으로 정리하고, 진짜 꼭 필요한 질문만 하나만 해줘.
처음에는 Part 4 트랙 A/B/C/D 중 가장 안전한 것 하나만 골라서 수정해줘.
수정 후에는 API 키 없이 데모 모드로 실행 검증하고, 수정 전후 차이를 초보자도 이해하게 설명해줘.
실거래는 절대 하지 마.
```

## 수정 트랙 선택 (CH1 · 기존 시스템 수정 템플릿 소개) — 사전과제 3줄이 그대로 템플릿

> 강의에서 부르는 "수정 템플릿"이 아래 트랙 A~D입니다. 준비해온 이론 중 하나를 골라 해당 트랙만 고칩니다.

| 트랙 | 사전과제 항목 | 내용 | 대상 파일 | 난이도 |
|------|------|------|----------|--------|
| **A** | 진입 | 기본 데모 후보 조건·상수 (심화: `ScreeningStrategy` plugin) | root `screening.py` | ★☆☆ |
| **B** | 진입 | LLM 연결 시 분석 프롬프트 | `analysis.py` | ★☆☆ |
| **C** | 청산 | 매도·목표가·트레일링 스탑 | `trading.py` (`_decide_exit`) | ★★☆ |
| **D** | 리스크 | 보유 종목 수·현금·매수 점수 | `trading.py` (상수) | ★☆☆ |
| 심화 | — | 데이터 소스 추가 / 뼈대부터 구현 | `analysis.py` / `blank_pipeline.py` | ★★★ |

> 준비해온 이론 3줄 중 **하나만** 골라 구현하면 오늘은 성공. 진입은 A·B, 청산은 C, 리스크는 D. 처음 전략을 바꾸는 수강생은 root `screening.py`의 Track A부터 시작합니다. `prism_core/screening.py`의 `ScreeningStrategy` plugin, 섹터별 보유 제한, 부분청산은 classroom·paper/live의 상세 흐름까지 검증할 때 고르는 **심화 선택지**입니다.

## 대표 예시 — 시황 필터가 들어간 터틀 추세추종

수업에서는 아래처럼 여러 트랙이 섞인 전략도 다룹니다. 다만 한 번에 전부 바꾸지 않고, **한 트랙씩 수정 → 데모 검증 → 전후 비교**로 진행합니다.

```
나의 매매 이론 3줄:
1. 진입: 터틀 추세추종처럼 20일 신고가 돌파 종목을 본다. 단, 코스피 흐름이 너무 나쁘면 진입을 줄인다.
2. 청산: ATR 기준 손절과 트레일링 스탑으로 추세가 꺾이면 빠져나온다.
3. 리스크: 장이 좋을 때는 비중을 키우고, 장이 나쁠 때는 현금을 더 남긴다.

추가 판단:
- 뉴스, 공시, 유료 리포트 캡처처럼 숫자로 정형화하기 어려운 내용은 AI가 보조 판단한다.
```

### 이 전략을 트랙으로 나누면

| 순서 | 트랙 | 맡길 일 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | A | 20일 신고가·거래대금·시장지수 필터 | 먼저 어떤 종목을 볼지 정해야 함 |
| 2 | C | ATR 손절·트레일링 스탑 | 추세추종은 "언제 나올지"가 핵심 |
| 3 | D | 시장국면별 현금 비중·포지션 크기 | 수익률보다 수익금을 키우는 부분 |
| 4 | B | 뉴스·공시·리포트 해석 프롬프트 | 정량 신호를 보류/강화하는 판단 레이어 |

### 코딩 에이전트에게 처음 맡길 때

```text
내 전략은 시황 필터가 들어간 터틀 추세추종이야.

진입: 20일 신고가 돌파와 거래대금 증가를 보고, 코스피 흐름이 나쁘면 후보를 줄이고 싶어.
청산: ATR 기준 손절과 트레일링 스탑을 쓰고 싶어.
리스크: 장이 좋을 때는 비중을 키우고, 장이 나쁠 때는 현금을 더 남기고 싶어.
비정형 자료: 뉴스, 공시, 유료 리포트 요약을 사람이 붙여넣으면 AI가 보유/매도 판단에 참고했으면 해.

한 번에 전부 바꾸지 말고, Part 4 트랙 A/B/C/D로 나눠서 순서를 정해줘.
이번에는 가장 안전한 첫 트랙 하나만 수정하고, API 키 없이 데모 모드로 검증해줘.
실거래는 절대 하지 마.
```

> "강화학습처럼 계속 좋아지나요?"라고 느낄 수 있습니다. 이 수업에서는 정통 강화학습을 구현하지 않습니다. 대신 매매일지와 피드백을 남기고, 반복되는 실수와 성공 패턴을 다음 프롬프트와 참고자료에 반영하는 **기억 루프**를 보여줍니다.

## 실전 프롬프트 공식 (CH2 · 강사 라이브 시범)

> 트랙을 직접 고치기 전에, **AI에게 코드를 맡기는 "프롬프트 공식"**을 먼저 익힙니다.
> 같은 요청도 어떻게 말하느냐에 따라 결과가 갈립니다.

### 핵심 공식

```
[현재 상태] + [원하는 결과] + [유지할 제약]
```

- **현재 상태**: 지금 코드가 무엇으로 되어 있는지 (파일·상수·함수명까지)
- **원하는 결과**: 무엇으로 바꾸고 싶은지 (구체적 숫자·조건)
- **유지할 제약**: 깨지면 안 되는 것 (함수 이름·입출력 형태, 나머지 구조)

### Bad vs Good

| ❌ Bad | ✅ Good |
|---|---|
| "코드 좀 고쳐줘" | "현재 screening.py는 거래량 5배 기준이야. RSI 30 이하 + 거래량 3배로 바꿔줘. 함수 시그니처는 유지해줘." |

### 자주 쓰는 3가지 패턴

> 아래 사례는 강사가 PRISM을 1년 운영하며 코딩 에이전트에게 **실제로 보낸 프롬프트**입니다 (일부 축약).

**① 수정 요청** — 현재 상태 + 원하는 결과 + 유지할 제약
```
강사 실제 사례 (2026-01, 매수/매도 에이전트 프롬프트 튜닝):
"아래 요구사항에 대한 계획과 실행을 진행해줘. 기존 에이전트 프롬프트의 결을
완전히 벗어나지 않으며, 과도하게 프롬프트를 증가시키지 않으며,
과적합을 주의하며 프롬프트를 수정하면 돼."

(틀) "현재 ___는 ___야. ___로 바꿔줘. ___는 유지해줘."
```

→ 포인트: 바꿀 것(요구사항)보다 **지킬 것(결·분량·과적합 주의)을 더 길게** 적었습니다. 제약을 명시하면 AI가 멋대로 '개선'하지 않습니다.

**② 에러 해결** — 에러 메시지를 그대로 + 원인 설명 요청
```
강사 실제 사례 (2026-01, 배치 파이프라인 장애):
"오케스트레이터를 돌리는데 '6. Tracking system batch' 단계부터 에러가 나서
실제 매수/매도 에이전트가 잘 안 돌아가. 최근에 데이터 라이브러리를
교체했는데 거기서 문제가 발생한 것 같아."

(틀) "이 에러가 났어: [에러 메시지 붙여넣기]. 원인 설명하고, 고친 뒤 같은 실행을 다시 검증해줘."
```

→ 포인트: 증상(어느 단계에서 났는지) + **최근에 무엇이 바뀌었는지**를 같이 줬습니다. AI가 원인을 넘겨짚지 않게 하는 가장 싼 방법입니다.

**③ 이론-코드 갭 점검** — 내 이론 vs 코드(AI 동작) 일치 확인
```
강사 실제 사례 (2026-01, 매수 기준 완화 후 점검):
"저번에 너랑 같이 강세장에 대해 매수 기준을 완화했어. 그 이후 며칠 더
지켜본 결과, 모델이 오히려 점수를 6점 줄 것을 5점 주는 식으로
손실회피를 억지로 하고 있는 느낌을 받았어."

(틀) "이 코드가 내 이론을 정확히 반영하는지 확인해줘. 내 이론: ___"
```

→ 포인트: 수정이 '돌아간다'에서 끝내지 않고 **실제 결과를 며칠 관찰한 뒤 의도와 다른 동작을 근거로 재점검**시켰습니다. 여러분의 "전후 비교"가 바로 이 습관의 시작입니다.

> 트랙 A~D는 **CH3(수강생 실습)**에서 이 공식을 직접 적용하는 부분입니다.

## 트랙 A — 스크리닝 조건 수정

**목표**: root `screening.py`의 간단한 후보 조건·상수를 본인 이론으로 교체

기본 데모가 실제로 쓰는 값은 `VOLUME_SURGE_RATIO`, `MIN_MARKET_CAP_KRW`, `MOMENTUM_DAYS`, `MAX_CANDIDATES`입니다. 이 값과 `_filter_candidates()`의 간단한 조건을 바꾸면 API 키 없이도 후보 종목이 달라지는 것을 볼 수 있습니다.

처음에는 root `screening.py`만 고칩니다. `run_screening() -> list[str]` 형태와 `main.py` 파이프라인은 유지합니다.

### 코딩 에이전트 프롬프트

```text
root screening.py의 기본 스크리닝 조건을 내 이론으로 바꿔줘.
내 이론은 RSI 30 이하 반등 + 거래량 3배 + 중형주 이상이야.
VOLUME_SURGE_RATIO, MIN_MARKET_CAP_KRW, MOMENTUM_DAYS, MAX_CANDIDATES 같은 상수와 _filter_candidates() 안의 단순 조건만 우선 검토해줘.
run_screening()의 입력과 list[str] 반환은 유지하고, API 키 없이 데모 모드로 전후 후보가 달라지는지 검증해줘.
실거래는 절대 하지 마.
```

### 검증

```text
바꾼 screening.py가 내 이론을 정확히 반영하는지 확인해줘.
수정 전후로 어떤 종목이 통과/탈락하는지 표로 비교해줘.
API 키 없는 데모 경로가 끝까지 도는지도 확인해줘.
```

### 심화 선택 — 상태 저장형 ScreeningStrategy plugin

```text
기본 Track A가 끝난 뒤, prism_core.screening의 ScreeningStrategy protocol을 구현하는 상세 plugin도 만들어줘.
classroom fixture에서 bull 통과·bear 거절 사례를 검증하고, root run_screening() 호환은 유지해줘.
paper/live나 브로커 주문은 건드리지 말고 실거래는 절대 하지 마.
```

### Track B/C/D가 유지할 core contract

- Track B는 LLM 연결이 있을 때만 프롬프트 변경 효과가 보입니다. 정량 점수·가격 규칙을 프롬프트가 마음대로 우회하지 않습니다.
- Track C는 청산 규칙을 바꿔도 손절·트레일링·목표가 각각의 전용 시나리오로 증명해야 합니다.
- Track D 기본 실습은 root `trading.py`가 실제로 쓰는 `MAX_SLOTS`, `CASH_RESERVE_RATIO`, `BUY_SCORE_THRESHOLD`만 약속합니다.

walk-forward는 각 시점의 과거만 보고 다음 구간을 평가합니다. 미래 데이터를 후보 점수나 regime 판정에 섞으면 결과를 믿을 수 없습니다. 종목 목록도 첫 판단일에 알고 있던 point-in-time universe snapshot이어야 하며, 오늘의 구성 종목을 과거에 소급하는 survivorship bias는 허용하지 않습니다. 이 보고서는 전략·regime 궁합의 교육용 증거이며 **수익 보장 아님**입니다. live 활성화는 이 결과와 별개의 provider fail-closed, 브로커, 이중 안전 플래그를 모두 확인하는 별도 gate입니다.

## 트랙 B — 분석 프롬프트 교체

**목표**: LLM을 연결한 뒤 `analysis.py`의 `TECHNICAL_AGENT_PROMPT`를 본인 이론으로 교체

> 📌 `analysis.py`는 원본 PRISM처럼 **6개 섹션**(기술·수급·재무·산업·뉴스·시장)을 만듭니다.
> 이 중 **수급·재무·산업·시장은 규칙(실데이터 지표)**, **기술·뉴스·리스크의 정성 서술은 종목당 한 번의 구조화 LLM 호출**이 담당합니다. 추천·점수·목표가·손절가는 규칙이 소유하며, LLM은 BUY를 HOLD로만 veto할 수 있습니다.
> 트랙B가 바꾸는 건 기술·뉴스 관점이 담긴 정성 프롬프트이며, 정량 gate를 우회하는 전략 에이전트가 아닙니다.

> ⚠️ **중요 — 프롬프트 변경 효과는 LLM을 연결해야 보입니다.**
> OpenAI API 키/공식 Codex 구독 로그인(파트3 CH1)이 **없으면** 기술 섹션은 실데이터 지표 템플릿(또는 더미 응답)으로 나오고,
> 프롬프트를 바꿔도 출력이 **그대로**입니다. 트랙B를 제대로 실습하려면 **LLM 연결이 사실상 필수**입니다.
> LLM을 쓰지 않는 수강생은 트랙 A·C·D를 고르거나, 트랙B에서는 "코드/mock 완성"까지만 받으세요.

### Claude Code 프롬프트

```text
현재 analysis.py 기술적 분석 에이전트는 CANSLIM 기반이야.
내 이론: 볼린저 밴드 하단 터치 + RSI 과매도 반등으로 바꿔줘.
LLM 연결이 없으면 출력 변화가 안 보일 수 있다는 점을 먼저 확인해줘.
TECHNICAL_AGENT_PROMPT만 수정하고 나머지 구조는 그대로 둬.
API 키 없는 데모에서는 코드/mock 완성 여부만 검증하고, 실거래는 절대 하지 마.
```

### 프롬프트 품질 검증 (LLM 연결 상태에서)

```text
LLM을 연결한 상태에서, 이 프롬프트로 삼성전자를 분석하면
기술 섹션이 어떻게 달라지는지 수정 전후로 실행해서 비교해줘.
LLM이 연결되지 않았으면 결과 변화가 없다고 명확히 말하고, A/C/D 중 하나를 추천해줘.
```

### 결과 제출 (선택) — 본인 이름 브랜치로 push

GitHub 제출은 선택입니다. 오늘의 성공 기준은 먼저 “내 전략이 데모 모드에서 실행되는 것”입니다. 제출이 막히면 화면 공유나 결과 캡처로 대체해도 됩니다.

직접 Git 명령어를 치지 말고 코딩 에이전트에게 아래처럼 맡기세요.

```text
내 실습 결과를 제출할 수 있게 Git 작업을 도와줘.

조건:
1. 현재 변경 파일을 먼저 보여주고, API 키·토큰·DB 파일 같은 민감한 파일이 포함되어 있지 않은지 확인해줘.
2. main 브랜치가 아니라 내 이름 브랜치에서 작업하게 해줘. 브랜치 이름은 [본인이름-영문] 으로 해줘.
3. 변경 내용을 커밋해줘. 커밋 메시지는 "내 전략 적용"으로 해줘.
4. 원격 저장소에 내 이름 브랜치를 push해줘.
5. push가 실패하면 collaborator 권한 문제인지, 로그인 문제인지, 원격 저장소 문제인지 구분해서 설명해줘.

위 과정에서 필요한 Git 명령은 네가 실행하고, 각 단계 결과를 나에게 확인시켜줘.
```

> 푸시가 안 되면: 강사에게 collaborator 초대를 받았는지 확인. 자세한 흐름은 루트의 `README.md` 참고.
> 화면 공유가 기본 — 푸시는 원하는 사람만.
