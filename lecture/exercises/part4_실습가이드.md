## 사전과제 (파트 3 수강 후 준비)

```
나의 매매 이론 3줄:
1. 진입 조건: _______________________________
2. 청산/목표가: ______________________________
3. 리스크 관리: _____________________________

예시)
1. 진입: RSI 30 이하 + 거래량 3배 이상 동시 충족
2. 청산: +15% 목표가 또는 -7% 손절
3. 리스크: 동일 섹터 최대 2종목, 전체 포트 20% 이내
```

```text
처음에는 Part 4 트랙 A/B/C/D 중 가장 안전한 것 하나만 골라서 수정해줘.
수정 후에는 API 키 없이 데모 모드로 실행 검증하고, 수정 전후 차이를 초보자도 이해하게 설명해줘.
실거래는 절대 하지 마.
```

## 수정 템플릿(트랙) 선택 (CH1 · 기존 시스템 수정 템플릿 소개) — 사전과제 3줄이 그대로 템플릿

> 강의에서 부르는 "수정 템플릿" = 아래 트랙 A~D. 준비해온 이론 중 하나를 골라 해당 템플릿을 고칩니다.

| 트랙 | 사전과제 항목 | 내용 | 대상 파일 | 난이도 |
|------|------|------|----------|--------|
| **A** | 진입 | 종목 선정 조건 | `screening.py` | ★☆☆ |
| **B** | 진입 | 분석 에이전트 프롬프트 | `analysis.py` | ★☆☆ |
| **C** | 청산 | 매도·목표가·트레일링 스탑 | `trading.py` (`_decide_exit`) | ★★☆ |
| **D** | 리스크 | 슬랏·섹터·현금·손절 | `trading.py` (상수) | ★☆☆ |
| 심화 | — | 데이터 소스 추가 / 뼈대부터 구현 | `analysis.py` / `blank_pipeline.py` | ★★★ |

> 준비해온 이론 3줄 중 **하나만** 골라 구현하면 오늘은 성공. 진입은 A·B, 청산은 C, 리스크는 D.

## 실전 프롬프트 공식 (CH2 · 강사 라이브 시범)

> 트랙을 직접 고치기 전에, **AI에게 코드를 시키는 "프롬프트 공식"**을 먼저 익힙니다.
> 같은 요청도 어떻게 말하느냐에 따라 결과가 갈립니다.

### 핵심 공식

```
[현재 상태] + [원하는 결과] + [유지할 제약]
```

- **현재 상태**: 지금 코드가 무엇으로 되어 있는지 (파일·상수·함수명까지)
- **원하는 결과**: 무엇으로 바꾸고 싶은지 (구체적 숫자·조건)
- **유지할 제약**: 깨지면 안 되는 것 (함수 시그니처, 나머지 구조)

### Bad vs Good

| ❌ Bad | ✅ Good |
|---|---|
| "코드 좀 고쳐줘" | "현재 screening.py는 거래량 5배 기준이야. RSI 30 이하 + 거래량 3배로 바꿔줘. 함수 시그니처는 유지해줘." |

### 자주 쓰는 3가지 패턴

> 🔲 = **강사 실제 사례 자리 (상록님 작성)**. PRISM / lecture-prism을 코딩 에이전트와 실제로 작업하며 썼던 프롬프트를 그대로 넣어주세요. 진짜 사례일수록 수강생에게 설득력이 큽니다.

**① 수정 요청** — 현재 상태 + 원하는 결과 + 유지할 제약
```
🔲 [강사 실제 사례 자리]

(틀) "현재 ___는 ___야. ___로 바꿔줘. ___는 유지해줘."
```

**② 에러 해결** — 에러 메시지를 그대로 + 원인 설명 요청
```
🔲 [강사 실제 사례 자리]

(틀) "이 에러가 났어: [에러 메시지 붙여넣기]. 원인 설명하고, 고친 뒤 같은 실행을 다시 검증해줘."
```

**③ 이론-코드 갭 점검** — 내 이론 vs 코드 일치 확인
```
🔲 [강사 실제 사례 자리]

(틀) "이 코드가 내 이론을 정확히 반영하는지 확인해줘. 내 이론: ___"
```

> 트랙 A~D는 **CH3(수강생 실습)**에서 이 공식을 직접 적용하는 부분입니다.

## 트랙 B — 분석 프롬프트 교체

**목표**: `analysis.py`의 `TECHNICAL_AGENT_PROMPT`를 본인 이론으로 교체

> 📌 `analysis.py`는 원본 PRISM처럼 **6개 섹션**(기술·수급·재무·산업·뉴스·시장)을 냅니다.
> 이 중 **수급·재무·산업·시장은 규칙(실데이터 지표)**, **기술·뉴스·전략은 LLM 에이전트**가 담당합니다.
> 트랙B가 바꾸는 건 LLM이 쓰는 **에이전트 프롬프트**입니다.

> ⚠️ **중요 — 프롬프트 변경 효과는 LLM을 연결해야 보입니다.**
> API 키/ChatGPT OAuth 프록시(파트3 CH1)가 **없으면** 기술 섹션은 실데이터 지표 템플릿(또는 mock)으로 나오고,
> 프롬프트를 바꿔도 출력이 **그대로**입니다. 트랙B를 제대로 실습하려면 **LLM 연결이 사실상 필수**입니다.
> (프롬프트 없이 결과가 바로 바뀌는 걸 보고 싶다면 트랙 A·C·D를 고르세요.)

### Claude Code 프롬프트

```
"현재 analysis.py 기술적 분석 에이전트는 CANSLIM 기반이야.
내 이론: 볼린저 밴드 하단 터치 + RSI 과매도 반등으로 바꿔줘.
TECHNICAL_AGENT_PROMPT만 수정하고 나머지 구조는 그대로 둬."
```

### 프롬프트 품질 검증 (LLM 연결 상태에서)

```
"LLM을 연결한 상태에서, 이 프롬프트로 삼성전자를 분석하면
기술 섹션이 어떻게 달라지는지 수정 전후로 실행해서 비교해줘."
```

**목표**: `trading.py`의 `_decide_exit`를 본인 청산 이론으로 교체

### 현재 코드
```python
TAKE_PROFIT = 0.15      # 목표가 +15% 도달 시 청산
TRAILING_STOP = 0.08    # 고점 대비 -8% 되돌림 시 트레일링 스탑
# _decide_exit: 손절 → 트레일링 스탑 → 목표가 순으로 점검
```

### Claude Code 프롬프트
```
"trading.py의 _decide_exit를 내 청산 이론으로 바꿔줘.
내 이론: 목표가 +20%에서 절반 청산, 트레일링 스탑은 고점 대비 -10%, 손절 -5%.
함수 시그니처(holding, current_price)는 유지해줘."
```

### 검증 (손절·트레일링·목표가 3시나리오 실행)
```
"trading.py --exit 실행해서 손절·트레일링·목표가가 각각 잘 발화하는지 보여줘."
```

```
[000660] 청산 신호: 손절 (-8.3%) @ 110,000원
```

## 발표 포맷 (CH4 결과 공유)

```
1. 내 이론 1줄: ___________________________
2. 뭘 바꿨나: screening.py(진입) / analysis.py(진입) / trading.py(청산·리스크) / blank_pipeline.py(심화)
3. 실행 결과: [화면 공유]
```

### 결과 제출 (선택) — 본인 이름 브랜치로 push

GitHub 제출은 선택입니다. 오늘의 성공 기준은 먼저 “내 전략이 데모 모드에서 실행되는 것”입니다. 제출이 막히면 화면 공유나 결과 캡처로 대체해도 됩니다.

직접 Git 명령어를 치지 말고 코딩 에이전트에게 아래처럼 맡기세요.

```text
내 실습 결과를 제출할 수 있게 Git 작업을 도와줘.

조건:
1. 현재 변경 파일을 먼저 보여주고, API 키·토큰·DB 파일 같은 민감한 파일이 포함되어 있지 않은지 확인해줘.
2. main 브랜치가 아니라 내 이름 브랜치에서 작업하게 해줘. 브랜치 이름은 [본인이름-영문] 으로 해줘.
3. 변경 내용을 커밋해줘. 커밋 메시지는 "내 전략 적용"으로 해줘.
4. 원격 저장소에 내 이름 브랜치를 push해줘.
5. push가 실패하면 collaborator 권한 문제인지, 로그인 문제인지, 원격 저장소 문제인지 구분해서 설명해줘.

위 과정에서 필요한 Git 명령은 네가 실행하고, 각 단계 결과를 나에게 확인시켜줘.
```

> 푸시가 안 되면: 강사에게 collaborator 초대를 받았는지 확인. 자세한 흐름은 루트의 `README.md` 참고.
> 화면 공유가 기본 — 푸시는 원하는 사람만.
