# 파트 4 — 수강생 붙여넣기 프롬프트

> 명령어를 직접 외우거나 입력하지 않습니다. 아래에서 **강사가 지정한 번호 하나만** 복사해 코딩 에이전트에 붙여넣으세요.
>
> 오늘의 성공은 전략 전체가 아니라 **파일 하나의 규칙 하나를 바꾸고 전후 증거를 설명하는 것**입니다. 실제 주문·브로커·계좌·시크릿은 사용하지 않습니다.

## 매번 지킬 4단계

1. 실행 전: 무엇이 바뀔지, 무엇은 유지돼야 할지 한 줄로 예상한다.
2. 프롬프트에서 **현재 상태 / 원하는 결과 / 지킬 제약**을 표시한다.
3. 실행 뒤: diff·테스트·결과 표 중 한 가지 증거를 확인한다.
4. 실행 후: “내 전략 → 바꾼 파일 → 달라진 결과”를 한 문장으로 말한다.

## P4-01 · 내 전략 3줄을 기록하기

### 실행 전 예상

- 내 전략에서 오늘 하나만 먼저 바꾼다면 진입·청산·리스크 중 무엇일까?

### 코딩 에이전트에 붙여넣기

```text
MY_STRATEGY.md를 열어 내 전략을 아래 세 줄로 정리하도록 도와줘.

1. 진입: [내가 후보를 볼 조건]
2. 청산: [손실·수익·추세 훼손에서 나올 조건]
3. 리스크: [최대 보유 종목 수·현금·매수 기준]

내 말이 모호하면 숫자·조건·우선순위를 제안하되, 사실을 지어내지 말고 내가 확인할 질문은 하나만 해줘.
아직 코드·.env·브로커·계좌 설정은 수정하지 마.
마지막에 Part 4 트랙 A/B/C/D 중 오늘 가장 안전한 첫 선택지를 하나만 추천하고 이유를 설명해줘.
```

### 성공 증거

- `MY_STRATEGY.md`에 세 줄이 있음
- 오늘 고를 트랙이 하나로 좁혀짐

### 실행 후 한 문장

> 내 전략에서 오늘 먼저 검증할 것은 ___이고, 그래서 ___ 트랙을 고른다.

## P4-02 · 하네스로 한 트랙만 수정하기

### 실행 전 예상

- 에이전트는 어느 파일 하나를 바꿀까?
- 수정 뒤 무엇을 비교해야 내 전략이 반영됐다고 말할 수 있을까?

### 코딩 에이전트에 붙여넣기

```text
MY_STRATEGY.md를 읽고 내 전략을 lecture-prism에 반영해줘.

오늘은 Part 4 트랙 A/B/C/D 중 내 전략과 가장 가까운 한 트랙만 골라줘.
관련 파일 하나만 최소한으로 수정하고, 수정 전 증거와 수정 후 증거를 비교해줘.
run_screening, run_analysis, run_trading, run_feedback의 입출력 형태와 기본 mock 경로는 유지해줘.
API 키 없이 mock 데모를 끝까지 실행해 검증하고, 실제 주문·브로커·계좌 설정은 절대 사용하지 마.
마지막에는 바꾼 파일, 바꾼 규칙, 달라진 결과, 남은 한계를 초보자도 이해하게 표로 정리해줘.
```

### 성공 증거

- 파일 하나만 바뀐 diff
- 수정 전후 결과 비교와 mock 완주

### 실행 후 한 문장

> 나는 ___을 위해 ___ 파일의 ___을 바꿨고, 결과는 ___처럼 달라졌다.

## P4-03 · 트랙 A: 후보 선별 규칙

### 실행 전 예상

- 거래량 기준을 낮추면 후보 수는 늘어날까, 줄어들까?

### 코딩 에이전트에 붙여넣기

```text
root screening.py의 기본 스크리닝 조건을 내 이론으로 바꿔줘.

내 이론: [예: RSI 30 이하 반등 + 거래량 3배 + 중형주 이상]
VOLUME_SURGE_RATIO, MIN_MARKET_CAP_KRW, MOMENTUM_DAYS, MAX_CANDIDATES와 _filter_candidates()의 단순 조건만 먼저 검토해줘.
run_screening()의 입력과 list[str] 반환은 유지하고, 관련 없는 파일은 수정하지 마.
수정 전후 후보 목록을 표로 비교하고 API 키 없는 mock 데모가 끝까지 도는지 검증해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- `screening.py`만 최소 수정됨
- 전후 후보 목록과 mock 완주 결과가 있음

### 실행 후 한 문장

> 후보 조건을 ___로 바꾸자, 통과 종목이 ___처럼 달라졌다.

## P4-04 · 트랙 C: 청산 규칙

### 실행 전 예상

- 손절·트레일링·목표가 중 어느 규칙이 먼저 적용돼야 할까?

### 코딩 에이전트에 붙여넣기

```text
trading.py의 _decide_exit를 내 청산 이론으로 바꿔줘.

내 이론: [예: 목표가 +20%, 트레일링 스탑 고점 대비 -10%, 손절 -5%]
holding과 current_price 함수 시그니처는 유지하고, 부분청산은 이번 기본 실습에 넣지 마.
손절·트레일링·목표가가 각각 따로 발화하는 보유 예시 3개를 만들어 검증해줘.
각 예시에서 현재가·진입가·고점·기대 청산 사유·실제 청산 사유를 표로 보여주고, API 키 없는 mock 데모도 끝까지 실행해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- 세 청산 규칙이 서로 다른 예시에서 각각 증명됨
- 기본 mock 데모가 유지됨

### 실행 후 한 문장

> 내 청산 규칙은 ___을 먼저 확인하고, ___일 때 나온다.

## P4-05 · 트랙 D: 리스크 관리

### 실행 전 예상

- 보유 종목 수와 현금 비중을 바꾸면 매수 수량은 어떻게 달라질까?

### 코딩 에이전트에 붙여넣기

```text
trading.py의 리스크 상수를 내 원칙으로 바꿔줘.

내 원칙: [예: 최대 5종목, 현금 50% 유지, 매수 점수 6 이상]
이번 기본 실습에서는 _decide_position이 실제로 쓰는 MAX_SLOTS, CASH_RESERVE_RATIO, BUY_SCORE_THRESHOLD만 바꿔줘.
동일 섹터 제한이나 부분청산처럼 root 데모에서 아직 쓰지 않는 기능은 심화 과제로 분리해줘.
수정 전후로 포지션 수량과 매수 통과 기준이 어떻게 달라지는지 표로 비교하고, API 키 없는 mock 데모를 끝까지 실행해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- `trading.py`의 실제 사용 상수만 바뀜
- 수량 또는 매수 통과 기준의 전후 비교가 있음

### 실행 후 한 문장

## P4-06 · 선택 트랙 B: LLM 분석 관점

> 공식 Codex OAuth 또는 OpenAI API를 실제로 연결한 사람만 결과 문장 변화를 확인합니다. 연결이 없으면 A/C/D를 고르세요.

### 실행 전 예상

- 기술·뉴스 설명은 바뀔 수 있지만, 매수점수와 목표가는 바뀔 수 있을까?

### 코딩 에이전트에 붙여넣기

```text
현재 analysis.py의 기술적 분석 관점을 내 이론으로 바꿔줘.

내 이론: [예: 볼린저 밴드 하단 터치 + RSI 과매도 반등]
TECHNICAL_AGENT_PROMPT와 직접 연결된 정성 설명만 최소한으로 수정하고, 정량 점수·추천·목표가·손절가 규칙은 바꾸지 마.
공식 Codex OAuth 또는 OpenAI API가 실제로 연결되어 있는지 먼저 확인해줘.
연결되어 있으면 같은 종목의 기술·뉴스 설명을 수정 전후로 비교하고, 연결되어 있지 않으면 결과 문장 변화가 없을 수 있음을 설명한 뒤 코드는 mock으로만 검증해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- LLM 연결 여부가 명확히 표시됨
- 정성 설명과 정량 규칙의 경계가 유지됨

### 실행 후 한 문장

> 나는 분석의 ___ 관점만 바꿨고, 점수·목표가·손절가는 ___이 유지한다.

## P4-07 · 전후 비교와 1분 공유 준비

### 실행 전 예상

- 내 전략이 코드에 반영됐다는 가장 작은 증거는 무엇일까?

### 코딩 에이전트에 붙여넣기

```text
방금 내 전략을 반영한 변경을 검증해줘.

1. 수정한 파일이 하나인지와 변경 전후 차이를 보여줘.
2. 내 트랙에 맞는 증거를 하나 더 확인해줘: A는 후보 목록, C는 손절·트레일링·목표가 3시나리오, D는 수량·매수 기준, B는 LLM 연결 여부와 설명 문장 비교야.
3. API 키 없는 mock 데모가 끝까지 도는지 확인해줘.
4. 아래 발표 양식을 내 결과로 채워줘.

내 전략 한 줄:
바꾼 파일 한 개:
수정 전후 결과와 이유:

실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- 전략·파일·전후 결과가 한 화면 또는 한 표에 연결됨

### 실행 후 한 문장

> 내 전략을 다음에 더 바꾼다면, 오늘 증거를 유지한 채 ___ 트랙을 이어서 검증하겠다.
