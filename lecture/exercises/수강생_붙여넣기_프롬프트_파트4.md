## 작업 순서

1. **PRD를 적는다:** 무엇을 왜 바꾸고 언제 끝낼지 정합니다.
2. **작업·검증 계획을 세운다:** 수정 순서와 확인할 증거를 적습니다.
3. **설계한다:** 담당 파일·함수·데이터·안전 경계를 연결합니다.
4. **구현한다:** 회귀 사례를 먼저 만들고 규칙 하나만 바꿉니다.
5. **검증한다:** 코드 차이·테스트·로그·DB에서 결과를 찾습니다.
6. **피드백한다:** 어긋난 단계부터 고치고 다음에 할 한 가지를 남깁니다.

이 여섯 단계는 **질문한다 → 예측한다 → 실행한다 → 증거를 읽는다 → 회고한다**를 실제 개발 산출물에 연결한 순서입니다.

## P4-KIS · KIS 실제 수급을 분석에 한 번 연결하기

> 파트3에서 KIS paper 또는 real 읽기 전용 조회를 준비한 사람만 선택합니다. 준비하지 않았다면 건너뜁니다.

### P4-KIS 선택 준비 프롬프트

KIS 읽기 전용 조회에는 선택한 환경의 App Key와 App Secret만 필요합니다. 계좌번호와 HTS ID는 필요하지 않으며, `trading/trading/config/kis_devlp.yaml`은 모의·실거래 브로커 심화에서만 사용합니다.

```text
lecture-prism의 KIS 읽기 전용 수급 설정만 안전하게 준비해 줘. 아직 조회나 분석은 실행하지 마.

1. `.env.example`과 `.gitignore`를 확인하고, 프로젝트 루트의 `.env`가 없으면 견본을 복사해 만들어 줘. 기존 `.env`가 있으면 다른 값은 바꾸지 마.
2. 내가 고른 환경은 [paper 또는 real]이야. 이 환경의 App Key와 App Secret 두 항목을 찾고 `LECTURE_KIS_MODE`도 맞춰 줘. paper면 demo, real이면 real이야. 계좌번호·HTS ID·kis_devlp.yaml은 요구하거나 만들지 마.
3. macOS 텍스트 편집기나 Windows 메모장처럼 운영체제의 기본 텍스트 편집기로 `.env`를 열어 줘. 키를 채팅에 붙여넣으라고 요구하지 말고, 내가 파일에 직접 입력·저장할 때까지 기다려 줘.
4. 내가 저장했다고 말하면 값 자체를 출력하지 말고, 값이 도구 출력에도 나오지 않는 상태 검사로 `준비됨 / 비어 있음 / 형식 오류`만 알려 줘.
5. `.env`가 Git 추적에서 제외됐는지 확인해 줘. `.gitignore`는 Git 업로드를 막을 뿐 에이전트의 로컬 파일 읽기까지 막지는 않는다고 설명해 줘.
```

준비된 사람은 이어서 아래 실행 프롬프트를 붙여넣습니다.

```text
lecture-prism의 KIS 읽기 전용 수급 보강을 삼성전자 005930 한 종목에 한 번 적용해 줘.

먼저 kis_market_data.py, data_source.py, analysis.py와 관련 테스트를 읽고, KIS 경로가 현재가와 일별 기관·외국인·개인 순매수만 조회하는지 확인해 줘. Part 3에서 확인한 paper 또는 real 환경을 그대로 사용하고, 어느 환경인지 불분명하면 그 선택만 나에게 물어봐.

기본 yfinance 분석과 KIS 수급 보강 분석을 각각 한 번 비교해 줘. KIS 보강은 이번 실행에만 적용하고, 매매는 simulation으로 유지해. 가장 최근 영업일 기준일, 가격, 기관·외국인·개인 순매수, 달라진 수급 섹션, 그대로인 다른 분석 섹션을 표로 보여 줘.

주문·취소·정정·잔고·계좌 API 호출은 0회여야 한다. 키와 토큰 값 자체를 답변에 출력하거나 복사하지 마. 실패하면 자동 재시도나 환경 전환을 하지 말고, 실패 원인과 거래량 프록시로 돌아갔는지 여부를 구분해 알려 줘.
```

## P4-05 · 트랙 A: 후보 선별 규칙 바꾸기

```text

내 전략 프로그램을 내 컴퓨터가 꺼져도 계획한 시각에 실행할 수 있도록 24시간 클라우드 서버 운영 환경을 준비해 줘.

중요한 경계:

1단계 · 현황 조사와 질문

3. 이 저장소의 docs/runtime-profiles.md, deploy/systemd/lecture-prism.service.example, operations.py의 doctor·status·schedule 경계를 읽어 실제 제공 기능을 확인해.
4. 클라우드·Ubuntu·systemd·Nginx 설정은 현재 공식 문서를 확인하고 출처 링크를 남겨.

2단계 · 변경 전 계획
1. 로컬에서 SSH로 서버에 접속하는 과정을 비개발자도 이해하도록 “내 컴퓨터에서 멀리 있는 서버의 터미널을 안전하게 여는 연결”이라고 먼저 설명해.
2. SSH 키 준비, 공개키 등록, 개인키 권한, 서버 사용자, 클라우드 방화벽과 UFW, 보안 업데이트, Git 인증 방법을 표로 계획해.
3. 비밀번호 로그인을 끄거나 SSH 포트를 제한하기 전에는 새 키로 두 번째 접속이 실제 성공하는지 먼저 검증하게 해. 접속을 잃었을 때 제공사 콘솔로 복구하는 방법도 적어.

5. 이 계획을 보여준 뒤 멈추고 내 승인을 기다려.

3단계 · 승인한 설치와 simulation 검증
1. 내가 승인하면 SSH 연결을 확인하고 전용 일반 사용자와 최소 권한 원칙을 적용해.
2. 내가 지정한 저장소를 Git으로 내려받아 프로젝트 루트의 .venv에 requirements.txt를 설치해. 비공개 저장소 인증값은 화면에 출력하지 마.
3. .env.example을 복사하되 비밀값은 채우지 말고 실제 .env를 기본 편집기로 열어 내가 직접 입력하게 해. 파일 권한과 Git 추적 제외 상태만 준비됨·비어 있음·형식 오류로 확인해.
4. operations.py doctor와 status, API 키 없는 main.py mock·simulation을 먼저 실행하고 다섯 단계 완료·실제 주문 0건·로그·DB 기록을 표로 보여 줘.

4단계 · 상시 서비스와 운영 정책
1. deploy/systemd/lecture-prism.service.example을 현재 서버 경로에 맞춘 사본으로 준비해. --execute-broker를 넣지 말고 simulation으로 유지해.
2. systemd 등록 전 실제 ExecStart·WorkingDirectory·환경·재시작 정책·중지·삭제 명령을 보여주고 다시 승인받아.
3. 승인 뒤 서비스 시작, 상태, scheduler heartbeat, 중복 실행 잠금, 마지막 작업 결과를 확인해. 가능하면 재부팅 뒤 자동 시작은 별도 승인 후 한 번 검증해.
4. 로그는 일별 또는 용량별로 회전·압축하고 내가 정한 기간만 보관하도록 logrotate 정책을 준비해. dry-run과 강제 회전 시험으로 새 로그가 계속 기록되는지 확인해.
5. 서비스 실행 여부, heartbeat, 마지막 작업 성공·실패·stale_data, 디스크 여유, 최근 백업 시각을 감시 항목으로 정리해. 임계값·확인 주기·중복 알림 간격·정상 복구 알림을 먼저 정해.
6. 내가 선택한 경우에만 감시 결과를 Telegram·Discord·이메일 같은 채널로 보내는 가장 작은 통로를 준비해. 토큰이나 주소는 .env에만 두고 메시지에는 계좌정보·시크릿·원문 로그를 넣지 마. 시험 경고 한 건과 정상 복구 한 건으로 확인해.

5단계 · 대시보드·백업·장애 연습
1. 대시보드는 기본적으로 127.0.0.1에만 두고 SSH 터널로 보는 방법을 먼저 제안해.
2. 내가 외부 공개를 명시적으로 선택한 경우에만 도메인·Nginx 역방향 프록시·HTTPS 인증서·로그인 인증·요청 제한·클라우드 방화벽·UFW를 설계해. 원래 대시보드 포트 8080은 인터넷에 직접 열지 마.
3. prism.db와 필요한 설정 구조, 서버 스냅샷의 백업 주기·보관 기간·비용을 정리해. 비밀 설정 백업은 암호화·접근권한을 먼저 확인해.
4. 백업을 만들었다는 기록만 믿지 말고 임시 위치에 복원해 DB를 읽을 수 있는지 한 번 확인해. 운영 DB를 덮어쓰지 마.
5. 서비스 중지→감지, 서비스 재시작, 시험 실패→알림, 로그 회전, 백업 복원을 하나씩 실행하고 예상 증거와 실제 결과를 비교해.
```

### 성공 증거

- 유료 서버 발급·비밀값 입력·위험 변경은 사람이 직접 결정함
- 서버의 simulation 서비스가 재시작 가능하고 상태·로그·DB 경로가 확인됨
- 로그 회전·감시·백업 복원 중 실제로 확인한 결과가 표로 남음
- 선택한 경우에만 감시 알림 통로가 시험 경고와 정상 복구로 검증됨
- 중지·삭제·접속 복구·백업 복원 방법이 함께 남음
