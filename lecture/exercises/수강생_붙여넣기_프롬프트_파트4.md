## P4-TOSS · Toss 실제 시세를 읽어 보는 선택 실습

### P4-TOSS-SETUP · 공식 Open API 준비 상태 확인

```text
[현재 프롬프트: P4-TOSS-SETUP · 공식 Open API 준비 상태 확인]

컨텍스트: Toss 실제 시세를 한 건 읽을 준비만 확인하는 선택 실습이야. 주문이나 계좌 조회는 하지 않아.

lecture-prism에서 Toss 실제 시세를 읽어 보는 선택 실습을 준비해 줘. 이 실습은 공식 Open API와 tossctl 0.43.1 이상을 사용하고, 주문은 하지 않아.

먼저 `brokers/base.py`, `brokers/tossctl.py`, `brokers/toss.py`와 관련 테스트를 읽어 줘. `BrokerQuote`라는 공통 결과 형식과 `TossctlQuoteAdapter`가 어떤 역할을 하는지 쉬운 말로 설명해 줘.

그다음 tossctl이 설치되어 있는지와 버전을 확인해 줘. 없다면 바로 설치하지 말고, 설치하면 무엇이 바뀌는지와 설치 뒤 확인할 내용을 먼저 보여 줘. 내가 설치를 허락하면 공식 저장소의 tossctl 0.43.1을 설치하고 버전 확인까지 해 줘.

토스 계좌와 Open API 키가 없으면 `계좌 없음` 또는 `키 없음`이라고 적고 멈춰. 이것은 실패가 아니라 아직 실제 시세를 읽을 준비가 안 된 상태야. 토스 계좌가 있으면 내가 토스증권 WTS에서 Open API 키를 만들고 허용 IP를 등록할 수 있게 안내해 줘.

중요: tossctl의 Open API 로그인은 키와 비밀값을 명령에 직접 넣는 방식이야. 그러므로 키를 채팅에 붙여넣거나 에이전트에게 전달하지 마. 내가 요청하면 키가 비어 있는 로그인 방법만 보여 주고 실행하지 마. 나는 그 내용을 내 개인 터미널에 직접 입력한 뒤 `준비 완료`라고 말할게. 키·비밀값·토큰·쿠키·세션 파일·계좌번호는 채팅·로그·프로젝트 파일에서 읽거나 출력하지 마.

내가 준비를 마쳤다고 말하면 `openapi status`로 준비 상태만 확인해 줘. 결과는 `준비됨 / 실행 파일 없음 / 계좌 없음 / 키 없음 / 허용 IP 확인 필요 / 확인 필요` 중 하나로 알려 줘. 주문·취소·정정·잔고·계좌 API 호출은 0회여야 해.
```

- `LECTURE_PROFILE=paper` + `LECTURE_TRADE_MODE=demo` / `classroom`·`backtest`: 별도 심화 경로

```text
[현재 프롬프트: P4-14 · 개선한 버전 전체 파이프라인 다시 돌리기]

컨텍스트: 예약 없이 개선한 코드를 `main.py`로 한 번 다시 실행하고, 선택한 프로필의 전후 결과를 비교하는 단계야.

MY_STRATEGY.md, 이번에 바꾼 파일과 관련 테스트를 읽고 개선한 lecture-prism 전체 파이프라인을 한 번 직접 실행해 줘. 이 대화에 P4-04의 실행 결과와 현재 트랙 계획이 남아 있으면 참고하되, 그 내용을 알고 있다고 가정하지 마. 예약·스케줄러·서비스 등록은 사용하지 말고 main.py 경로만 실행해.

`real_data`, `research`, `paper`를 선택했을 때는 `docs/runtime-execution-preflight.md`를 먼저 읽어. 프로젝트 `.venv`의 Python과 패키지를 사용하고, 외부 DNS·네트워크 승인 상태를 확인한 뒤 필요한 읽기 요청만 실행해.

실행 결과와 전후 비교가 길어지면 `docs/lecture-prism-output-style.md`를 읽고 `reports/interactive/`에 HTML로 정리해 줘. 채팅에는 프로필, 파이프라인 상태, 가장 큰 변화, 파일 경로만 먼저 알려 줘.

P4-04의 결과가 이 대화에 없거나 현재 트랙이 분명하지 않으면 ‘P4-04 계획 없음’이라고 먼저 적어. 그다음 MY_STRATEGY.md, 이번에 바꾼 파일, `git diff`, 관련 테스트를 근거로 이번 변경이 트랙 A(진입), B(분석), C(청산), D(리스크) 중 어디에 해당하는지 ‘추정’으로만 표시하고, 트랙을 새로 정하거나 코드를 추가로 수정하지 말고 파이프라인 실행을 계속해.

실행 프로필은 [mock / real_data / research / paper] 중 [선택한 프로필]이야. 이 대괄호 안의 값은 내가 이번 실행에서 직접 고르는 값이야. 비워 두면 `mock + simulation`을 사용해. `paper`를 고르면 `LECTURE_TRADE_MODE=demo`로 유지해. `live`는 이 프롬프트에서 실행하지 말고, 실거래가 필요하다고 말하면 `real_data + simulation` → `paper + demo` → 별도 live 검토 순서를 알려 줘.

프로필에 따라 아래 경계를 지켜.
1. `mock`: API 키·외부 데이터·브로커를 사용하지 말고 전체 5단계를 실행해.
2. `real_data`: Yahoo Finance에 필요한 범위 제한 네트워크 승인을 먼저 요청해. 005930 한 종목으로 실제 가격·거래량을 읽되 매매는 simulation으로 유지해.
3. `research`: 승인된 외부 실행과 필요한 데이터 연결만 사용해. 005930 한 종목으로 한 번 실행하고, LLM 성공·규칙 보고서 대체·호출 실패를 나눠 기록해.
4. `paper`: `LECTURE_TRADE_MODE=demo`를 유지해. 실제 모의 서버 요청을 보내기 전에 사용한 브로커·환경·호출 범위·중지 방법을 보여 주고 내 승인을 받아. live 플래그는 켜지 마. 모의 서버 요청이 실행되면 접수와 체결을 구분해.

실행 전에 현재 프로필, 데이터 원천, 브로커 호출 여부, 실제 주문 가능성, 생성될 로그·보고서·DB 기록을 표로 보여 줘. 내가 선택한 프로필과 다르게 바꾸지 마.

실행이 끝나면 아래 표를 채워 줘.
- 프로필과 데이터 원천
- `[1/5]`부터 `[5/5]`까지 각 단계의 실제 결과
- 수정한 파일과 규칙
- 수정 전후 후보·분석·매수 시나리오·매매 결과 비교
- `logs/`, `reports/`, `prism.db`의 실제 경로
- simulation 체결 수 또는 paper 접수·체결 수
- 실제 주문·취소·정정·잔고·계좌 API 호출 수
- 실패한 외부 연결과 대체 경로

자동으로 여러 번 반복하지 마. 결과가 만족스럽지 않으면 이번 사이클을 끝낸 뒤 다음에 바꿀 규칙 하나만 제안해. 내가 그 규칙을 수정한 뒤 이 프롬프트를 다시 붙여넣으면 같은 방식으로 한 사이클을 다시 실행해.

코드·설정·DB를 바꾸라는 지시가 없는 단계에서는 수정하지 마. API 키·토큰·계좌번호·시크릿은 출력하지 마. 실제 주문을 성공했다고 말하려면 브로커 응답과 체결 근거를 따로 확인해.
```

## P4-16 · 수업 후 24시간 서버 운영 준비하기

```text
[현재 프롬프트: P4-16 · 수업 후 24시간 서버 운영 준비하기]

컨텍스트: 수업 후 서버 운영 계획을 세우는 단계야. 먼저 mock·simulation과 승인 흐름부터 확인해.

내 전략 프로그램을 내 컴퓨터가 꺼져도 정해진 때 실행할 수 있도록 24시간 운영 환경을 준비하는 계획을 같이 세워 줘. P4-14에서 어떤 프로필을 골랐는지와 상관없이, 이 단계의 설치·서비스·검증은 doctor와 mock·simulation으로 시작해.

먼저 현재 운영체제, 서버가 이미 있는지, 프로젝트 경로, 실행 시각, 로그 보관 기간, 대시보드 공개 여부, 알림 채널을 확인해 줘. 서버가 아직 없으면 서버를 만들거나 결제하지 말고 필요한 최소 조건만 알려 줘.

그다음 이 저장소의 `docs/runtime-profiles.md`, `deploy/systemd/lecture-prism.service.example`, `operations.py`의 doctor·status·schedule 경계를 읽고, SSH·일반 사용자·방화벽·보안 업데이트·Git·`.venv`·`.env`·simulation 검증·서비스 관리자·로그·감시·백업·복구·대시보드 순서로 계획을 세워 줘. 각 단계에서 무엇이 바뀌는지, 위험은 무엇인지, 어떻게 되돌리는지를 함께 보여 줘.

계획을 먼저 보여 주고 내 승인을 기다려. 승인 뒤에도 한 단계씩 진행하면서, 실제로 확인한 결과만 알려 줘. systemd나 다른 서비스 등록, 방화벽·SSH·재부팅·Nginx 변경은 별도 승인을 받아. 대시보드는 기본적으로 127.0.0.1과 SSH 터널만 사용하고, 포트 8080을 인터넷에 직접 열지 마.

유료 서버 발급과 결제, 비밀값 입력, `LECTURE_ENABLE_LIVE_BROKER`, `LECTURE_ALLOW_REAL_BROKER`, `LECTURE_UNATTENDED_LIVE_ACK` 변경, 실제 주문은 하지 마. SSH 개인키·API 키·토큰·계좌정보·`.env` 값은 읽거나 출력하거나 로그에 남기지 마. 알림은 내가 고른 채널만 설계하고, 계좌정보와 원문 로그는 보내지 마.

마지막에는 서버·서비스·로그·DB·백업 위치, 감시 항목, 접근 방법, 중지·삭제·복구 방법, 아직 하지 않은 작업을 짧게 정리해 줘. 계획과 운영 결과가 길어지면 `docs/lecture-prism-output-style.md`와 `docs/lecture-prism-output-template.html`을 읽고 `reports/interactive/`에 HTML로 남겨 줘. 채팅에는 현재 단계, 승인할 변경, 남은 위험만 먼저 알려 줘.
```
