## 매번 지킬 순서

1. **PRD를 적는다:** 무엇을 왜 바꾸고 언제 완료인지 정합니다.
2. **작업·검증 계획을 세운다:** 수정 순서와 확인할 증거를 함께 적습니다.
3. **설계한다:** 담당 파일·함수·데이터·안전 경계를 잇습니다.
4. **구현한다:** 회귀 사례를 먼저 만들고 규칙 하나만 바꿉니다.
5. **검증한다:** 코드 차이·테스트·로그·DB에서 결과를 찾습니다.
6. **피드백한다:** 어긋난 단계부터 고치고, 다음에 시도할 한 가지를 남깁니다.

이 여섯 단계는 기존의 쉬운 표현인 **질문한다 → 예측한다 → 실행한다 → 증거를 읽는다 → 회고한다**를 실제 개발 산출물에 연결한 것입니다.

## P4-KIS · KIS 실제 수급을 분석에 한 번 연결하기

> 파트3에서 KIS paper 또는 real 읽기 전용 조회를 준비한 사람만 선택합니다. 준비하지 않았다면 건너뜁니다.

### P4-KIS 선택 준비 프롬프트

KIS 읽기 전용 조회에는 선택한 환경의 App Key와 App Secret만 필요합니다. 계좌번호와 HTS ID는 필요하지 않으며, `trading/trading/config/kis_devlp.yaml`은 모의·실거래 브로커 심화에서만 사용합니다.

```text
lecture-prism의 KIS 읽기 전용 수급 설정만 안전하게 준비해줘. 아직 조회나 분석은 실행하지 마.

1. `.env.example`과 `.gitignore`를 확인하고, 프로젝트 루트의 `.env`가 없으면 견본을 복사해 만들어줘. 기존 `.env`가 있으면 다른 값은 바꾸지 마.
2. 내가 고른 환경은 [paper 또는 real]이야. 이 환경의 App Key와 App Secret 두 항목을 찾고 `LECTURE_KIS_MODE`도 맞춰줘. paper면 demo, real이면 real이야. 계좌번호·HTS ID·kis_devlp.yaml은 요구하거나 만들지 마.
3. macOS 텍스트 편집기나 Windows 메모장처럼 운영체제의 기본 텍스트 편집기로 `.env`를 열어줘. 키를 채팅에 붙여넣으라고 요구하지 말고, 내가 파일에 직접 입력·저장할 때까지 기다려줘.
4. 내가 저장했다고 말하면 값 자체를 출력하지 말고, 값이 도구 출력에도 나오지 않는 상태 검사로 `준비됨 / 비어 있음 / 형식 오류`만 알려줘.
5. `.env`가 Git 추적에서 제외됐는지 확인해줘. `.gitignore`는 Git 업로드를 막을 뿐 에이전트의 로컬 파일 읽기까지 막지는 않는다고 설명해줘.
```

준비된 사람은 이어서 아래 실행 프롬프트를 붙여넣습니다.

```text
lecture-prism의 KIS 읽기 전용 수급 보강을 삼성전자 005930 한 종목에 한 번 적용해줘.

먼저 kis_market_data.py, data_source.py, analysis.py와 관련 테스트를 읽고, KIS 경로가 현재가와 일별 기관·외국인·개인 순매수만 조회하는지 확인해줘. Part 3에서 확인한 paper 또는 real 환경을 그대로 사용하고, 어느 환경인지 불분명하면 그 선택만 나에게 물어봐.

기본 yfinance 분석과 KIS 수급 보강 분석을 각각 한 번 비교해줘. KIS 보강은 이번 실행에만 적용하고, 매매는 simulation으로 유지해. 가장 최근 영업일 기준일, 가격, 기관·외국인·개인 순매수, 달라진 수급 섹션, 그대로인 다른 분석 섹션을 표로 보여줘.

주문·취소·정정·잔고·계좌 API 호출은 0회여야 한다. 키와 토큰 값 자체를 답변에 출력하거나 복사하지 마. 실패하면 자동 재시도나 환경 전환을 하지 말고, 실패 원인과 거래량 프록시로 돌아갔는지 여부를 구분해 알려줘.
```

## P4-05 · 트랙 A: 후보 선별 규칙 바꾸기

