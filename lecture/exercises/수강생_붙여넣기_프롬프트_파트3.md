# 파트 3 — 수강생 붙여넣기 프롬프트

> 명령어를 직접 외우거나 입력하지 않습니다. 아래에서 **강사가 지정한 번호 하나만** 복사해 코딩 에이전트에 붙여넣으세요.
>
> 기본 실습은 API 키 없는 `mock`과 `simulation`입니다. 실제 주문·브로커·계좌·시크릿은 어떤 프롬프트에서도 사용하지 않습니다.

## 매번 지킬 4단계

1. 실행 전 30초 동안 `실행 전 예상`에 답한다.
2. 프롬프트에서 **현재 상태 / 원하는 결과 / 지킬 제약**을 하나씩 찾는다.
3. 실행 뒤에는 `성공 증거` 중 한 가지를 확인한다.
4. `실행 후 한 문장`을 자기 말로 완성한다. 오류가 나면 P3-03만 사용한다.

## P3-01 · API 키 없는 첫 성공

### 실행 전 예상

- 이 실행에서 실제 데이터나 실제 주문이 나갈까?
- 네 단계 중 마지막 단계는 무엇일까?

### 코딩 에이전트에 붙여넣기

```text
이 lecture-prism 프로젝트가 내 컴퓨터에서 API 키 없는 기본 데모로 실행되는지 확인해줘.

조건:
1. 현재 폴더가 lecture-prism 프로젝트 루트인지와 Python 3.10 이상인지 먼저 확인해줘.
2. 외부 패키지·API 키·브로커·계좌 설정은 추가하거나 읽지 말고, 기본 mock 파이프라인을 한 번만 실행해줘.
3. 스크리닝 → 분석 → 시뮬레이션 매매 → 피드백·저장이 모두 끝났는지 표로 정리해줘.
4. 데이터 원천이 mock인지, 실제 주문·브로커 API 호출이 없었는지 로그 근거를 한 줄씩 보여줘.
5. 실패하면 내가 터미널 명령어를 직접 치게 하지 말고, 원인과 API 키 없는 mock으로 돌아가기 위한 최소 조치만 설명해줘.
```

### 성공 증거

- 네 단계가 모두 끝났다는 로그
- `모의 데이터(mock)` 또는 mock이라는 데이터 원천 표시
- simulation 체결 또는 안전한 매수 보류 결과

### 실행 후 한 문장

> 이 실행은 ___ 데이터를 써서, ___ 단계까지 갔고, 실제 주문은 ___.

## P3-02 · 방금 나온 결과 읽기

### 실행 전 예상

- 후보를 고른 규칙과 매수 여부를 정한 규칙은 같은 파일일까?
- BUY가 보이면 실제 주문도 나갔을까?

### 코딩 에이전트에 붙여넣기

```text
방금 실행한 lecture-prism mock 결과를 초보자에게 설명해줘.

screening.py, analysis.py, trading.py, feedback.py가 각각 무엇을 했는지 한 줄씩 설명하고,
이번 결과에서 후보 종목·추천·매수점수·시뮬레이션 체결 또는 보류·저장된 피드백을 표로 정리해줘.
분석의 BUY가 실제 주문을 뜻하지 않는 이유와, 데이터가 mock인지 확인한 로그 근거도 함께 보여줘.
코드를 수정하거나 실제 주문을 실행하지 마.
```

### 성공 증거

- 네 파일의 역할이 결과 화면과 연결되어 있음
- 추천, 매수 판단, 실제 주문 여부가 구분되어 있음

### 실행 후 한 문장

> 후보를 고른 곳은 ___이고, 매수 여부를 다시 거른 곳은 ___이다.

## P3-03 · 오류를 에이전트에게 다시 전달하기

### 실행 전 예상

- 오류 메시지에서 “어느 단계”와 “무엇을 못 했는지”를 찾을 수 있을까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism 실행 중 아래 오류가 났어.

[오류 메시지를 처음부터 끝까지 그대로 붙여넣기]

내가 직접 터미널 명령어를 치게 하지 말고,
1. 오류가 스크리닝·분석·매매·피드백 중 어느 단계인지,
2. 원인이 Python·파일 경로·선택 패키지·설정 중 무엇인지,
3. API 키 없는 mock 기본 경로를 먼저 복구하는 최소 조치가 무엇인지 설명해줘.
수정이 필요하면 관련 파일만 최소한으로 고치고 같은 기본 데모를 다시 검증해줘.
실제 주문·브로커·계좌·시크릿은 절대 사용하지 마.
```

### 성공 증거

- 오류 원인과 고친 범위가 구분되어 있음
- mock 기본 데모의 재실행 결과가 있음

### 실행 후 한 문장

> 오류는 ___ 단계에서 났고, 에이전트는 ___을 확인해 해결했다.

## P3-04 · 선택: 실데이터 관찰

> 인터넷과 선택 패키지를 쓸 수 있는 사람만 합니다. 실패해도 mock으로 돌아오면 정상적인 안전 동작입니다.

### 실행 전 예상

- 이번 결과의 데이터 원천은 yfinance일까, mock 폴백일까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism을 실데이터 관찰 단계로 점검해줘.

LECTURE_PROFILE=real_data를 이번 실행에만 적용하고, 삼성전자 005930 한 종목만 분석해줘.
실제 가격·거래량을 받았는지, mock 데이터로 폴백했는지를 data source·기준일·현재가로 구분해 설명해줘.
실패하거나 yfinance가 없으면 원인을 짧게 설명하고 API 키 없는 mock 데모가 계속 가능한지도 확인해줘.
실제 주문·브로커 API·계좌 설정은 절대 사용하거나 바꾸지 마. 매매는 simulation으로 유지해.
```

### 성공 증거

- `실데이터(yfinance)` 또는 `모의 데이터(mock)`가 명확히 표시됨
- 실제 주문 없이 simulation으로 끝남

### 실행 후 한 문장

> 이번 분석은 ___ 원천을 썼고, 그래서 현재가 ___을/를 ___로 해석해야 한다.

## P3-05 · 선택: 공식 Codex OAuth research

> ChatGPT Plus/Pro 로그인 또는 별도 API 키가 있는 사람만 합니다. 기본 실습의 성공 조건은 아닙니다.

### 실행 전 예상

- LLM이 바꿀 수 있는 것과 바꿀 수 없는 것은 각각 무엇일까?

### 코딩 에이전트에 붙여넣기

```text
공식 Codex CLI의 로그인 상태만 사용해 lecture-prism의 research 분석을 삼성전자 005930 한 종목으로 점검해줘.

LECTURE_PROFILE=research와 LECTURE_LLM_MODE=oauth를 이번 실행에만 적용해.
토큰·인증 파일·시크릿은 읽거나 출력하거나 복사하지 말고, Perplexity와 Firecrawl도 사용하지 마.
실제 LLM 응답 성공인지 규칙 폴백인지 로그로 구분하고, 데이터 원천·추천·매수점수·목표가·체결 수를 짧게 정리해줘.
LLM이 정량 점수·추천·목표가·손절가를 올릴 수 없고 BUY를 HOLD로만 veto할 수 있는지 코드와 결과를 함께 설명해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마. 매매는 simulation으로 유지해.
```

### 성공 증거

- 실제 LLM 성공 또는 규칙 폴백이 로그로 구분됨
- 점수·목표가·손절가가 규칙 소유라는 설명이 있음

### 실행 후 한 문장

> LLM은 ___을 맡고, 점수와 가격은 ___이 정한다.

## P3-06 · 대시보드에서 결과 찾기

### 실행 전 예상

- 분석 근거와 피드백은 같은 화면에 있을까, 다른 곳에 있을까?

### 코딩 에이전트에 붙여넣기

```text
방금 실행한 lecture-prism의 mock 결과를 로컬 대시보드에서 확인하게 도와줘.
dashboard.py를 실행할 수 있는 선택 패키지가 준비되어 있는지 먼저 확인하고, 준비되어 있으면 로컬 대시보드를 열어줘.
매매현황, AI 분석 근거, 축적된 피드백이 각각 어디에 보이는지 짚어줘.
패키지가 없거나 대시보드 실행이 안 되면 기본 mock 파이프라인 성공과는 별개라고 설명하고, 설치나 다음 조치를 제안해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- 대시보드 또는 DB에 분석·시뮬레이션·피드백 기록이 보임
- 대시보드 실패와 기본 데모 실패를 구분함
