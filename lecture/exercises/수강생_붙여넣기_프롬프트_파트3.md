> 명령어를 직접 외우거나 입력하지 않습니다. 아래에서 **강사가 지정한 번호 하나만** 복사해 코딩 에이전트에 붙여넣으세요.
>
> 첫 30분의 공통 목표는 **P3-01과 P3-02**입니다. API 키나 계좌 연결 없이 시스템을 한 바퀴 돌리고, 각 단계에서 나온 결과를 읽습니다. 이후에는 강사가 부르는 모듈 프롬프트부터 하나씩 이어 갑니다.
>
> - **연습 데이터(mock)**: 실제 오늘 시장이 아니라, 같은 결과를 다시 확인할 수 있게 준비한 고정 연습 재료
> - **가상 체결(simulation)**: 주문을 증권사에 보내지 않고 “이 조건이면 샀을 것”만 기록하는 연습
> - **작업 흐름**: 후보 찾기 → 분석 보고서 작성 → 매수 시나리오 → 가상 실행 → 기록 남기기의 순서
>
> 실제 주문·브로커·계좌·시크릿은 어떤 프롬프트에서도 사용하지 않습니다. 실데이터와 OAuth는 기본 성공 뒤에만 하는 선택 관찰입니다.
>
## 매번 지킬 5단계

1. 질문한다: 이번 실행에서 무엇을 알고 싶은지 정한다.
2. 예측한다: `실행 전 예상`에 30초 동안 답한다.
3. 실행한다: 프롬프트 하나만 붙여넣는다.
4. 증거를 읽는다: `성공 증거` 중 한 가지를 확인한다.
5. 회고한다: `실행 후 한 문장`을 자기 말로 완성한다. 오류가 나면 P3-03만 사용한다.

## P3-01 · API 키 없는 첫 성공

### 실행 전 예상

- 이 실행에서 실제 오늘 데이터나 실제 주문이 나갈까?
- 후보 찾기 다음에는 어떤 일이 이어질까?

### 코딩 에이전트에 붙여넣기

```text
이 lecture-prism 프로젝트가 내 컴퓨터에서 연습 데이터로 안전하게 첫 실행이 되는지 확인해줘.

조건:
1. 현재 폴더가 lecture-prism 프로젝트 루트인지와 Python 3.10 이상인지 먼저 확인해줘.
2. 외부 패키지·API 키·브로커·계좌 설정은 추가하거나 읽지 말고, 프로젝트 루트에서 `python3 main.py`를 한 번만 실행해 기본 mock 작업 흐름을 확인해줘.
3. 후보 찾기 → 분석 보고서 작성 → 매수 시나리오 → 가상 체결 판단 → 피드백 기록이 모두 끝났는지 표로 정리해줘.
4. 연습 데이터(mock)인지, 실제 주문·브로커 API 호출이 없었는지 로그 근거를 한 줄씩 보여줘.
5. 실패하면 내가 터미널 명령어를 직접 치게 하지 말고, 원인과 API 키 없는 mock으로 돌아가기 위한 최소 조치만 설명해줘.
```

### 성공 증거

- 다섯 단계가 모두 끝났다는 로그
- `모의 데이터(mock)` 또는 연습 데이터라는 원천 표시
- 가상 체결(simulation) 또는 안전한 매수 보류 결과

### 실행 후 한 문장

> 이 실행은 ___ 데이터를 써서, ___까지 기록했고, 실제 주문은 ___.

## P3-M1 · screening.py 구조를 묻고 실행하기

### 실행 전 예상

- `screening.py`는 어떤 순서로 후보를 줄일까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 screening.py가 연습 종목을 어떤 순서로 줄이는지 초보자도 따라갈 수 있게 보여줘.

조건:
1. 코드는 수정하지 마.
2. 프로젝트 루트에서 `python3 screening.py`를 연습 데이터로 한 번만 실행해.
3. 처음 들어온 연습 종목 수 → 각 조건에서 빠진 종목과 이유 → 남은 종목의 정렬 기준 → 최종 후보를 실행 로그와 함께 순서대로 설명해.
4. 코드에서 mock 경로와 `--real` 경로가 어디서 갈라지는지만 짧게 알려줘. `--real`은 실행하지 마.
5. 후보로 뽑힌 것은 다음 단계에서 더 살펴볼 대상을 고른 것이지, 매수가 확정된 것은 아니라고 설명해.

7. 마지막에는 내가 지금까지 본 내용만으로 답할 수 있는 아래 질문 세 개를 남겨줘.
   - 어떤 조건이 종목을 가장 먼저 걸러냈는가?
   - 남은 후보는 어떤 기준으로 순서가 정해졌는가?
   - 후보로 뽑힌 것과 실제 매수 결정은 왜 다른가?

수업에서는 구조 확인과 단독 실행까지만 해. 숫자나 조건을 바꾸는 실험은 파트 4에서 한다고 마지막에 한 줄로만 안내해줘.
```

- 입력 → 필터 → 정렬 → 최대 3종목의 순서가 설명되어 있음
- `python3 screening.py`의 조건 로그와 선정 결과가 있음
- 탈락한 종목과 남은 종목의 이유가 쉬운 말로 구분되어 있음
- 후보 선정과 매수 결정이 다른 단계라는 설명이 있음

## P3-M3 · trading.py와 운영 루프를 묻고 실행하기

### 실행 전 예상

- BUY 의견이 있어도 trading.py가 보류할 수 있을까?
- 장중 가격이 바뀌면 보유종목은 누가 다시 확인할까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 buy_agent.py, trading.py와 operations.py를 읽고, 실제 주문 없이 매수 판단과 보조 운영 장치를 확인해줘.

조건:
1. 코드는 수정하지 마.
2. `python3 buy_agent.py 005930`, `python3 trading.py`, `python3 trading.py --exit`를 각각 한 번 실행해 매수 시나리오와 청산 순서를 설명해.
3. buy_agent.py가 보고서를 읽어 Enter / No Entry를 만드는 부분과 trading.py가 점수, 가격 배열, 손익비, 보유 수, 현금 한도를 다시 검사하는 위치를 보여줘.

5. operations.py의 batch·monitor·reconcile·compress·schedule 역할을 한 줄씩 설명해. schedule은 실행하지 마.
6. reconcile은 주문 상태를 읽어 맞추는 조회 작업이며 새 주문을 만들지 않는지 코드로 확인해.
7. BUY 의견이 있어도 trading.py가 보류할 수 있는 예를 이번 실행 결과나 코드 조건에서 하나 찾아줘.
8. 실제 주문·브로커·계좌·API 키·시크릿을 사용하지 말고, 모든 체결은 simulation으로 유지해.
```

### 성공 증거

- 분석 보고서 → 매수 에이전트 → 코드 진입 게이트가 분리되어 있음
- 청산 점검 순서가 손절 → 트레일링 스탑 → 목표가로 확인됨
- 보유종목 감시 결과가 피드백 단계로 돌아감
- 예약 루프를 켜지 않고 일회성 작업만 실행함

## P3-M4 · 피드백과 메모리 압축을 묻고 실행하기

### 실행 전 예상

- 매수 직후에 성공·실패 교훈을 만들 수 있을까?
- 오래된 교훈을 모두 프롬프트에 넣으면 어떤 문제가 생길까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 feedback.py, memory.py, db.py, operations.py를 읽고 피드백과 메모리 압축 흐름을 연습 데이터로 확인해줘.

조건:
1. 코드는 수정하지 마.
2. BUY 직후에는 체결 기록만 남고 결과 교훈을 만들지 않으며, SELL로 거래가 닫힌 뒤에만 판단 교훈을 만드는 코드 근거를 보여줘.
3. `python3 feedback.py`를 한 번 실행해 최근 교훈 조회 결과를 설명해.
4. `python3 operations.py compress`를 한 번 실행하고, 단기·중기·장기 기억의 기준과 이동 건수, 장기 기억 최대 개수를 정리해.
5. trading.py가 다음 판단 전에 관련 기억을 최대 몇 건, 어떤 우선순위로 읽는지 보여줘.
6. operations.py의 일요일 압축 작업은 시간표만 읽고 schedule은 실행하지 마.
7. 메모리를 쓴다고 수익이 보장되지 않으며, 오래된 교훈을 모두 다음 판단에 넣지 않는 이유를 설명해.
8. 실제 주문·브로커·계좌·API 키·시크릿은 사용하지 마.
```

### 성공 증거

- BUY 기록과 SELL 결과 교훈이 구분되어 있음
- 단기 → 중기 → 장기 이동 기준과 장기 기억 제한이 보임
- 다음 매매 판단이 관련 기억만 제한적으로 읽음
- 압축 작업이 연습 DB에서 안전하게 끝남

### 실행 후 한 문장

## P3-04 · 선택: 실데이터 관찰

```text
실제 주문·브로커 API·계좌 설정은 절대 사용하거나 바꾸지 마. 매매는 simulation으로 유지해.
```

## P3-05 · 선택: 공식 Codex OAuth research

> 공식 Codex 로그인이 이미 준비된 사람만 합니다. 기본 실습의 성공 조건은 아닙니다. 수업 중 로그인·설치를 기다리지 않습니다.

### 실행 전 예상

- LLM이 바꿀 수 있는 것과 바꿀 수 없는 것은 각각 무엇일까?

### 코딩 에이전트에 붙여넣기

```text
공식 Codex CLI의 로그인 상태만 사용해 lecture-prism의 research 분석과 simulation 전체 흐름을 삼성전자 005930 한 종목으로 점검해줘.

LECTURE_PROFILE=research와 LECTURE_LLM_MODE=oauth를 이번 실행에만 적용해.
토큰·인증 파일·시크릿은 읽거나 출력하거나 복사하지 말고, Perplexity와 Firecrawl도 사용하지 마.
main.py의 단일 종목 전체 흐름으로 분석→가상 매매→피드백까지 실행해줘.
실제 LLM 응답 성공인지 규칙 폴백인지 로그로 구분하고, 데이터 원천·추천·매수점수·목표가·simulation 체결 수를 짧게 정리해줘.
LLM이 정량 점수·추천·목표가·손절가를 올릴 수 없고 BUY를 HOLD로만 veto할 수 있는지 코드와 결과를 함께 설명해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마. 매매는 simulation으로 유지해.
```

### 성공 증거

- 실제 LLM 성공 또는 규칙 폴백이 로그로 구분됨
- 점수·목표가·손절가가 규칙 소유라는 설명이 있음

### 실행 후 한 문장

## P3-06 · 대시보드에서 결과 찾기

### 실행 전 예상

- 분석 근거와 피드백은 같은 화면에 있을까, 다른 곳에 있을까?

### 코딩 에이전트에 붙여넣기

```text
방금 실행한 lecture-prism의 연습 결과를 로컬 대시보드에서 확인하게 도와줘.
dashboard.py를 실행할 수 있는 선택 패키지가 준비되어 있는지 먼저 확인하고, 준비되어 있으면 로컬 대시보드를 열어줘.
매매현황, AI 분석 근거, 축적된 피드백이 각각 어디에 보이는지 짚어줘.
패키지가 없거나 대시보드 실행이 안 되면 기본 mock 파이프라인 성공과는 별개라고 설명하고, 설치나 다음 조치를 제안해줘.
실제 주문·브로커·계좌 설정은 절대 사용하지 마.
```

### 성공 증거

- 대시보드 또는 DB에 분석·시뮬레이션·피드백 기록이 보임
- 대시보드 실패와 기본 연습 실행 실패를 구분함
