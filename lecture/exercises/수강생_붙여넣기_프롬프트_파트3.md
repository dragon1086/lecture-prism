# 파트 3 — 수강생 붙여넣기 프롬프트

> 명령어를 직접 외우거나 입력하지 않습니다. 아래에서 **강사가 지정한 번호 하나만** 복사해 코딩 에이전트에 붙여넣으세요.
>
> 첫 30분의 공통 목표는 **P3-01과 P3-02**입니다. API 키나 계좌 연결 없이 시스템을 한 바퀴 돌리고, 각 단계에서 나온 결과를 읽습니다. 이후에는 강사가 부르는 모듈 프롬프트부터 하나씩 이어 갑니다.
>
> - **연습 데이터(mock)**: 실제 오늘 시장이 아니라, 같은 결과를 다시 확인할 수 있게 준비한 고정 연습 재료
> - **가상 체결(simulation)**: 주문을 증권사에 보내지 않고 “이 조건이면 샀을 것”만 기록하는 연습
> - **작업 흐름**: 후보 찾기 → 자료 읽기 → 가상 판단 → 기록 남기기의 순서
>
> 이번 실행에서 꼭 확인할 한 가지를 먼저 적어 둡니다. 강의에서는 이 한 줄을 **북극성**이라고 부릅니다.
>
> 실제 주문·브로커·계좌·시크릿은 어떤 프롬프트에서도 사용하지 않습니다. 실데이터와 OAuth는 기본 성공 뒤에만 하는 선택 관찰입니다.

## 매번 지킬 5단계

1. 질문한다: 이번 실행에서 무엇을 알고 싶은지 정한다.
2. 예측한다: `실행 전 예상`에 30초 동안 답한다.
3. 실행한다: 프롬프트 하나만 붙여넣는다.
4. 증거를 읽는다: `성공 증거` 중 한 가지를 확인한다.
5. 회고한다: `실행 후 한 문장`을 자기 말로 완성한다. 오류가 나면 P3-03만 사용한다.

## P3-01 · API 키 없는 첫 성공

### 실행 전 예상

- 이 실행에서 실제 오늘 데이터나 실제 주문이 나갈까?
- 후보 찾기 다음에는 어떤 일이 이어질까?

### 코딩 에이전트에 붙여넣기

```text
이 lecture-prism 프로젝트가 내 컴퓨터에서 연습 데이터로 안전하게 첫 실행이 되는지 확인해줘.

조건:
1. 현재 폴더가 lecture-prism 프로젝트 루트인지와 Python 3.10 이상인지 먼저 확인해줘.
2. 외부 패키지·API 키·브로커·계좌 설정은 추가하거나 읽지 말고, 프로젝트 루트에서 `python3 main.py`를 한 번만 실행해 기본 mock 작업 흐름을 확인해줘.
3. 후보 찾기 → 자료 읽기 → 가상 체결 판단 → 피드백 기록이 모두 끝났는지 표로 정리해줘.
4. 연습 데이터(mock)인지, 실제 주문·브로커 API 호출이 없었는지 로그 근거를 한 줄씩 보여줘.
5. 실패하면 내가 터미널 명령어를 직접 치게 하지 말고, 원인과 API 키 없는 mock으로 돌아가기 위한 최소 조치만 설명해줘.
```

### 성공 증거

- 네 단계가 모두 끝났다는 로그
- `모의 데이터(mock)` 또는 연습 데이터라는 원천 표시
- 가상 체결(simulation) 또는 안전한 매수 보류 결과

### 실행 후 한 문장

> 이 실행은 ___ 데이터를 써서, ___까지 기록했고, 실제 주문은 ___.

## P3-M1 · screening.py 구조를 묻고 실행하기

### 실행 전 예상

- `screening.py`는 어떤 순서로 후보를 줄일까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 screening.py를 읽고 직접 실행한 뒤, 원본 PRISM 스크리닝과 어디까지 같고 무엇이 빠졌는지 보여줘.

조건:
1. 코드는 수정하지 마.
2. 프로젝트 루트에서 `python3 screening.py`를 연습 데이터로 한 번 실행해. 입력 → 필터 → 정렬 → 최종 3개를 실제 코드와 실행 결과로 설명해.
3. mock과 `--real` 경로를 나눠 보고, 이동평균 조건이 실제로 어디에 적용되는지도 확인해.
4. 원본 PRISM Insight의 오전·오후 6개 신호, 공통 하한, 시장별 재점수, 최종 3개 자리 배분과 비교해.
5. 비교 결과를 `구현됨 / 작게 구현됨 / 아직 없음` 세 칸으로 정리해.
6. 이미지 생성 도구를 쓸 수 있으면 큰 글자의 고밀도 구조도 한 장을 만들어. 이미지 생성이 안 되면 각 단계를 눌러 설명을 여는 로컬 HTML을 만들고 브라우저로 열어줘.
7. 실제 주문·브로커·계좌·시크릿은 쓰지 마.
8. 마지막에는 아래 질문을 남겨줘.
   - 나는 어떤 종목부터 모으고 싶은가?
   - 여러 후보가 남으면 무엇으로 순서를 정할 것인가?
   - 이 후보는 뒤의 매수 방식과 왜 잘 맞는가?

수업에서는 구조 확인과 단독 실행까지만 해. 조건을 바꾸는 실험은 파트 4나 개인 실습에서 이어갈 수 있다고 마지막에만 안내해줘.
```

### 성공 증거

- 입력 → 필터 → 정렬 → 최대 3종목의 순서가 설명되어 있음
- `python3 screening.py`의 조건 로그와 선정 결과가 있음
- mock과 `--real`의 이동평균 적용 차이가 구분되어 있음
- 원본 PRISM과 강의용 축소판의 차이가 세 칸으로 정리되어 있음
- 이미지 한 장 또는 클릭해서 읽는 로컬 HTML이 만들어져 있음

## P3-M3 · trading.py와 운영 루프를 묻고 실행하기

### 실행 전 예상

- BUY 의견이 있어도 trading.py가 보류할 수 있을까?
- 장중 가격이 바뀌면 보유종목은 누가 다시 확인할까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 trading.py와 operations.py를 읽고, 실제 주문 없이 매매 판단과 보조 운영 장치를 확인해줘.

조건:
1. 코드는 수정하지 마.
2. `python3 trading.py`와 `python3 trading.py --exit`를 각각 한 번 실행해 신규 진입과 손절·트레일링 스탑·목표가 청산 순서를 설명해.
3. 분석의 BUY를 받은 뒤에도 buy_score, 가격 배열, 손익비, 보유 수, 현금 한도를 다시 검사하는 코드 위치를 보여줘.
4. 원본 PRISM의 CAN SLIM, 신규 진입, 피라미딩, 매도 순서, 보호 루프와 비교해 `구현됨 / 작게 구현됨 / 아직 없음`으로 나눠.
5. `python3 operations.py monitor`를 한 번 실행해 보유종목 감시가 청산 판단 → simulation 체결 → feedback으로 이어지는지 확인해.
6. operations.py의 batch·monitor·reconcile·compress·schedule 역할과 기본 시간표를 읽어 설명해. schedule은 실행하지 마.
7. reconcile은 주문 상태를 읽어 맞추는 조회 작업이며 새 주문을 만들지 않는지 코드로 확인해.
8. 실제 주문·브로커·계좌·시크릿을 사용하지 말고, 모든 체결은 simulation으로 유지해.
```

### 성공 증거

- 분석 의견 뒤에 별도의 진입 게이트가 있음
- 청산 점검 순서가 손절 → 트레일링 스탑 → 목표가로 확인됨
- 보유종목 감시 결과가 피드백 단계로 돌아감
- 예약 루프를 켜지 않고 일회성 작업만 실행함

## P3-M4 · 피드백과 메모리 압축을 묻고 실행하기

### 실행 전 예상

- 매수 직후에 성공·실패 교훈을 만들 수 있을까?
- 오래된 교훈을 모두 프롬프트에 넣으면 어떤 문제가 생길까?

### 코딩 에이전트에 붙여넣기

```text
lecture-prism의 feedback.py, memory.py, db.py, operations.py를 읽고 피드백과 메모리 압축 흐름을 연습 데이터로 확인해줘.

조건:
1. 코드는 수정하지 마.
2. BUY 직후에는 체결 기록만 남고 결과 교훈을 만들지 않으며, SELL로 거래가 닫힌 뒤에만 판단 교훈을 만드는 코드 근거를 보여줘.
3. `python3 feedback.py`를 한 번 실행해 최근 교훈 조회 결과를 설명해.
4. `python3 operations.py compress`를 한 번 실행하고, 단기·중기·장기 기억의 기준과 이동 건수, 장기 기억 최대 개수를 정리해.
5. trading.py가 다음 판단 전에 관련 기억을 최대 몇 건, 어떤 우선순위로 읽는지 보여줘.
6. operations.py의 일요일 압축 작업은 시간표만 읽고 schedule은 실행하지 마.
7. 원본 PRISM의 매매일지 → 교훈 → 재진입 제한과 비교해 `구현됨 / 작게 구현됨 / 아직 없음`으로 나눠.
8. 메모리를 쓴다고 수익이 보장되지 않으며, 교훈도 검증·비활성화·압축 대상이라는 점을 설명해.
9. 실제 주문·브로커·계좌·시크릿은 사용하지 마.
```

### 성공 증거

- BUY 기록과 SELL 결과 교훈이 구분되어 있음
- 단기 → 중기 → 장기 이동 기준과 장기 기억 제한이 보임
- 다음 매매 판단이 관련 기억만 제한적으로 읽음
- 압축 작업이 연습 DB에서 안전하게 끝남

### 실행 후 한 문장

> 결과가 닫히면 ___이 교훈을 만들고, ___이 반복된 교훈만 오래 남기며, 다음 판단은 ___만 제한적으로 읽는다.
