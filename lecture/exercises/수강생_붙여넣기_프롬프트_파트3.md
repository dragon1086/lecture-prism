> 명령어를 직접 외우거나 입력하지 않습니다. 아래에서 **강사가 지정한 번호 하나만** 복사해 코딩 에이전트에 붙여넣으세요.
>
> 첫 30분의 공통 목표는 **P3-01과 P3-02**입니다. 준비된 사람은 실데이터와 Discord까지 포함해 전체 흐름을 보고, 준비가 안 된 사람은 연습 데이터로 같은 흐름을 확인합니다. 어느 경로든 API 키나 계좌 연결 없이 가상 매매로 끝납니다.
>
> - **연습 데이터(기술 이름: mock)**: 실제 오늘 시장이 아니라, 같은 결과를 다시 확인할 수 있게 준비한 고정 연습 재료
> - **실데이터(real_data)**: 인터넷에서 받은 실제 가격·거래량을 쓰되, 실패하면 연습 데이터로 돌아가는 선택 경로
> - **가상 체결(simulation)**: 주문을 증권사에 보내지 않고 “이 조건이면 샀을 것”만 기록하는 연습
> - **Discord 판단 알림**: 계좌 정보가 아니라 이번 실행의 후보·분석·매매 판단을 보내는 선택 알림
> - **작업 흐름**: 후보 찾기 → 분석 보고서 작성 → 매수 시나리오 → 가상 실행 → 기록 남기기의 순서
>
> 실제 주문·브로커·계좌·시크릿은 어떤 프롬프트에서도 사용하지 않습니다. 실데이터와 Discord는 P3-01에서 준비된 사람만 선택합니다. 실제 LLM은 P3-M2 뒤에서 한 번 확인하되, 공식 Codex 로그인이 준비된 사람과 준비되지 않은 사람이 서로 다른 프롬프트로 시작해 P3-M3으로 다시 합류합니다.
>
> 모든 실행은 프로젝트 루트의 `.venv`를 사용합니다. 수강생이 직접 환경을 켜거나 Python 경로를 입력하지 않고, 코딩 에이전트가 준비된 `.venv`의 Python으로 실행하게 합니다.
>
> 수업 전 공통 준비에서 프로젝트 루트의 `.venv`에 `requirements.txt` 전체를 설치합니다. 패키지가 설치되어 있어도 실데이터·Discord·OAuth·브로커가 자동으로 켜지는 것은 아니며, 첫 실행에서 준비 상태를 확인한 뒤 안전하게 연습 데이터 경로로 돌아갈 수 있습니다.
>
> 실데이터·Discord처럼 인터넷을 쓰는 선택 기능은 코딩 에이전트가 필요한 도메인에 대한 **범위 제한 네트워크 승인**을 요청한 뒤에만 실행합니다. 전역 샌드박스를 끄거나 권한을 통째로 우회하지 않습니다.
>

```text
8. 실제 주문·브로커·계좌·API 키·시크릿은 사용하지 마.
9. 마지막에는 내가 직접 답할 아래 질문 세 개를 질문만 남겨줘. 답을 대신 쓰지 마.
```

## P3-M5 · 내 컴퓨터의 운영 준비 상태 확인하기

### 실행 전 예상

- 한 번 실행에 성공한 프로그램을 매일 안전하게 돌리려면 무엇을 더 확인해야 할까?

이 실습에서는 설치나 연결 설정을 바꾸지 않습니다. 코딩 에이전트가 현재 상태를 읽고, 준비된 것과 빠진 것만 쉬운 말로 알려 줍니다.

### 무엇을 실행하나요?

수강생이 터미널 명령어를 직접 입력하지 않습니다. 아래 첫 번째 프롬프트를 붙여넣으면 코딩 에이전트가 준비 상태 점검(doctor)과 현재 상태 확인을 읽기 전용으로 실행합니다.

### 코딩 에이전트에 붙여넣기 1 · 준비된 것과 빠진 것 확인

```text
lecture-prism을 매일 안전하게 돌리기 전에 내 컴퓨터의 준비 상태를 확인해줘. 수강생이 터미널 명령어를 직접 입력하지 않습니다. 필요한 읽기 전용 명령은 네가 실행하고, 결과는 쉬운 한국어로 설명해줘.

조건:
1. 먼저 `operations.py doctor`와 `operations.py status`가 무엇을 읽는지 코드와 테스트에서 확인해. 둘 다 주문·취소 없이 상태만 읽는 것이 확인되면 실행해. 위험하거나 확실하지 않으면 실행하지 말고 이유를 알려줘.
2. 결과는 `준비됨(configured)`과 `준비 안 됨(missing)`으로 나눠 표로 보여줘. 설정값, API 키, 계좌번호, 토큰은 일부도 출력하지 마.
3. 운영 단계를 아래 한국어 이름으로 설명하고, 기술 이름은 괄호에 한 번만 적어줘.
   - 연습 데이터(mock)
   - 실데이터와 분석 보강(real_data, research)
   - 모의투자(paper)
   - 실거래(live)
4. 확인 순서는 `doctor → simulation → paper → live`를 지켜. 여기서 doctor는 준비 상태 점검이고, simulation은 증권사에 주문을 보내지 않는 실행 방식이라고 먼저 설명해. mock, real_data, research는 어떤 자료와 분석 기능을 쓸지 정하는 이름이라 이 안전 순서와 같은 종류의 단계가 아니라는 점도 알려줘. 앞 단계가 준비되지 않았으면 다음 단계로 넘어가지 마.

6. 컴퓨터가 맡을 다섯 일을 쉬운 말로 정리해. 정해진 때 시작하기(전체 배치), 보유 종목 살피기(보유 감시), 주문 결과 확인하기(주문 대사), 기록 정리하기(기억 압축), 이상 알려주기(상태·알림) 순서로 써.
7. KIS, Kiwoom, Toss 공식 Open API, Toss WTS의 차이는 `바로 사용 가능 / 추가 확인 필요 / 현재 사용하면 안 됨`으로 설명해. 정확한 기술 상태가 필요하면 READY나 CONDITIONAL 같은 원래 용어를 괄호에만 적어줘.
8. 코드를 수정하지 마. `.env`와 환경 변수도 만들거나 바꾸지 마. `LECTURE_ENABLE_LIVE_BROKER`, `LECTURE_ALLOW_REAL_BROKER`, `LECTURE_PROFILE`, `LECTURE_BROKER` 값을 바꾸지 마.

10. 마지막에는 지금 안전하게 실행할 수 있는 단계와 다음에 준비할 한 가지만 알려줘.

안전 문구는 그대로 지켜줘: 시크릿 값은 출력하지 마. 서비스 등록을 하지 마. 플래그 값을 바꾸지 마. 실제 주문·취소를 실행하지 마. 결과 표기는 준비됨(configured) / 준비 안 됨(missing)만 써.
```

### 코딩 에이전트에 붙여넣기 2 · 다음에 준비할 단계 고르기

```text

   - 컴퓨터가 자동으로 챙겨야 할 일은 무엇일까?
   - 준비가 덜 된 증권사는 무엇부터 더 확인해야 할까?

안전 문구는 그대로 지켜줘: 시크릿 값은 출력하지 마. 서비스 등록을 하지 마. 플래그 값을 바꾸지 마. 실제 주문·취소를 실행하지 마. 결과 표기는 준비됨(configured) / 준비 안 됨(missing)만 써.
```
