역할 배분 프레임워크

자율에이전트 맡기지 않는다
매매 실행을 에이전트에 완전히 위임하지 않음. 사람이 개선 방향을 판단하고 시스템이 실행하는 구조 강조.
AI-Native 전략의 우위
알고리즘 전략은 공개 즉시 파훼. AI-Native는 확률론적 의사결정이라 완전 복제 불가 → 오픈소스로 공유 가능한 유일한 전략.

CH 02 실전 프롬프트 공식 — 강사 라이브 시범 ⏱ 15분
강사가 준비한 시스템을 눈앞에서 즉석 수정합니다. "아, 이렇게 말 걸면 AI가 코드를 고쳐주는구나"를 체감 — 시스템을 성장시키는 프롬프트 공식 3개와, 같은 요청도 결과가 갈리는 Bad vs Good을 나란히 비교.
강사 시범 프롬프트 공식
Claude Code
"현재 screening.py는 거래량 5배 기준이야. RSI 30 이하 + 거래량 3배 조합으로 바꿔줘. 함수 시그니처는 유지해줘."
→ VOLUME_SURGE_RATIO 수정 + RSI 조건 추가 코드 생성
Claude Code
"이 에러가 났어: KeyError 'score' at trading.py:72. 원인 설명하고 고쳐줘."
→ 스택트레이스 분석 + 원인 설명 + 수정 코드 제안
Claude Code
"이 analysis.py 로직이 내 이론을 정확히 반영하는지 확인해줘. 내 이론: RSI 과매도 반등 + 거래량 동반 + 뉴스 촉매 3개 동시 충족 시 매수"
→ 코드와 이론 갭 분석 + 누락 조건 지적 + 보완 방향 제시
Bad vs Good: "코드 좀 고쳐줘" (❌) → "현재 [상태] + [원하는 결과] + [유지할 제약]" (✅)
CH 03 수강생 실습 — 본인 이론 구현 ⏱ 35분
이제 직접 차례. 고른 트랙으로 내 이론을 코드에 심고, 막히면 강사가 순회하며 "프롬프트가 문제인지, 코드가 문제인지"를 짚어줌. 35분 뒤엔 어제까지 남의 것이던 시스템이 내 로직으로 돌아갑니다.
실습 순회 코칭
트랙 A·B (진입): screening.py 조건 / analysis.py 프롬프트 교체
트랙 C·D (청산·리스크): trading.py의 _decide_exit 로직 / 포트폴리오 상수(슬랏·현금·손절) 교체
막히는 수강생: "프롬프트를 어떻게 바꿔야 하는가"를 코칭 (정답 주지 말고 방향만)
Claude Code
"main.py 전체 파이프라인 실행해봐. 내가 수정한 screening 로직이 제대로 통합되는지 확인하고 싶어"
→ 스크리닝 → 분석 → 매매 → 피드백 전 사이클 실행 + 내 로직 반영 여부 출력
CH 04 결과 공유 & 토론 ⏱ 15분
용기 낸 2-3명이 화면을 공유합니다. "내 이론 한 줄 → 뭘 바꿨나 → 방금 돌아간 결과." 남이 어떻게 풀었는지 보는 15분이 내 다음 아이디어가 됩니다.
발표 토론
발표 포맷: "내 이론 1줄 → 뭘 바꿨나 → 실행 결과 화면" (원하면 코딩 에이전트에게 “내 이름 브랜치로 보안 점검 후 제출해줘”라고 요청)
토론 질문: "이 로직이 실제로 의미 있으려면 어떻게 검증해야 할까?"
강사 코멘트: 각 이론의 장단점, 포워드 테스트(데모 운용)로 검증하는 방향 제안
CH 05 마무리 — 시스템을 발전시켜나가는 팁 ⏱ 15분
강의장을 나간 뒤가 진짜 시작. 거창한 로드맵 대신, 강사가 PRISM을 운영하며 실제로 순서대로 풀어온 고민들을 그대로 보여줍니다. 처음부터 13개 에이전트가 아니었고 — 부딪힌 문제를 하나씩 해결하다 보니 지금이 됐습니다. "이렇게 한 단계씩 키우면 되는구나"를 가져가는 게 목표.
마무리
제가 PRISM을 키워온 순서 (고민 → 해결):
① 한 LLM에 다 시켰더니 누락·편향 → 기술·뉴스·재무·전략을 전문 에이전트로 분리
② 매수보다 "언제 파는가"가 더 어려움 → 매도 판단을 규칙에서 AI 기반으로 전환
③ 손절이 당일 노이즈에 자꾸 걸림 → 진입 트리거(급등·거래량)별 손절폭 차등 + 트레일링으로 수익 보호
④ 종목은 좋아도 시장이 무너지면 끝 → 시장 국면·주도 섹터를 보는 Macro Intelligence 추가
⑤ 같은 실수를 반복함 → 매매일지 피드백 루프: 교훈을 다음 매매 프롬프트에 자동 주입
⑥ API 비용 부담 → ChatGPT 구독(OAuth)으로 전환해 운영비 절감 (파트3 CH1에서 배운 그것)
검증은 포워드 테스트: LLM은 비결정적·look-ahead·비용 때문에 백테스트가 부적합 → 데모 모드로 오늘부터 모의 운용하며 7/14/30일 성과를 쌓고, 충분히 검증되면 소액 실거래 → 슬랏 확대
끝까지 자율에이전트에 다 맡기지 않는다: 포워드 성과 3개월 검증 + 손절 로직 확실할 때만 비중 확대. 사람이 개선 방향을 잡고 시스템이 실행
커뮤니티 연결: GitHub PR 기여 / 텔레그램 토론방 / 개인 연락처

Prompt Chaining PRISM 사용
단계별 순차 처리. 각 LLM 호출이 이전 출력을 받아 처리. 중간 검증 포함.
→ 분석 에이전트 6개 순차 실행
Routing 코드 분기
입력 분류 후 전문 모듈로 분기. 다양한 케이스에 각각 최적화된 처리.
→ PRISM에선 코드 레벨 if/else (KR/US 분기). LLM이 분류 판단하진 않음.
Parallelization 데이터 레이어
독립 작업 동시 실행 or 같은 작업 N회 실행 후 투표 집계.
→ PRISM에선 데이터 프리패치 시 asyncio. 에이전트 간 병렬 실행은 아님.
Orchestrator-Workers PRISM 사용
중앙 에이전트가 동적으로 하위 에이전트에 위임하고 결과를 통합.
→ Orchestrator → 투자전략 에이전트 → 6개 분석 에이전트
Evaluator-Optimizer PRISM 사용
생성 에이전트 + 평가 에이전트 반복 루프. 품질 기준 도달까지 반복.
→ Summary Optimizer + Quality Evaluator (EXCELLENT까지 루프)
Autonomous Agents 외부 도구
도구 사용하며 스스로 계획·실행. 초기 지시만 받고 이후 자율 동작.
→ PRISM 파이프라인 자체가 아닌 Claude Code로 PRISM을 유지보수하는 개발 패턴.
