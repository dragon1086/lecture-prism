# PRISM 원본 기반 강의 질문 은행

이 문서는 실제 구독자 인터뷰에서 나온 질문과, 비슷한 수강생이 이어서 물을 만한 질문을 한곳에 모은 강사용 답변집입니다. 자세한 코드 구조는 [PRISM 원본 `run_full_pipeline` 전체 아키텍처](run-full-pipeline-architecture.md)를 먼저 참고하세요.

## 답변 상태

| 표시 | 뜻 |
|---|---|
| **현재 있음** | 원본 `run_full_pipeline()` 또는 직접 연결된 경로에서 동작 |
| **일부 있음** | 바탕은 있으나 질문 그대로 완성되지는 않음 |
| **새 모듈 필요** | 현재 경로에는 없고 입력·저장·판단 연결을 추가해야 함 |
| **별도 시스템** | 원본의 다른 시장·봇·배치에 있으나 KR 주 파이프라인과 분리됨 |
| **강의 범위 밖** | 4주 입문 실습에서 안전하게 구현하기에는 범위가 큼 |

## 1. 실제 구독자 질문

### Q1. 수업 전에 원본 PRISM과 API 유료 결제까지 해야 하나요?

**짧은 답:** 아닙니다. 강의는 원본 PRISM이 아니라 간소화한 `lecture-prism`으로 진행하고, 기본 실습은 API 키 없이 데모가 완주합니다. 필요한 것은 ChatGPT Plus와 Codex를 쓸 수 있는 환경입니다.

**원본과의 차이:** 원본은 KRX 로그인, LLM, Playwright, Telegram, KIS 같은 운영 설정이 여러 개 필요합니다. 그 구조를 그대로 수업 첫날에 설치하면 전략 구현보다 환경 문제에 시간을 더 쓰게 됩니다.

**상태:** 강의 저장소에 준비됨.

### Q2. 강사가 예시만 보여주나요, 각자 전략을 구현할 시간도 있나요?

**짧은 답:** 둘 다 합니다. 먼저 강사가 원본 구조가 강의용 코드에서 어떻게 줄어들었는지 보여주고, 3주차에 각자 전략을 세 줄로 정리한 뒤 4주차에 진입·분석·청산·리스크 중 한 축을 바꿉니다.

**강의 기준:** 처음부터 전체 시스템을 새로 만들지 않습니다. 한 번에 한 축만 바꾸고 데모 결과를 비교하면 비전공자도 본인 아이디어가 코드에 들어가는 과정을 확인할 수 있습니다.

**상태:** 강의 계획에 반영됨.

### Q3. 터틀 추세추종을 간단히 구현하고 나중에 변형할 수 있나요?

**짧은 답:** 가능합니다. 다만 원본에 “터틀”이라는 완성 전략이 들어 있는 것은 아닙니다. 원본에는 이동평균, 상대강도, 돌파 확인, 손절, 트레일링 등 필요한 부품이 이미 있습니다.

**권장 첫 버전:**

- 20일 신고가 돌파 시 후보
- 10일 저가 이탈 시 청산
- 시장이 약세면 신규 진입 수를 줄임
- ATR 손절과 수량 계산은 다음 단계로 추가

**상태:** 일부 있음. lecture-prism에서는 진입과 청산 트랙으로 구현 가능.

### Q4. ATR로 손절과 비중을 정할 수 있나요?

**짧은 답:** 만들 수 있지만 현재 원본의 표준 주문 수량은 ATR 방식이 아닙니다.

원본은 ADR을 과열 감점에 쓰고, 변동성으로 빠진 목표가·손절가를 보완합니다. 실제 KIS 주문 수량은 `종목당 고정 매수금액 ÷ 현재가`입니다. 터틀식으로 만들려면 다음 계산을 주문 앞에 넣어야 합니다.

```text
한 거래 허용손실 = 계좌자산 × 위험률
1주 위험 = 진입가 - ATR 손절가
수량 = 한 거래 허용손실 ÷ 1주 위험
```

**상태:** 새 수량 계산 로직 필요.

### Q5. KOSPI 시황을 보고 장이 나쁘면 줄이고, 좋으면 더 살 수 있나요?

**짧은 답:** 이 부분은 원본에 이미 여러 겹으로 들어 있습니다.

- KOSPI·KOSDAQ으로 강세·횡보·약세를 계산
- 강세에서는 상대강도가 높은 종목을 더 우대
- 약세에서는 과열 종목 감점을 강화
- 약세일수록 최소 점수·손익비를 높이고 최대 손절폭을 줄임
- 최대 보유 수를 6~10으로 조정
- 강한 장에서는 수익 중인 같은 종목을 추가 진입할 수 있음

다만 금액 자체를 ATR이나 계좌 위험률로 연속 조절하지는 않습니다. 현재는 “슬롯 수와 진입 문턱”으로 비중을 바꾸는 방식입니다.

**상태:** 현재 있음. 금액 단위의 정교한 사이징은 추가 필요.

### Q6. 시황 흐름을 AI가 휴리스틱하게 판단해도 되나요?

**짧은 답:** 됩니다. 원본도 이미 코드와 AI의 역할을 나눕니다.

- 이동평균, 수익률, 분산일처럼 계산 가능한 것은 Python이 판단
- 주도 업종, 위험 사건, 뉴스의 지속성처럼 문맥이 필요한 것은 LLM이 판단
- 마지막 매수는 두 결과를 함께 읽고 결정

강의에서는 “AI가 전부 판단”보다 이 분업이 안전하고 설명하기 쉽다는 점을 보여주면 됩니다.

**상태:** 현재 있음.

### Q7. 외국인 리포트나 유료 콘텐츠 캡처를 넣어 매도 판단에 반영할 수 있나요?

**짧은 답:** 기술적으로 가능하지만 현재 KR 자동배치에는 그 입력 통로가 없습니다.

Telegram AI 봇은 이미 이미지를 받아 해석할 수 있습니다. 하지만 그 결과는 대화 안에만 남고 `run_full_pipeline()`, 종목 보고서, 매매 DB로 넘어가지 않습니다. 표준 파이프라인에 넣으려면 다음 중간 모듈이 필요합니다.

```text
캡처·PDF 입력
  → OCR 또는 비전 해석
  → 종목·작성일·출처·핵심 주장·유효기간 구조화
  → 사용자가 확인
  → 해당 종목의 분석 컨텍스트에 추가
  → 매수·매도 프롬프트에서 참고
```

저작권이 있는 자료는 원문을 다시 배포하지 않고, 사용자가 가진 자료를 개인 판단에 참고하는 범위와 보관 정책을 정해야 합니다.

**상태:** 새 모듈 필요.

### Q8. 공시도 같이 판단할 수 있나요?

**짧은 답:** 현재 KR 주 파이프라인은 WiseReport와 뉴스가 중심이며 DART 공시 전용 단계는 없습니다.

공시는 뉴스보다 구조가 분명하므로 AI에게 원문 전체를 던지기 전에 공시 종류, 금액, 상대방, 발행주식 대비 비율, 일정, 정정 여부를 코드로 뽑는 편이 낫습니다. 그 요약을 뉴스·매도 에이전트에 넣으면 됩니다.

**상태:** 새 모듈 필요.

### Q9. 강화학습으로 계속 매매 기능을 개선할 수 있나요?

**짧은 답:** 원본의 자기개선은 강화학습이 아닙니다.

현재 시스템은 거래가 끝나면 매매일지를 쓰고, 교훈과 반복 패턴을 DB에 저장한 뒤 다음 판단 프롬프트에 넣습니다. 트리거별 30일 성과도 참고합니다. 보상으로 모델 가중치를 자동 업데이트하는 강화학습 코드는 없습니다.

수강생에게는 “처음부터 강화학습”보다 다음 순서가 현실적입니다.

1. 모든 입력·결정·결과를 빠짐없이 저장
2. 같은 조건에서 결과가 반복되는지 통계 확인
3. 프롬프트와 규칙을 한 번에 하나씩 수정
4. 수정 전후 결과 비교
5. 데이터와 평가기가 충분해진 뒤 학습 모델 검토

**상태:** 기억 기반 피드백은 현재 있음. 강화학습은 강의 범위 밖.

### Q10. 매도 후 단기·중기·장기 기억으로 나누나요?

**짧은 답:** 원본은 비슷한 구조를 갖습니다.

- 0~7일: 상세 거래 일지
- 8~30일: 짧은 상황·행동·결과 요약
- 31일 이후: 반복 조건과 원칙 형태의 직관

압축은 `run_full_pipeline()` 안에서 바로 하지 않고 별도 주기 작업으로 실행합니다.

**상태:** 현재 있음. 기본은 비활성이라 설정 필요.

### Q11. 나중에 선물에도 적용할 수 있나요?

**짧은 답:** 분석 아이디어는 옮길 수 있지만 주문·리스크 구조는 새로 봐야 합니다.

현물 주식과 달리 선물은 레버리지, 증거금, 강제청산, 펀딩비, 만기, 양방향 포지션이 있습니다. 종목 선별과 시황 판단은 재사용할 수 있어도 수량·손절·주문·계좌 안전장치는 별도 모듈로 분리해야 합니다.

원본에는 BTC 선물용 `prism-btc`가 별도 시스템으로 존재하지만 KR 주식 `run_full_pipeline()`과 같은 경로는 아닙니다.

**상태:** 별도 시스템. 4주 강의 범위 밖.

### Q12. 지수 ETF와 업종 ETF 비중을 시황에 맞춰 바꿀 수 있나요?

**짧은 답:** 가능합니다. 개별 종목보다 데이터 구조가 단순해 가족용 장기 포트폴리오 실습에도 잘 맞습니다.

다만 원본 KR 주 파이프라인은 “후보 종목 최대 3개 → 종목별 보고서 → 10슬롯” 구조라 ETF 자산배분 엔진은 아닙니다. 다음 상태를 가진 별도 전략 세트가 더 깔끔합니다.

- 현금, 지수 ETF, 업종 ETF 목표 비중
- 월·주 단위 리밸런싱
- 장세별 허용 위험
- ETF별 추세와 상대강도
- 거래비용과 최소 변경 폭

**상태:** 새 전략 세트 필요.

### Q13. 프리즘 안에서 메일·알림 같은 기능을 모듈식으로 붙일 수 있나요?

**짧은 답:** 가능합니다. 원본도 Telegram, Redis, GCP Pub/Sub, Firebase를 선택 기능으로 붙입니다.

분석 에이전트마다 메일 코드를 넣기보다 `analysis_completed`, `buy_signal`, `sell_signal` 같은 이벤트를 만들고 구독 모듈이 처리하는 편이 유지보수하기 쉽습니다. n8n 없이도 Python 모듈 하나로 이메일·슬랙·웹훅을 붙일 수 있습니다.

**상태:** 일부 있음. 이메일 어댑터는 새로 필요.

### Q14. 상승률 상위 50, 거래대금 상위 50을 업종·테마로 묶을 수 있나요?

**짧은 답:** 업종은 가깝고, 테마는 외부 매핑이 필요합니다.

원본은 KRX 업종 맵과 상승률·거래대금 트리거를 이미 갖고 있습니다. 다만 최종 출력은 최대 3종목이므로 상위 50 시장판을 만들려면 선별 결과를 자르기 전 별도 집계 화면을 만들어야 합니다. 테마는 ThinkPool 같은 외부 소스의 테마-종목 관계를 날짜와 함께 저장해야 합니다.

**상태:** 업종 일부 있음, 테마 새 모듈 필요.

### Q15. Docker로 한 번에 운영할 수 있나요?

**짧은 답:** 원본에는 Docker Compose와 cron 구성이 있습니다. 다만 현재 코드와 문서 사이에 DB 마운트, 차트 경로, 일부 스크립트 연결이 맞지 않는 구간이 있어 “설치하면 모든 기능이 그대로 돈다”고 단정하기 전에 점검해야 합니다.

강의용 `lecture-prism`은 Docker 운영보다 코딩 에이전트로 데모를 완주하고 전략 한 축을 바꾸는 데 초점을 둡니다.

**상태:** 원본에 있음. 운영 점검 필요.

## 2. 전략·지표 질문

### Q16. 이동평균, RSI, MACD, 볼린저밴드를 모두 쓰나요?

원본 주가·거래량 에이전트의 분석 지침에는 모두 들어 있습니다. 다만 지표가 많다고 매수 품질이 자동으로 좋아지지는 않습니다. 최종 거래 에이전트는 펀더멘털, 종목 추세, 모멘텀, 시장 상태, 손익비를 묶어 봅니다.

**상태:** 현재 있음.

### Q17. 지표가 서로 반대 신호를 내면 누가 결정하나요?

계산된 사실은 보고서에 남고, 거래 시나리오 LLM이 시장별 진입 표에 맞춰 결론을 냅니다. 그 뒤 Python이 점수, 업종 집중, 슬롯, 재진입 제한을 다시 검사합니다. AI 결론 하나로 바로 주문하지 않습니다.

**상태:** 현재 있음.

### Q18. 손익비는 수량에도 반영되나요?

아닙니다. 손익비는 후보 점수와 진입 허용에 쓰이지만 KIS 주문 수량은 고정 매수금액 기준입니다. 손익비·ATR·계좌 위험률을 수량까지 연결하려면 포지션 사이징을 별도 구현해야 합니다.

**상태:** 진입 판단에는 있음, 수량에는 없음.

### Q19. 강세장에서 목표가에 오면 바로 파나요?

거래 프롬프트는 강세장 목표가를 “전량 매도점”보다 “트레일링을 시작할 이정표”로 봅니다. 하지만 실제 `run_full_pipeline()`은 Enhanced 매도 경로를 타므로 부모 클래스의 명확한 오닐 규칙과 완전히 같다고 보면 안 됩니다.

**상태:** 프롬프트와 부모 규칙에 있음. 실제 주 경로는 차이 있음.

### Q20. 손절은 종가 기준인가요, 장중 가격 기준인가요?

프롬프트와 부모 오닐 엔진은 종가 기준 취지를 강조하고 0.5% 완충을 둡니다. 그러나 Enhanced 경로에는 현재 조회가가 저장 손절가 이하인지 먼저 보는 규칙이 있어 더 빠르게 매도할 수 있습니다.

**상태:** 실제 경로와 설계 의도가 다름.

### Q21. 추세가 좋은 종목을 더 사는 피라미딩이 있나요?

있습니다. 강한 강세, 기존 평균단가 대비 +5% 이상, 같은 종목 3슬롯 미만일 때 추가 진입을 검토합니다. 추가 진입도 독립 슬롯 하나를 씁니다.

이것은 손실 종목을 더 사는 물타기가 아닙니다. 강세장에서 이미 수익 중인 리더에만 최대 두 번 더 싣는 구조이며, 전체 10슬롯·업종 한도·새 진입 점수도 다시 통과해야 합니다. 행별 청산 수량을 나눠 주문해 같은 종목을 과도하게 매도하지 않도록 처리합니다. 상세 구조는 [매매·시황·비중 제어 문서](trading-and-regime-architecture.md)를 참고합니다.

**상태:** 현재 있음.

### Q22. 섹터 쏠림은 어떻게 막나요?

같은 업종 최대 3슬롯, 보유 4개 이상일 때 업종 비율 30% 제한을 확인합니다. 거래 에이전트도 현재 업종 분포를 읽습니다.

**상태:** 현재 있음.

## 3. 데이터와 AI 질문

### Q23. 어떤 것은 코드로 하고 어떤 것은 AI로 하나요?

**코드가 잘하는 일:** 가격 계산, 이동평균, 점수, 한도, 중복 제거, DB 저장, 주문 상태.

**AI가 잘하는 일:** 뉴스 재료의 의미, 사업 경쟁력, 위험 사건의 영향 경로, 여러 보고서의 종합 설명.

판단 기준은 “같은 입력에 항상 같은 답이 나와야 하는가?”입니다. 그렇다면 우선 코드로 만듭니다.

### Q24. 뉴스가 틀리거나 오래됐으면 어떻게 하나요?

에이전트 프롬프트는 날짜와 출처 확인을 지시하지만 코드가 모든 주장과 출처를 다시 검증하지는 않습니다. 중요한 재료는 작성일, 사건일, 출처 URL, 종목코드를 구조화하고, 오래된 자료에는 유효기간을 두는 개선이 필요합니다.

**상태:** 일부 있음.

### Q25. AI가 같은 자료를 보고 매번 다르게 판단하지 않나요?

가능합니다. 그래서 입력 원문, 프롬프트 버전, 모델명, 출력 JSON, 실제 결과를 함께 저장해야 합니다. 비교 실험에서는 한 번에 한 요소만 바꿔야 원인을 알 수 있습니다.

**상태:** 일부 기록은 있으나 완전한 실험 추적 체계는 별도 정리 필요.

### Q26. LLM이 실패하면 매수해 버릴 수도 있나요?

거래 시나리오 생성이 실패하면 기본값은 점수 0과 미진입입니다. 이 경로는 안전하게 닫힙니다. 반면 거시 분석은 실패해도 기본 트리거를 계속 돌리는 쪽입니다. 기능마다 실패 정책이 다릅니다.

**상태:** 현재 있음.

### Q27. 차트 이미지를 AI가 읽나요?

선택 기능으로 읽습니다. 차트 렌더 품질 검사와 CAN SLIM 베이스 패턴 분석이 있습니다. 기본은 판단에 영향을 주지 않는 shadow이며, 실제 매수 게이트 연결은 아직 없습니다.

**상태:** 일부 있음.

### Q28. PDF 리포트를 그대로 넣으면 판단할 수 있나요?

tracking의 `run(pdf_report_paths=...)`는 PDF 목록을 받아 거래 시나리오를 만들 수 있습니다. 하지만 표준 오케스트레이터는 자신이 만든 PDF만 넘깁니다. 외부 PDF를 안전하게 넣으려면 파일 종류, 종목, 기준일, 출처를 검증하는 입구가 필요합니다.

**상태:** 기술적 접점은 있음, 표준 입력 경로는 없음.

## 4. 매매와 안전 질문

### Q29. 텔레그램만 끄면 주문도 꺼지나요?

아닙니다. `--no-telegram`은 알림만 끕니다. PDF가 만들어지면 tracking과 주문 경로는 계속 실행됩니다. 원본을 테스트할 때 가장 주의해야 할 부분입니다.

**상태:** 현재 동작.

### Q30. 실제 주문은 기본적으로 안전한가요?

예시 KIS 설정은 기본 계좌 모드가 `demo`지만 `auto_trading: true`입니다. lecture-prism처럼 두 개의 별도 실거래 허용 플래그로 막는 구조는 원본에 없습니다. 운영 전에는 실제 설정의 계좌 모드와 자동매매 값을 별도로 확인해야 합니다.

**상태:** 데모 기본이지만 운영 확인 필요.

### Q31. DB에 매수됐는데 실제 계좌에는 없을 수 있나요?

가능성이 있습니다. 현재 순서는 로컬 DB 보유 기록이 먼저이고 KIS 주문이 나중입니다. 주문 실패 시 DB 변경을 자동으로 되돌리는 처리가 보이지 않습니다. “분석 신호”, “DB상 매수”, “브로커 체결”을 따로 모니터링해야 합니다.

**상태:** 현재 주의점.

### Q32. 주문이 안 체결되면 누가 관리하나요?

Loop C가 미체결 주문의 조회·정정·취소를 담당하도록 만들어져 있습니다. 다만 별도 프로세스이며 기본 Docker cron에는 들어 있지 않습니다. 실제 서버 활성 여부를 확인해야 합니다.

**상태:** 별도 시스템.

### Q33. 급락할 때 LLM 응답을 기다리나요?

별도 Loop A는 LLM 없이 손절가와 절대 -7%를 자주 확인하도록 설계돼 있습니다. 주 분석 배치와 분리돼 있어 급한 손절을 보고서 생성에 의존하지 않습니다.

**상태:** 별도 시스템.

### Q34. 매수하지 않은 종목도 나중 성과를 보나요?

Enhanced 경로는 보류·미진입 종목을 관심 이력과 성과 추적 테이블에 저장합니다. 별도 배치가 7·14·30일 뒤 가격을 채웁니다. 다만 현재 성공 매수 경로는 같은 방식의 `was_traded=True` 저장이 보이지 않아, 신규 데이터만으로 매수와 미매수의 완전한 비교가 되지는 않을 수 있습니다.

**상태:** 일부 있음.

## 5. 운영과 확장 질문

### Q35. 원본은 완전한 멀티에이전트 시스템인가요?

역할별 에이전트는 여러 개입니다. 다만 에이전트가 자유롭게 서로 대화하는 구조라기보다, 각자 보고서를 만든 뒤 결과 문자열을 다음 에이전트에게 합쳐 넘기는 파이프라인입니다. 이 방식이 호출 순서와 비용을 통제하기 쉽습니다.

### Q36. 분석을 병렬로 돌리면 더 빠르지 않나요?

종목 하나의 6개 섹션은 설정으로 병렬화할 수 있습니다. 기본은 호출 제한과 MCP 충돌을 줄이려고 직렬입니다. 종목 여러 개도 직렬입니다. 빠르기보다 실패율과 비용 예측을 우선한 설정입니다.

### Q37. 한 종목에 얼마나 걸리나요?

코드에는 종목별 실제 600초 제한이 없습니다. 데이터·LLM·Firecrawl·Perplexity·PDF 상황에 따라 크게 달라집니다. 전체 프로세스만 CLI에서 120분 뒤 종료합니다.

### Q38. 과거 날짜로 분석하면 그날 차트가 나오나요?

본문은 `reference_date`를 받지만 일부 차트 함수는 현재 시점을 기준으로 데이터를 가져옵니다. 과거 재현 실험에서는 본문과 차트 기준일이 달라질 수 있으므로 수정이 필요합니다.

**상태:** 현재 주의점.

### Q39. 이메일이나 다른 채널을 붙일 때 어디를 바꾸나요?

분석 함수 안에 메일 코드를 넣지 말고, 보고서 완료·매수·매도 이벤트를 받아 보내는 어댑터를 추가하는 편이 낫습니다. 현재 Redis와 GCP 신호 발행기가 좋은 참고 구조입니다.

### Q40. 한국 주식과 미국 주식은 같은 코드인가요?

방향은 비슷하지만 `prism-us/`에 별도 오케스트레이터와 데이터·주문 경로가 있습니다. 공통 개념은 재사용하되 파일과 운영 시간은 분리돼 있습니다.

### Q41. 코인도 같은 시스템으로 붙일 수 있나요?

원본에는 `prism-btc`가 별도로 있습니다. 현물 주식의 보고서 파이프라인을 그대로 복사하기보다 거래소, 24시간 장, 펀딩비, 레버리지, 강제청산을 별도 설계한 구조가 맞습니다.

### Q42. 모듈을 계속 붙이면 너무 복잡해지지 않나요?

복잡해집니다. 그래서 다음 네 경계를 지키는 것이 중요합니다.

- 데이터 수집은 데이터 모듈
- 투자 판단은 규칙과 에이전트
- 주문은 브로커 모듈
- 알림은 메시징 모듈

한 기능이 네 경계를 동시에 건드리면 새 기능보다 먼저 입력과 출력 계약을 정리해야 합니다.

## 6. 강의에서 바로 쓰는 답변 틀

수강생 질문에 길게 설명하기 전에 아래 순서로 답하면 이해가 빠릅니다.

1. **지금 원본에 있는가:** 현재 있음, 일부 있음, 새 모듈 필요 중 하나
2. **코드와 AI 중 누가 맡는가:** 계산 규칙인지 문맥 판단인지
3. **어디에 연결하는가:** 선별, 분석, 청산, 리스크, 데이터 중 하나
4. **첫 실습은 어디까지인가:** 한 파일 또는 한 함수만 바꾸기
5. **검증은 무엇으로 하는가:** 과거 데이터, 데모, 로그, DB 중 하나

예를 들어 “유료 리포트를 매도에 반영하고 싶다”는 질문에는 이렇게 답할 수 있습니다.

> 현재 자동배치에는 유료자료 입력 통로가 없습니다. 다만 이미지 해석 기능과 PDF를 읽는 거래 판단기는 따로 있습니다. 첫 단계에서는 캡처에서 종목·작성일·핵심 주장·위험 신호를 뽑아 사용자가 확인하게 만들고, 확인된 요약만 매도 프롬프트에 넣는 구조가 적당합니다. 처음부터 AI가 캡처를 보고 바로 주문하게 만들지는 않겠습니다.

## 7. 강의 실습으로 바꾸는 기준

| 질문 유형 | lecture-prism 트랙 | 첫 수정 예시 |
|---|---|---|
| 어떤 종목을 볼까 | A 진입 | 20일 신고가, 거래량, 시황 필터 |
| AI가 무엇을 읽을까 | B 분석 | 뉴스 지속성, 유료자료 요약 입력 |
| 언제 팔까 | C 청산 | ATR 손절, 10일 저가, 트레일링 |
| 얼마나 살까 | D 리스크 | 장세별 슬롯, 계좌 위험률, 업종 한도 |
| 새 데이터가 필요하다 | 심화 데이터 | DART, 테마 맵, ETF 목록 |

수강생이 여러 가지를 한꺼번에 말해도 첫 실습은 한 축만 고릅니다. 터틀+ATR+시황+뉴스 전략이라면 `A 진입 → C 청산 → D 리스크 → B AI 판단` 순서가 안전합니다.
