# 명령어를 코딩 에이전트 프롬프트로 바꾼 대응표

이 문서는 README와 실습 문서에서 수강생이 직접 입력하던 명령어를 코딩 에이전트 프롬프트로 바꾼 이유와 확인 기준을 정리합니다.

## 원칙

- 수강생은 터미널 명령어를 외우지 않습니다.
- 수강생은 “원하는 결과”를 코딩 에이전트에게 말합니다.
- 코딩 에이전트는 필요한 명령을 실행하고, 결과 로그를 읽어 성공·실패를 판단합니다.
- 프롬프트에는 반드시 “실행 후 검증해줘”가 들어가야 합니다.

## 100% 같은 결과를 만들기 위한 프롬프트 조건

프롬프트가 기존 명령어와 같은 결과를 내려면 아래 조건을 만족해야 합니다.

1. **대상 파일을 명시한다.** 예: `main.py`, `screening.py`, `trading.py`
2. **실행 모드를 명시한다.** 예: “API 키 없이 데모 모드”, “실거래 금지”, “시뮬레이션”
3. **검증 기준을 명시한다.** 예: “로그를 읽고 성공 여부를 판단해줘”
4. **민감한 작업은 사전 점검을 요구한다.** 예: “커밋 전 시크릿 포함 여부 확인”
5. **결과를 요약하게 한다.** 예: “마지막에 실행한 일과 결과를 표로 정리해줘”

## 코딩 에이전트가 반드시 확인해야 하는 것

초기 설정 프롬프트를 받은 코딩 에이전트는 다음을 확인해야 합니다.

- 현재 작업 폴더가 `lecture-prism` 루트인지
- Python 3.10 이상이 있는지
- 가상환경을 만들었는지 또는 이미 있는 것을 재사용했는지
- 외부 패키지 설치 전에 기본 데모 실행이 API 키 없이 성공했는지
- `requirements.txt` 설치가 필요한 단계와 기본 데모 단계를 구분했는지
- 실패 시 사용자가 직접 명령어를 치게 하지 않고 원인을 분류했는지
