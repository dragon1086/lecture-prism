# 사전 오픈 세미나 Reveal.js 리모델링 설계

20분 안에 강사의 개인 문제의식, 근거 기반 AI 리서치의 출발, PRISM의 실운영 위험과 검증 근거, 강의의 첫 실행을 하나의 인과관계로 전달하는 오프라인 인터랙티브 프레젠테이션을 만든다.

## 인과관계

`이론과 실행의 갭` → `실제 데이터를 가져와 판단해야 함` → `보고서만으로는 매매가 되지 않음` → `AI 판단을 실운영 시스템으로 옮김` → `위험은 주문 실행의 마지막 순간에 발생함` → `따라서 결과뿐 아니라 판단·주문·체결 근거를 남김` → `수강생도 AI와 mock-first 구조로 자기 전략을 시작할 수 있음`

운영 근거 장 앞에는 다음 문구의 단독 챕터 전환 슬라이드를 둔다.

> 결과가 좋았다는 말만으로는 부족했습니다. 위험을 겪고 나서, 판단과 주문과 결과를 남기기 시작했습니다.

## Reveal.js 구현

- Reveal.js 배포 파일을 `lecture/slides/vendor/reveal.js/`에 로컬로 포함한다. 발표 실행 시 CDN·인터넷·빌드 과정이 필요 없다.
- 기존 HTML은 Reveal.js의 `.reveal > .slides > section` 구조로 재작성한다.
- `controls`, `progress`, `slideNumber: 'c/t'`, `hash`, `keyboard`, `touch`, `overview`, `navigationMode: 'linear'`를 활성화한다.
- 기본 화살표 컨트롤과 키보드·클릭·터치 내비게이션을 제공한다. 시작 화면에는 `클릭하거나 → 키를 눌러 시작` 안내를 둔다.
- 위험 수치, 개인 서사 타임라인, 근거 슬라이드의 설명은 `fragment`로 한 단계씩 표시한다. 나머지 장면은 한 번에 보여 발표 속도를 안정시킨다.
- 현재의 다크 톤과 보라·청록 강조색을 유지하되, Reveal.js 캔버스에 맞춰 모든 콘텐츠가 1280×720 기준으로 안전하게 배치된다.

## 운영 근거와 안전

- 운영 DB에서 집계한 주문 재시도·취소·손절 기록은 종목·계좌·주문번호·원문 payload 없이 집계 수치와 교훈만 쓴다.
- 대시보드는 시뮬레이션 누적 실현 결과이고, 실계좌와 합산하지 않는다.
- 실계좌 이미지는 계좌명·소유자·계좌번호 영역을 CSS 크롭으로 보이지 않게 한다.
- 대시보드·실계좌 원본은 공개 저장소에 커밋하지 않는다. 로컬 발표 자산으로만 유지한다.
- 각 성과 근거 장에는 과거 성과가 미래 수익을 보장하지 않는다는 문구를 둔다.

## 검증

- Reveal.js 스크립트·스타일·로컬 이미지의 모든 상대 경로가 존재해야 한다.
- HTML 파싱과 슬라이드 수 20장을 확인한다.
- 로컬 HTTP 서버로 프레젠테이션을 열어 클릭, 화살표, 키보드, 진행 바, 슬라이드 번호, URL hash 이동을 점검한다.
- 위험·근거·계좌 크롭 장을 캡처해 텍스트 잘림과 식별 영역 노출이 없는지 확인한다.
- 기본 `python3 main.py` mock 파이프라인도 완주해야 한다.
