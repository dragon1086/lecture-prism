# README 결과 중심 개편 설계

## 목표

메인 README를 설치 설명서가 아니라, 세미나 참가자와 수강생이 3~5분 안에 “이 수업에서 무엇을 만들고 어떻게 완주하는지” 이해하는 소개 페이지로 바꾼다.

README, 사전오픈 세미나의 README 미리보기 슬라이드, 발표 스크립트가 모두 아래 한 문장으로 끝나야 한다.

> 내 매매 아이디어를 한 트랙에 넣고 안전한 데모로 검증한 뒤, 실데이터·실제 AI·KIS 주문 경로까지 이어지는 시스템을 만든다.

## 대상 독자

- 매매 전략 아이디어는 있지만 코딩 경험이 적은 투자자
- Claude Code·Codex·리포지토리·모듈·`.env` 같은 용어가 낯선 수강생
- 세미나에서 README를 처음 보고 본강의의 결과물을 빠르게 판단하려는 참가자

## 선택한 접근

메인 README는 결과 중심의 짧은 소개 페이지로 유지하고, 설치·인증·증권사 연결·제출 같은 세부 절차는 기존 문서와 실습 가이드로 연결한다.

다음 접근은 사용하지 않는다.

- 기존 README 문장을 부분적으로만 줄이는 방식: 정보량과 전문용어 밀도가 그대로 남는다.
- 홍보 문구만 남기는 극단적인 축약: 실제로 실행되는 프로젝트라는 근거가 약해진다.
- 상세 절차를 새 문서 하나에 그대로 복제하는 방식: 기존 `START_HERE.md`, `docs/`, `lecture/exercises/`와 중복된다.

## README 정보 구조

### 1. 이 수업에서 만드는 것

- 내 매매 아이디어가 코딩 에이전트를 거쳐 실데이터·실제 AI·KIS 주문 경로까지 연결 가능한 시스템이 된다는 결과를 첫 화면에서 보여준다.
- “완제품 자동매매 판매”나 “수익 보장”으로 오해하지 않도록 첫 검증은 데모로 진행하고, KIS 실계좌 주문은 명시적인 승인과 안전장치 해제 뒤에만 가능하다고 밝힌다.
- 첫 실행은 안전한 데모라는 점과, 수업에서 KIS 연결까지 단계적으로 올라간다는 점을 함께 보여준다.
- 첫 이미지에서 전략 입력, 최소 수정, 데모 검증, 실제 데이터·AI 연결, KIS 주문 경로의 전체 여정을 보여준다.

### 2. 내가 실제로 하는 일

- `MY_STRATEGY.md`에 진입·청산·리스크를 적는다.
- A~D 중 가장 가까운 트랙 하나를 고른다.
- 코딩 에이전트에게 수정·실행·검증을 맡긴다.
- 수정 전후 결과를 비교한다.

### 3. 시스템이 움직이는 모습

- 후보 선정 → AI 분석 → 주문 판단 → KIS 연결 → 기록의 흐름을 투자자의 말로 설명한다.
- `screening.py` 같은 파일명은 핵심 문장보다 작게 보조 정보로만 둔다.
- 데모 결과 예시와 KIS 연결 상태를 함께 보여 “처음에는 안전하게 검증하고, 준비되면 실제 주문 경로까지 연결한다”는 구조를 알 수 있게 한다.

### 4. 내 전략을 넣는 네 가지 트랙

- A 진입, B 분석 관점, C 청산, D 리스크를 한 화면에서 비교한다.
- 각 트랙은 한 문장짜리 쉬운 예시만 사용한다.
- 처음부터 전체를 바꾸지 않고 한 트랙만 완주하는 것이 성공 기준임을 강조한다.

### 5. 수업이 끝나면 남는 것

- 내 전략이 반영된 코드 한 조각
- API 키와 설정 파일이 없어도 전체 흐름이 완주되는 기본 실행 결과
- 수정 전후 차이에 대한 설명
- `.env` 값을 바꾸고 `trading/trading/config/kis_devlp.yaml`에 KIS App Key·Secret·계좌 정보를 채우면, 같은 프로젝트로 KIS 모의투자와 실전투자 주문 경로를 사용할 수 있는 결과물

이 절은 “나중에 개발하면 가능하다”는 가능성으로 표현하지 않는다. 수업이 끝난 시점의 같은 코드베이스에 KIS 어댑터와 주문 경로가 이미 들어 있고, 사용자가 설정과 인증 정보를 채우면 모드를 전환할 수 있다는 사실을 분명히 말한다.

- 모의투자: `LECTURE_PROFILE=paper`, `LECTURE_BROKER=kis`, `LECTURE_BROKER_MODE=demo`, `LECTURE_ENABLE_LIVE_BROKER=1`
- 실전투자: `LECTURE_PROFILE=live`, `LECTURE_BROKER=kis`, `LECTURE_BROKER_MODE=real`, `LECTURE_ENABLE_LIVE_BROKER=1`, `LECTURE_ALLOW_REAL_BROKER=1`
- 두 모드 모두 `trading/trading/config/kis_devlp.yaml`의 해당 KIS 인증·계좌 정보를 사용한다.
- README 본문에는 위 변수 전체를 나열하지 않고 “`.env` 모드 변경 + `kis_devlp.yaml` 작성”으로 설명한 뒤, 정확한 설정은 `docs/runtime-profiles.md`로 연결한다.

## 이미지 설계

README에는 의미가 겹치지 않는 이미지 세 장만 사용한다.

### 이미지 1. 내 전략이 KIS까지 이어지는 과정

- 목적: 첫 화면에서 수업 전체 결과를 이해시킨다.
- 흐름: 전략 3줄 → AI가 한 트랙 수정 → 안전한 데모 검증 → 실데이터·실제 AI → KIS 주문 경로
- 문장은 짧고 큰 글자로 제한한다.

### 이미지 2. 실행하면 보이는 시스템 결과

- 목적: 추상적인 구조도가 아니라 실제로 만들 수 있는 결과물을 체감하게 한다.
- 공개 가능한 가상 종목·가상 금액·데모 배지를 사용한다.
- 후보, AI 분석 점수, 주문 판단, KIS 연결 상태, 매매일지 또는 교훈이 한 화면에 보이게 한다.
- 데모 모드와 KIS 모의·실계좌 연결 가능 상태를 명확히 구분한다.
- “기본은 키 없이 실행”과 “설정 후 KIS 모의·실전 주문”이 서로 다른 프로젝트가 아니라 같은 결과물의 모드 전환임을 보여준다.
- 개인 계좌, 운영 데이터, 실제 보고서, 실계좌 캡처는 사용하지 않는다.

### 이미지 3. 내 전략을 넣는 네 가지 트랙

- 목적: 본인의 이론이 어디에 들어갈지 즉시 고르게 한다.
- A 진입, B 분석, C 청산, D 리스크를 큰 제목과 쉬운 예시로 보여준다.
- 파일명은 하단의 작은 보조 설명으로만 둔다.

## GPT Image 2 제작 제약

- 세 이미지 모두 GPT Image 2가 배경, 도형, 아이콘, 한글 문구를 한 번에 직접 생성한다.
- 배경 이미지를 만든 뒤 PIL·HTML·SVG·Canvas·슬라이드 도형으로 글자를 합성하지 않는다.
- 이미지에 들어갈 한글은 프롬프트에 정확한 문구로 제공한다.
- 한글 오탈자, 깨진 글자, 잘못된 숫자가 있으면 후처리로 고치지 않고 해당 이미지를 다시 생성한다.
- 생성 결과는 원본 크기로 직접 확인하고, 한글 정확성·가독성·구조·여백을 검수한다.
- 같은 색상 체계와 16:9 비율을 사용하되, 세 이미지가 같은 카드 배열을 반복하지 않게 한다.

## 세미나 슬라이드와 원고

README 미리보기 슬라이드는 README의 실제 순서와 같은 다섯 항목을 사용한다.

1. 내 전략이 KIS까지 이어지는 시스템
2. API 키 없이 안전하게 첫 실행
3. 실데이터·실제 AI·KIS 연결
4. 내 전략을 넣는 네 가지 트랙
5. 작동하는 코드와 주문 경로로 확인

발표 스크립트는 README를 처음부터 끝까지 읽지 않는다. 실제 README를 열어 첫 이미지, 안전한 데모, 실데이터·실제 AI·KIS로 올라가는 경로, 네 트랙을 짚는다. 마지막에는 “본강의에서는 내 전략을 직접 수정하고 검증한 뒤 KIS 주문 경로까지 어떻게 이어지는지 확인한다”로 닫는다.

## 안전과 공개 범위

- README와 생성 이미지는 공개 저장소에 올라갈 수 있는 내용만 담는다.
- API 키, 계좌번호, 운영 DB, 실계좌 성과, 개인 대시보드, 로컬 경로를 포함하지 않는다.
- KIS 실계좌 주문 경로를 숨기거나 단순 가상매매 프로젝트처럼 표현하지 않는다.
- KIS 설정 파일의 실제 이름은 항상 소문자 `kis_devlp.yaml`로 표기한다. `.yml`, `Kis_Devlp.yml` 같은 변형 표기를 사용하지 않는다.
- 실계좌 주문은 이중 안전장치를 명시적으로 해제해야만 가능하다는 사실을 함께 표시한다.
- 안전장치는 KIS 연결이라는 강의 가치를 지우지 않되, 수강생의 우발적 주문을 막는 조건으로 설명한다.

## 검증 기준

- README 본문은 제목·표·프롬프트를 포함해 3~5분 안에 훑을 수 있다.
- 첫 화면만 보고도 수강생이 “내 전략 한 부분을 AI와 수정하고 안전하게 검증한 뒤, 실데이터·실제 AI·KIS 주문까지 연결하는 수업”이라고 설명할 수 있다.
- 이미지 속 핵심 한글이 축소된 GitHub README 화면에서도 읽힌다.
- 세 이미지에 한글 오탈자와 개인·운영 데이터가 없다.
- README, 슬라이드, 발표 스크립트의 항목 순서와 결론이 일치한다.
- 단일 HTML 슬라이드를 다시 생성한 뒤 외부 이미지 의존성 없이 열린다.
