# Part 3·4 KIS 수급 데이터 보강 실습 설계

## 목적

Part 3에서 수강생이 현재 보고서의 데이터 한계를 발견한 뒤 “그래서 부족한 데이터는 어떻게 가져오는가?”라는 질문을 남기지 않도록 한다. Part 4에서는 강사와 수강생이 각자 로컬 KIS App Key·App Secret으로 삼성전자 한 종목의 투자자별 수급을 직접 조회하고, 기존 거래량 기반 수급 추정이 실제 외국인·기관·개인 순매수 근거로 바뀌는 과정을 확인한다.

기본 학습 경로의 무키 실행과 실거래 차단은 그대로 유지한다. KIS 수급 조회는 선택 데이터 보강 경로이며 주문·잔고·계좌 조회와 분리한다.

## 학습 성과

수강생은 실습 뒤 다음을 설명할 수 있어야 한다.

1. 공식 Open API, 공개 웹/API·크롤링, 파일·DB, MCP의 역할 차이
2. 데이터 원천과 에이전트 연결 인터페이스가 서로 다른 선택이라는 점
3. 외부 응답을 그대로 쓰지 않고 필요한 필드만 공통 형태로 변환하는 이유
4. 데이터 출처·기준 시각·단위·갱신 주기·실패 시 동작을 함께 정해야 하는 이유
5. yfinance를 통째로 버리는 것이 아니라 수급 섹션의 약한 근거만 KIS로 보강하는 방식
6. 실제 조회와 실제 주문은 별개의 경로라는 안전 경계

## 수업 구조

### Part 3: 발견과 예고

현재 “보고서의 빈칸은 더 좋은 LLM이 아니라 알맞은 데이터로 채웁니다” 슬라이드를 고밀도 구조 이미지 중심으로 바꾼다. 이미지는 다음 세 층을 한 화면에 담는다.

- 상단: 데이터 수집 방식 지도
  - 공식 Open API: KIS
  - 공개 웹/API·크롤링: 공시·뉴스·웹페이지
  - 파일·DB: CSV·SQLite
  - 기존 라이브러리: yfinance
- 중앙: 공통 데이터 계약
  - 필요한 근거 선택
  - 응답 검증
  - 필드 정규화
  - 출처·기준 시각·단위·갱신 주기 기록
- 하단: 분석 연결 방식
  - Python 직접 HTTP
  - SDK·어댑터 함수
  - MCP 도구
  - 기술·수급·재무·뉴스·시장 담당 섹션

이미지 안에서 “MCP는 데이터 원천이 아니라 이미 만든 수집 기능을 에이전트에게 제공하는 연결 방식”을 분명히 표시한다.

슬라이드의 마지막 행동 문장은 다음 의미를 전달한다.

> 지금은 필요한 빈칸과 수집 방식을 고릅니다. Part 4에서는 KIS로 삼성전자 수급 한 칸을 직접 보강합니다.

Part 3 말미에는 Part 4 준비 상태 확인을 추가한다. KIS 신청을 이때 처음 안내하지 않는다. 수업 전 안내에서 계좌·Open API 신청·App Key·App Secret 발급을 먼저 안내하고, Part 3 말미에는 로컬 설정 파일에 값이 준비됐는지만 확인한다.

### Part 4: 공통 KIS 데이터 보강 실습

A/B/C/D 개인 전략 트랙 전에 모든 수강생이 같은 공통 실습을 수행한다.

1. 삼성전자 `005930`을 yfinance 기반 `real_data`로 분석한다.
2. 기존 수급 섹션이 상승일·하락일 거래량 비율과 OBV로 매수·매도 우위를 추정한다는 점을 확인한다.
3. KIS 일별 투자자 수급 조회를 한 번 실행한다.
4. 외부 응답에서 날짜와 기관·외국인·개인 순매수 필드만 골라 공통 형태로 변환한다.
5. 수급 섹션의 근거만 KIS 데이터로 교체한다.
6. 수정 전후 보고서에서 근거 문장과 데이터 provenance가 어떻게 달라졌는지 비교한다.
7. KIS 조회가 실패하면 원인을 한 번 기록하고 기존 거래량 프록시로 돌아간다. 자동 반복 호출은 하지 않는다.

메인 실습은 장 종료 뒤에도 재현 가능한 일별 수급을 사용한다.

- 경로: `/uapi/domestic-stock/v1/quotations/investor-trade-by-stock-daily`
- TR ID: `FHPTJ04160001`
- 핵심 필드:
  - `stck_bsop_date` → 기준일
  - `orgn_ntby_qty` → 기관합계
  - `frgn_ntby_qty` → 외국인합계
  - `prsn_ntby_qty` → 개인

장중 외인·기관 추정 endpoint는 시간대와 추정치 성격 때문에 선택 시연으로만 소개한다.

## 코드 경계

### 단일 진입점

`data_source.py`는 계속 분석·스크리닝의 데이터 단일 접점이다. yfinance가 가격·거래량·기본 재무·뉴스·시장지수를 제공하고, KIS는 명시적으로 선택됐을 때 수급 근거만 보강한다.

예상 흐름:

```text
data_source.fetch_stock_data()
  ├─ yfinance: 가격·거래량·기본 재무·뉴스
  └─ KIS 선택 보강: 투자자별 순매수
           ↓
analysis._section_supply()
           ↓
수급 분석가 → 보고서 provenance → 전후 비교
```

### 조회 전용 KIS 어댑터

lecture-prism의 표준 라이브러리 기반 KIS HTTP 전송과 인증 패턴을 재사용하되, 수급 조회 API를 공개 조회 메서드로 추가한다. 수업용 데이터 경로는 App Key·App Secret만 사용하고 주문에 필요한 계좌번호·상품코드를 요구하지 않는다.

조회 어댑터는 다음을 책임진다.

- 고정된 KIS 호스트와 수급 endpoint만 호출
- 토큰과 비밀값을 로그·예외·반환값에서 제거
- 성공 응답의 형태와 숫자 필드 검증
- 날짜순 정렬과 필요한 기간 자르기
- 빈 값과 0을 구분
- transport 주입으로 네트워크 없는 테스트 지원

### 데이터 선택

기본값은 기존 yfinance 거래량 프록시다. KIS 보강은 명시적 설정에서만 활성화한다. 설정 이름은 구현 계획에서 기존 runtime profile·환경 변수 규칙을 조사한 뒤 결정하되, `mock` 기본 경로와 `real_data`의 자동 폴백 의미를 바꾸지 않는다.

## 보안과 운영 경계

- 수강생은 App Key·App Secret을 코딩 에이전트 채팅에 붙여넣지 않는다.
- 코딩 에이전트는 로컬 설정 파일에 빈 항목만 준비하고, 수강생이 파일을 직접 열어 값을 넣는다.
- 준비 점검은 값의 존재 여부만 표시하고 값을 출력하지 않는다.
- `.env`, 인증 파일, 토큰, 원시 응답, 로컬 보고서·로그·DB를 Git에 추가하지 않는다.
- KIS 주문·취소·잔고·계좌 endpoint를 호출하지 않는다.
- `LECTURE_ENABLE_LIVE_BROKER`, `LECTURE_ALLOW_REAL_BROKER`와 무인 실행 확인값을 켜지 않는다.
- KIS 조회 실패는 수업 실패가 아니다. 기존 거래량 프록시 보고서로 한 번 완주한다.
- 수강생은 자기 키로 자기 투자 목적의 데이터를 조회하며, KIS 원시 시세·수급 데이터를 공개 저장소나 강의 배포물로 재배포하지 않는다.

## 검증

### 코드

- KIS 성공 응답이 기관·외국인·개인 순매수로 정규화됨
- 잘못된 응답·빈 결과·인증 실패·네트워크 오류에서 비밀값 없이 실패함

- 조회 전용 실습에서 주문·취소·잔고·계좌 호출이 0회임
- 전체 단위 테스트와 관련 집중 테스트 통과

## 기준선 주의

작업 시작 당시 `main`의 전체 테스트는 기존 문서 계약 불일치로 651개 중 1개가 실패한다. `docs/architecture.md`에 `피드백 저장` 문구가 없어 `DiscordDocumentationContractTest`가 실패하는 상태다. 구현 계획에서는 이 기준선 실패를 승인된 범위에 포함해 먼저 복구한 뒤, 새 변경으로 추가 실패가 생기지 않았음을 구분해 검증한다.
