# 분석 보고서 에이전트 분리 설계

## 목표

Lecture-PRISM의 모듈 2를 원본 PRISM처럼 독립된 전문 에이전트들이 분석 보고서를 작성하고 편집 에이전트가 조립하는 구조로 바꾼다. 매수 판단은 모듈 3의 별도 매수 에이전트로 이동해 보고서 작성과 주문 판단의 책임을 분리한다.

## 책임 경계

- `analysis_agents.py`: 기술·수급·재무·산업·뉴스·시장 에이전트와 보고서 편집 에이전트의 역할, 프롬프트, 입력·출력 계약을 정의한다.
- `analysis.py`: 종목·시장 데이터를 한 번 수집하고 일곱 에이전트를 조립해 분석 보고서를 반환한다. 매수 여부, 점수, 목표가, 손절가를 결정하지 않는다.
- `buy_agent.py`: 완성된 보고서를 읽어 진입 시나리오를 만든다. 규칙 엔진이 점수·가격·손익비의 하한을 소유하고 LLM은 근거를 해석하거나 진입을 거부할 수만 있다.
- `trading.py`: 매수 시나리오를 다시 검증하고 포지션 크기와 주문을 결정한다. 기존 청산·브로커 안전 게이트는 유지한다.
- `main.py`: 스크리닝 → 분석 보고서 → 매수 에이전트 → 매매 실행 → 피드백 순서를 로그와 코드에서 명시한다.

## 에이전트 실행

여섯 전문 에이전트는 서로의 결과에 의존하지 않고 같은 근거 묶음에서 개별 호출한다. LLM이 활성화되면 `asyncio.gather()`로 여섯 공급자 호출을 실행한다. 어느 한 호출이 실패하면 그 섹션만 규칙 기반 결과로 폴백하고 다른 섹션은 유지한다. 편집 에이전트는 여섯 결과가 모인 뒤 일곱 번째 호출로 핵심 요약을 작성한다.

API 키가 없는 기본 경로에서는 같은 에이전트 인터페이스가 규칙 기반 작성기를 실행한다. 표준 라이브러리만으로 전체 파이프라인이 완주해야 한다.

## 데이터 계약

`run_analysis_report(ticker)`는 종목 식별자, 현재가, 섹터, 데이터 출처, 섹션별 출처, 여섯 섹션 요약, 핵심 요약, 내부 정량 근거를 담은 dict를 반환한다. 이 결과에는 `recommendation`, `decision`, `buy_score`, `target_price`, `stop_loss`가 없다.

`run_buy_agent(report)`는 보고서 필드를 보존하면서 `recommendation`, `decision`, `buy_score`, `min_score`, `target_price`, `stop_loss`, `risk_reward_ratio`, `rationale`, `risk`를 추가한다. `run_analysis(ticker)`는 기존 수강 자료와 외부 호출의 입출력 호환을 위해 두 함수를 순서대로 호출하는 얇은 호환 래퍼로 남긴다.

## 프롬프트 안전 경계

전문 분석 에이전트는 제공된 근거만 설명하며 매수·매도 지시나 가격 목표를 출력하지 않는다. 편집 에이전트도 보고서 요약만 작성한다. 매수 에이전트는 정량 엔진의 점수와 가격 배열을 변경할 수 없으며, `Enter`를 `No Entry`로 낮추는 거부권만 가진다. 주문 실행은 계속 `trading.py`가 담당한다.

## 강의 자료 동기화

Part 3 모듈 2는 독립 보고서 에이전트 6개와 편집 에이전트 1개의 조립을 보여준다. 모듈 3은 보고서 → 매수 에이전트 → 안전 검증 → 주문의 흐름을 보여준다. 강사용 진행 스크립트와 수강생 붙여넣기 프롬프트는 `analysis.py`에서 매수 조건을 고치라고 안내하지 않고, 분석 관점은 `analysis_agents.py`, 진입 판단은 `buy_agent.py`, 주문·청산은 `trading.py`로 안내한다.

## 검증

- 여섯 LLM 에이전트가 정확히 여섯 번 독립 호출되고 편집기가 일곱 번째 호출인지 테스트한다.
- 섹션 하나의 실패가 해당 섹션의 규칙 폴백으로만 격리되는지 테스트한다.
- 보고서 결과에 매수 판단 필드가 없고 매수 에이전트 결과에만 생기는지 테스트한다.
- 기존 `run_analysis()`의 출력 형태와 기본 mock 파이프라인 완주를 유지한다.
- 실거래 이중 차단과 전체 테스트를 회귀 검증한다.
- 슬라이드·강사 스크립트·수강생 프롬프트에서 이전 단일 호출·모듈 2 매수 판단 설명이 남지 않았는지 정적 검사한다.
