# 파트 3 학습자 참여 중심 재구성 설계

## 목적

파트 3의 사실 정확성과 고밀도 이미지는 유지하면서 강의 순서를
`문제 상황 → 수강생 예상 → 실행 예시 → 구조 설명 → 내 전략에 적용`으로
바꾼다. 수강생은 기능을 확인하는 데서 끝나지 않고, 각 모듈을 자기 전략의
어디에 쓸지 입으로 말한다.

## 강의 원칙

1. 설명보다 먼저 투자자가 겪을 문제를 보여 준다.
2. 예시는 현재 저장소에서 반복 실행할 수 있는 mock fixture와 테스트만 쓴다.
3. 질문은 정답 확인보다 선택·우선순위·적용을 묻는다.
4. 네 모듈마다 수강생이 최소 한 번 자기 답을 말한다.
5. 마지막은 요약이나 일반 Q&A가 아니라 오늘 바로 적용할 한 가지로 닫는다.

## 표지와 첫 실행

### P3-S01

- 기존 하단 SVG와 이모지 도식을 제거한다.
- 어두운 남색 배경의 하단 35~40%에 유리·금속 질감의 AI 시스템 콘솔을 둔다.
- 보라색 신호가 청록색으로 이어지며, 콘솔 가장자리는 배경에 자연스럽게 섞인다.
- 이미지 안에는 글자, 로고, 종목 차트, 이모지, 워터마크를 넣지 않는다.
- 상단은 기존 제목이 또렷하게 보이도록 어두운 여백을 유지한다.

### P3-S04

- 수강생이 프롬프트 파일에서 찾을 실제 항목을 직접 안내한다.
- 표시 문구는 `P3-01 · API 키 없는 첫 성공`과
  `코딩 에이전트에 붙여넣기 블록 전체`다.
- 관리번호만 보여 주지 않고 파일에서 무엇을 찾아 복사하는지 함께 설명한다.

## 네 모듈의 문제 상황과 좋은 예시

### 모듈 1 · 스크리닝

- 문제 질문: `시장이 흔들려도 어제와 같은 기준으로 후보를 골라도 될까요?`
- 실행 예시: 연습 종목 7개 중 등락률이 가장 높은 현대차는 거래량 3.6배로
  5배 기준을 통과하지 못하고, 삼성전자·SK하이닉스·NAVER 세 종목이 남는다.
- 학습 포인트: 많이 오른 종목과 내 규칙을 통과한 종목은 다르다.

마지막 사고 질문은 다음 세 개다.

1. 내 전략이라면 후보를 가장 먼저 어떤 조건으로 거를까?
2. 후보가 너무 많다면 무엇을 우선해 순서를 정할까?
3. `screening.py`에서 바꿀 한 가지와 그대로 둘 안전장치는 무엇일까?

### 모듈 2 · 종목 분석

- 문제 질문: `차트가 좋아 보인다는 이유만으로 종목 분석을 끝내도 될까요?`
- 실행 예시: 수급 분석 에이전트 하나가 실패해도 다른 다섯 보고서는 유지되고,
  실패한 섹션만 규칙 보고서로 대체한 뒤 편집 에이전트가 보고서를 완성한다.
- 학습 포인트: 역할 분리는 다양한 관점뿐 아니라 실패 격리에도 필요하다.

마지막 사고 질문은 다음 세 개다.

1. 내 전략에서 숫자로 확인할 근거와 맥락으로 읽을 근거는 각각 무엇일까?
2. 여섯 역할 중 반드시 남길 분석가와 새로 보태고 싶은 분석가는 무엇일까?
3. 어떤 근거가 빠지면 매수 판단을 다음 단계로 넘기지 않을까?

### 모듈 3 · 매매

- 문제 질문: `AI가 BUY 8점을 줬는데 주문이 0건이면 오류일까요?`
- 실행 예시: BUY 8점이어도 손익비가 1.0이면 주문을 만들지 않는다. HOLD는
  점수가 10점이어도 주문을 만들지 않는다. 청산 데모는 손절·트레일링 스탑·
  목표가 도달을 서로 다른 결과로 보여 준다.
- 학습 포인트: AI 의견과 코드 안전문은 다른 책임이다.

마지막 사고 질문은 다음 세 개다.

1. AI가 좋다고 해도 코드가 반드시 막아야 할 진입은 무엇일까?
2. 내 전략에서는 손절·수익 보호·목표가를 어떤 순서로 확인할까?
3. 체결 상태가 불분명할 때 새 주문 전에 무엇을 확인할까?

### 모듈 4 · 피드백과 기억

- 문제 질문: `방금 샀는데 아직 결과도 모르면서 성공 교훈을 만들어도 될까요?`
- 실행 예시: BUY 체결은 거래 기록만 남기고 결과 교훈을 만들지 않는다. SELL로
  거래가 끝나야 단기 교훈을 만든다. 서로 다른 두 종목에서 같은 교훈이 반복되면
  하나의 장기 원칙으로 압축한다.
- 학습 포인트: 교훈은 결과가 닫힌 뒤 만들고, 반복된 것만 오래 남긴다.

마지막 사고 질문은 다음 세 개다.

1. 거래가 끝나면 처음 계획과 실제 결과 중 무엇을 비교해 남길까?
2. 같은 실수가 몇 번 반복되면 장기 원칙으로 만들까?
3. 오늘의 교훈 중 다음 거래에는 넣지 말아야 할 일회성 상황은 무엇일까?

## 수강생이 입을 여는 지점

- 모듈 시작: 문제 질문에 20초 동안 혼자 예상한다.
- 모듈 실행 뒤: 마지막 사고 질문 세 개 중 하나를 골라 짝과 60초 동안 말한다.
- 시간 부족 시 전체 공유는 생략해도 짝 대화는 유지한다.
- 강사는 정답을 대신 말하지 않고 수강생의 선택과 이유를 한 문장으로 다시 묻는다.

슬라이드 P3-S13, P3-S20, P3-S29, P3-S36의 오른쪽 제목은
`확인 1·2·3`에서 `내 전략에 대입 1·2·3`으로 바꾼다. 같은 질문을 수강생
프롬프트의 각 모듈 마지막에도 넣어 코딩 에이전트가 질문만 남기게 한다.
코딩 에이전트가 수강생 대신 답하지는 않는다.

## 보조 운영 마무리

- P3-S30은 고밀도 이미지를 제거하고 모듈 3에서 4로 넘어가는 짧은 전환으로 쓴다.
- P3-S34는 운영 성과 통계를 제거하고 기억을 쓸 만하게 유지하는 원칙으로 바꾼다.
- P3-S37은 `prism-auxiliary-operations-loop.png`를 크게 사용해 네 모듈과
  보유 감시·체결 확인·기억 압축·다음 진입 참고를 한 화면에 모은다.
- 이미지는 P3-S37에서 한 번만 사용한다.

## 마지막 적용

P3-S38의 일반 Q&A를 `오늘 바로 바꿔 볼 한 가지는 무엇입니까?`로 바꾼다.
수강생은 후보 조건·분석 역할·진입과 청산·기록과 운영 중 하나를 고르고
`내 전략에서 ___을 먼저 바꿔 보고 싶다. 이유는 ___이다.`를 완성한다.
질문은 이 적용 문장을 말한 뒤 받는다.

## 검증 기준

- 파트 3은 38장, 파트 4는 40장을 유지한다.
- 표지 이미지에 읽을 수 없는 생성 글자와 워터마크가 없다.
- P3-S04에 `P3-01 · API 키 없는 첫 성공`과 복사할 블록 이름이 보인다.
- 네 모듈의 프롬프트 슬라이드와 수강생 프롬프트에 같은 사고 질문 12개가 있다.
- 각 모듈의 강사 진행에 20초 예상과 60초 짝 대화가 있다.
- P3-S34에 최근 90일 성과 통계와 참조·비참조 거래 표현이 없다.
- 보조 운영 이미지는 P3-S37에서 한 번만 사용한다.
- P3-S38은 적용 문장으로 끝나며 일반 Q&A 제목이 아니다.
- 1600×900 렌더에서 표지와 변경 슬라이드에 잘림·겹침이 없다.
- 관련 계약 테스트와 전체 테스트가 통과하고 mock `main.py`가 완주한다.

## 내일 리허설에서 확인할 것

1. 문제 질문을 먼저 들었을 때 수강생이 답을 예상할 시간을 실제로 갖는가?
2. 실행 결과가 문제 질문의 답으로 자연스럽게 이어지는가?
3. 사고 질문이 아직 배우지 않은 구현 지식을 요구하지 않는가?
4. 짝 대화 60초가 모듈별 시간 안에 들어오는가?
5. 마지막 적용 문장을 수강생이 자기 전략의 말로 완성할 수 있는가?
