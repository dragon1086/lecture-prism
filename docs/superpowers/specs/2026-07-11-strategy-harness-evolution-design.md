# Strategy Harness Evolution Design

## 목적

비전공 수강생이 대략적이거나 서로 모순되는 매매 생각을 한 문장으로 말해도, 코딩 에이전트가 그 뜻을 쉬운 말로 정리하고 안전한 한 단계부터 코드에 반영하도록 Strategy Harness Lite를 확장한다.

이 설계는 다음 첫 경험을 보존한다.

- API 키가 없어도 기본 데모가 끝까지 실행된다.
- 실거래는 기본적으로 차단된다.
- 수강생은 터미널 명령어 대신 코딩 에이전트에게 자연어로 요청한다.
- 여러 요구가 있어도 한 번에 한 트랙씩 수정하고 검증한다.
- 기존 `run_screening`, `run_analysis`, `run_trading`, `run_feedback` 계약은 유지한다.

## 대상 수강생의 요구

구독자 대화를 바탕으로 다음 요구를 일반화한다.

- 터틀식 신고가 돌파, 거래량, ATR 등 숫자 규칙을 쓰고 싶다.
- KOSPI 같은 시장 흐름에 따라 진입 문턱과 현금 비중을 바꾸고 싶다.
- 뉴스, 공시, 외국 리포트처럼 숫자로 만들기 어려운 자료를 AI가 참고했으면 한다.
- 유료 자료는 자동 수집 대신 캡처나 본문을 직접 넣을 수 있어야 한다.
- 매매일지와 반복 패턴을 다음 판단의 참고자료로 쌓고 싶다.
- 지금은 정확한 로직을 몰라도 데이터를 남겨 나중에 전략을 다듬고 싶다.
- 상승률·거래대금 상위 종목을 업종·테마로 묶거나 ETF·선물·코인으로 확장하고 싶다.
- 별도 자동화 도구를 여러 개 설치하지 않고 프로젝트 안에서 기능을 추가하고 싶다.
- macOS와 Windows에서 Python 3.10 이상으로 같은 기본 실습을 하고 싶다.

ETF·선물·코인·메일 발송은 이번 구현에서 실제 기능으로 추가하지 않는다. 하네스가 이를 별도 확장 과제로 분류하고, 필요한 데이터·위험·인증 조건을 설명하는 데까지 포함한다.

## 사용자 대화 원칙

하네스는 사용자를 비전공자로 간주한다.

- 전문 용어보다 결과를 먼저 말한다.
- `adapter`, `schema`, `fallback`을 그대로 말하지 않고 각각 `데이터 연결 부품`, `결과 모양`, `안 되면 대신 쓰는 방법`처럼 풀어서 설명한다.
- 한 화면에서 질문은 최대 하나만 한다.
- 답이 없어도 안전한 기본값으로 진행할 수 있으면 묻지 않는다.
- 숫자가 없는 표현은 임의로 확정하지 않고 `하네스가 우선 가정한 값`으로 표시한다.
- 모순된 요구는 틀렸다고 말하지 않고, 동시에 만족하기 어려운 이유와 안전한 우선순위를 설명한다.
- 사용자가 해야 하는 일과 코딩 에이전트가 대신 할 일을 분리한다.
- API 키가 필요하면 키 값을 채팅에 붙이지 말고 `.env`에 저장하도록 안내한다.
- 문서에는 사용자가 직접 실행할 터미널 명령을 제시하지 않고, 코딩 에이전트에게 붙여넣을 프롬프트를 제공한다.

## 전략 해석 결과

인터뷰어는 자유로운 설명을 다음 구조로 정리한다.

| 항목 | 쉬운 질문 | 예시 |
|---|---|---|
| 목표 | 어떤 결과를 원하나요? | 추세가 살아 있을 때 수익금을 키운다 |
| 진입 | 어떤 종목을 언제 살까요? | 20일 신고가와 거래량 증가 |
| 분석 | AI가 무엇을 중요하게 볼까요? | 뉴스 악재 해소와 시장 흐름 |
| 청산 | 언제 팔까요? | ATR 손절 또는 채널 이탈 |
| 위험 | 얼마나 사고 얼마를 남길까요? | 약세장에는 현금 60% 유지 |
| 시장 흐름 | 장이 좋고 나쁨을 어떻게 나눌까요? | 지수 추세와 변동성 |
| 필요한 자료 | 판단에 어떤 자료가 필요한가요? | 가격, 지수, 뉴스, 공시, 수급 |
| 직접 넣을 자료 | 자동으로 못 가져오는 자료가 있나요? | 유료 리포트 핵심 문단 |
| 기억 | 다음 판단에 무엇을 남길까요? | 진입 이유, 청산 이유, 반복 실수 |
| 향후 확장 | 나중에 무엇으로 넓힐까요? | ETF 자산배분 |
| 모순 | 동시에 지키기 어려운 조건은 무엇인가요? | 신호 즉시 진입과 악재 확인 후 진입 |
| 기본 가정 | 빠진 숫자를 무엇으로 시험할까요? | 우선 데모값으로 비교 후 조정 |

정리 결과에는 `확실히 말한 것`, `하네스가 추정한 것`, `이번에 구현하지 않는 것`을 분리한다.

## 계층형 작업 흐름

1. 사용자 메시지와 `MY_STRATEGY.md`를 읽는다.
2. 요구를 전략 해석 결과 구조로 정리한다.
3. 모순, 빠진 숫자, 실거래 위험, 외부 자료 요구를 찾는다.
4. 필요한 자료마다 준비 상태를 분류한다.
5. 전체 요구를 Part 4 트랙 A/B/C/D 순서로 나눈다.
6. 가장 안전하고 결과 차이를 볼 수 있는 첫 트랙 하나를 선택한다.
7. 변경 전 데모 결과를 기록한다.
8. 회귀 테스트를 먼저 추가하고 실패를 확인한다.
9. 해당 트랙만 수정한다.
10. 트랙 단독 검증과 전체 mock 파이프라인을 실행한다.
11. 강세장·약세장·횡보장과 자료 누락 상황을 비교한다.
12. 쉬운 말로 결과와 다음 트랙을 설명한다.

여러 트랙을 요청하면 6~12단계를 트랙마다 반복한다. 한 사이클 안에서 여러 트랙을 동시에 수정하지 않는다.

## 자료 준비 상태 분류

필요한 자료는 다음 다섯 상태 중 하나로 분류한다.

| 상태 | 사용자 안내 | 하네스 행동 |
|---|---|---|
| 지금 사용 가능 | 이미 프로젝트에 있습니다 | 기존 값을 재사용한다 |
| 무료 연결 가능 | 별도 결제 없이 연결할 수 있습니다 | 공식·원천 문서를 확인하고 데이터 연결 부품을 만든다 |
| 키 또는 계정 필요 | 발급이나 로그인이 한 번 필요합니다 | 용도, 공식 발급 위치, 환경변수 이름, 비용 가능성, 대체 데모를 설명한다 |
| 사람이 넣어야 함 | 자동 접근이 어려워 직접 자료를 넣어야 합니다 | 텍스트·Markdown·이미지 중 허용 형식과 저장 위치를 안내한다 |
| 이번 범위 밖 | 현재 구조와 안전 조건이 크게 다릅니다 | 구현하지 않고 별도 확장 과제와 선행 조건을 제시한다 |

API 키나 계정이 준비되지 않아도 작업을 중단하지 않는다. mock 자료 또는 사용자가 넣은 예시 자료로 전략 동작을 먼저 검증한다.

## 데이터 연결 부품 계약

새 데이터 소스를 추가할 때는 `data_source.py`에 사이트별 코드를 계속 늘리지 않는다. 작은 데이터 연결 부품이 공통 결과를 반환하고, 기존 `data_source.py`가 이를 선택하도록 한다.

각 부품은 다음 정보를 가진다.

- 이름과 제공 자료
- 무료 여부와 인증 필요 여부
- 필요한 환경변수 이름
- 사용자가 직접 준비해야 하는 단계
- 반환하는 필드와 값의 기준 시각
- 실패 이유
- 실패할 때 사용할 mock 또는 기존 자료
- 출처 표시

첫 구현은 실제 신규 사이트 수집기를 추가하지 않는다. 대신 이 계약과 준비 상태 판정 구조, 예시 mock 부품을 만든다. 실제 사이트는 공식 문서와 이용 조건을 확인한 뒤 같은 계약으로 하나씩 추가한다.

## 수동 자료 입력

유료 리포트, 뉴스 캡처, 공시 발췌문은 자동 수집과 분리한다.

- 기본 입력은 UTF-8 Markdown 또는 텍스트다.
- 이미지는 이미지 입력이 가능한 코딩 에이전트나 OCR 단계가 있을 때만 읽는다.
- 원문 전체보다 출처, 작성 시각, 종목, 핵심 문단, 사용자가 중요하다고 본 이유를 함께 남긴다.
- 자료가 오래됐거나 종목이 불명확하면 분석에서 강한 근거로 사용하지 않는다.
- 저작권이 있는 유료 자료 원문을 공개 저장소에 커밋하지 않는다.
- 로컬 입력 폴더는 Git에서 제외한다.

## 전략 확장 구조

기존 공개 함수는 유지하되 내부 정책을 작은 단위로 분리할 수 있는 경계를 만든다.

- 진입 정책: 후보 조건과 통과 이유
- 분석 정책: 정량 요약과 AI 관점
- 청산 정책: 손절, 추세 이탈, 목표가의 우선순위
- 위험 정책: 현금 비중, 슬롯, 포지션 크기
- 시장 정책: 강세·약세·횡보 판단과 각 트랙에 전달할 조정값

첫 구현에서는 모든 기존 로직을 한꺼번에 이동하지 않는다. 하네스가 정책별 요구사항과 검증 시나리오를 만들 수 있는 명세를 먼저 도입하고, 실제 전략 변경이 발생할 때 한 정책씩 추출한다.

## 모순 처리

하네스는 다음 순서로 모순을 푼다.

1. 실거래 안전과 손실 제한을 우선한다.
2. 사용자가 직접 숫자로 말한 조건을 우선한다.
3. 진입보다 청산·위험 조건을 먼저 보존한다.
4. 시장 흐름 조건과 종목 조건을 분리한다.
5. AI 판단은 명시적인 코드 안전장치를 넘지 못한다.
6. 남는 모순은 하나의 질문으로 확인하거나 두 시나리오를 모두 mock에서 비교한다.

예를 들어 `신고가면 즉시 산다`와 `뉴스가 나쁠 때는 사지 않는다`가 함께 있으면, 신고가는 후보 선정으로 두고 뉴스는 최종 보류 판단으로 배치한다. 뉴스가 없을 때의 기본 행동도 함께 명시한다.

## 검증 시나리오

하네스 변경 자체와 이후 수강생 전략 변경은 다음 관점에서 검증한다.

- API 키가 전혀 없는 기본 mock 실행
- 단일 종목 실행
- 강세장, 약세장, 횡보장
- 필요한 자료가 비어 있음
- 외부 데이터 연결 실패
- 사용자가 모순된 조건을 제시함
- 매수 기준 바로 아래와 바로 위의 경계값
- 손절, 트레일링 스탑, 목표가가 겹치는 경계값
- 실거래 플래그가 없는 주문 요청
- 경로에 한글과 공백이 있는 경우
- macOS와 Windows에서 공통으로 사용할 수 있는 경로 처리
- Python 3.10 문법 호환성

검증은 표준 `unittest`를 기본으로 한다. 외부 API가 필요한 테스트는 기본 테스트에 포함하지 않고, mock 결과로 계약을 검증한다.

## macOS·Windows·Python 기준

- 지원 기준은 CPython 3.10 이상이다.
- 기본 데모 경로는 표준 라이브러리만 사용한다.
- 파일 경로는 `pathlib.Path`를 사용하고 `/Users/...`, `/tmp/...`, 드라이브 문자 같은 고정 경로를 코드에 넣지 않는다.
- 파일은 UTF-8로 읽고 쓴다.
- Bash, zsh, PowerShell 전용 문법을 Python 실행 경로에 넣지 않는다.
- 수강생 문서에는 운영체제별 명령 대신 코딩 에이전트가 Python 버전과 실행환경을 확인하도록 하는 프롬프트를 제공한다.
- Windows에서 선택 패키지 설치가 실패해도 mock 데모는 실행되어야 한다.

## 공개 저장소 안전

- `tasks/`, `강의자료/`, 로컬 입력 자료, 실제 DB, 계좌·대시보드 원본은 공개하지 않는다.
- 현재 `lecture/slides/assets/`에 있는 실계좌·대시보드 원본은 공개 커밋 대상에서 제외한다.
- CSS로 화면에서 가린 개인정보는 원본 파일에 그대로 남아 있을 수 있으므로 안전한 공개 파일로 간주하지 않는다.
- 새 하네스는 변경 전후에 Git 상태와 스테이징 파일을 확인하고, 키·토큰·계좌번호·로컬 절대경로를 검사한다.
- 공개용 구조 문서와 실제 운영 사례를 분리한다.

## 변경 대상

구현 계획은 다음 범위를 다룬다.

- `MY_STRATEGY.md`: 시장·자료·수동 입력·기억·확장·모순 항목 추가
- `.codex/`, `.claude/`, `.agents/`의 하네스 스킬: 동일한 해석·분류·검증 규칙 반영
- Codex·Claude 인터뷰어, 구현자, 검증자 역할: 쉬운 말 출력 계약과 자료 준비 상태 반영
- 하네스 참조 문서: 트랙 지도와 데이터 준비 지도 분리
- `docs/harness-lite.md`: 비전공자용 사용법과 API·수동 자료 안내
- 테스트: 세 하네스 사본의 핵심 규칙 동기화, 문서·경로 계약, Python 3.10 호환성 검사
- `.gitignore`: 로컬 입력 자료와 실계좌·대시보드 원본 보호

기존 매매 전략 코드는 이번 첫 구현에서 바꾸지 않는다. 하네스와 검증 기반을 먼저 만든 뒤, 구체적인 수강생 전략을 받을 때 TDD로 한 트랙씩 변경한다.

## 완료 조건

- 애매한 전략을 확장된 구조로 정리하는 출력 계약이 세 하네스 환경에 동일하게 존재한다.
- 자료 요구가 다섯 준비 상태 중 하나로 분류된다.
- API 키가 없을 때도 mock 검증을 계속하라는 규칙이 명시된다.
- 키·계정·수동 자료가 필요할 때 비전공자가 이해할 안내 형식이 존재한다.
- 모순된 전략의 우선순위와 질문 제한이 명시된다.
- 하네스가 macOS·Windows, Python 3.10 이상을 검증 대상으로 삼는다.
- 로컬 실계좌·대시보드 원본과 수동 입력 자료가 Git에서 제외된다.
- 기본 데모와 전체 단위 테스트가 통과한다.
- 실거래 요청은 기존 이중 안전장치 없이 계속 차단된다.
