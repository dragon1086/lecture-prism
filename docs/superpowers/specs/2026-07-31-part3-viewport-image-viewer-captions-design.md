# Part 3 브라우저 화면 맞춤·이미지 확대·캡션 교정 설계

## 목표

브라우저에서 Part 3 슬라이드가 현재 뷰포트의 세로 공간을 거의 모두 사용하게 하고, 고밀도 PRISM 원본 이미지를 더 크게 읽을 수 있게 한다. 각 이미지는 클릭하면 이미지 단독 전체화면으로 볼 수 있어야 하며, 하단 보조문구는 `PIPELINE_ARCHITECTURE_ko.md`와 실제 코드에 맞아야 한다.

## 실측 기준

- 측정 브라우저 뷰포트: 1920×958
- 현재 슬라이드 경계: 1280×720
- 현재 점유율: 가로 약 67%, 세로 약 75%
- 현재 첫 이미지 중심 슬라이드의 이미지 상자: 1160×500

## 화면 맞춤 방식

인쇄와 자료 보관의 기준인 1280×720, 16:9 캔버스는 유지한다. 화면 모드에서만 다음 배율을 계산해 각 슬라이드에 적용한다.

`min((뷰포트 너비 - 16px) / 1280, (뷰포트 높이 - 16px) / 720)`

실측 뷰포트에서는 슬라이드가 약 1675×942로 표시되어 위·아래 여백이 각각 약 8px 남는다. 창 크기가 바뀌면 배율을 다시 계산한다. 인쇄 모드에서는 배율을 적용하지 않는다.

## 이미지 중심 슬라이드

- 일반 이미지 슬라이드의 좌우 안쪽 여백을 약 24px, 위아래 여백을 12~16px로 축소한다.
- 제목과 캡션 영역은 읽을 수 있는 최소 높이만 사용한다.
- `reference-shot`의 최대 높이를 콘텐츠가 허용하는 약 610~625px까지 확대한다.
- 원본 이미지의 종횡비는 유지하고 잘라내지 않는다.
- 페이지 번호와 출처·주의 문구가 이미지 위를 가리지 않게 한다.

## 이미지 전체화면

- 슬라이드 안의 래스터 이미지는 마우스 클릭과 키보드 Enter/Space로 열 수 있다.
- 검은 배경 위에 선택한 이미지 한 장만 `object-fit: contain`으로 표시한다.
- 브라우저 Fullscreen API를 우선 사용하고, 지원되지 않거나 거부되면 고정 오버레이로 폴백한다.
- 이미지 재클릭, 바깥 배경 클릭, Esc로 닫는다.
- 전체화면 종료 이벤트와 오버레이 상태를 동기화한다.
- 이미지에는 확대 가능함을 알리는 커서와 접근성 레이블을 제공한다.

## 캡션 교정 원칙

`docs/assets/prism-insight/`의 아키텍처 이미지 14장은 `/Users/aerok/Desktop/rocky/prism-insight/prism-insight/docs/PIPELINE_ARCHITECTURE_ko.md`의 해당 이미지 직후 설명을 기준으로 다시 쓴다.

- 그림이 보여 주는 핵심 한 가지를 먼저 말한다.
- 기능 플래그, 관찰 모드, 운영 환경 확인처럼 결론을 바꾸는 조건은 생략하지 않는다.
- 코드에 없는 자동 학습, 항상 실행되는 스케줄, 확정된 기관 매도 같은 표현을 쓰지 않는다.
- 강의용 추가 이미지에는 원본 PRISM 그림이 아니라는 점과 설명용 데이터 여부를 남긴다.
- 캡션은 한두 문장으로 제한하고 이미지 면적을 침범하지 않게 한다.

## 검증

- 1920×958과 작은 16:9 뷰포트에서 슬라이드 경계와 이미지 크기를 재측정한다.
- 대표 이미지 슬라이드를 화면 캡처해 변경 전후 점유율을 비교한다.
- 전체화면 열기와 이미지·배경·Esc 닫기를 확인한다.
- 14개 원본 이미지 경로와 캡션을 원문 문서에 1:1로 매핑한다.
- 38개 슬라이드의 오버플로, 잘림, 제목 줄바꿈, 이미지 누락을 검사한다.
- 덱을 다시 생성하고 기존 테스트를 통과시킨다.
