# 기본 설정값 & 매매 철학

각 모듈에는 미리 정해둔 **기본값**이 있습니다. 파트4에서 이 값을 바꾸기 전에,
**"왜 이 값인지"**를 먼저 이해하면 본인 전략으로 바꿀 때 길을 잃지 않습니다.
모든 값은 코드 상단 상수로 모여 있어 한 줄만 고치면 동작이 실제로 바뀝니다.

## 스크리닝 — 알고리즘의 영역 (`screening.py`)

기본 학습 경로의 root `screening.py`는 7종목 데모 유니버스를 규칙으로 걸러, 필터가 실제로 결과를 바꾸는 첫 경험을 보여줍니다. 전종목 KRX 스크리너가 아닙니다. `classroom`·`paper`·`live`의 상세 후보 선별은 별도 `prism_core/screening.py`와 regime policy가 담당합니다. 두 경우 모두 규칙이 명확한 후보 선별은 **LLM이 아니라 규칙**으로 처리합니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `VOLUME_SURGE_RATIO` | `5.0` | 거래량이 최근 평균(실데이터 기준 20일)의 5배 이상 |
| `MIN_MARKET_CAP_KRW` | `5000억` | 시가총액 하한 (유동성·신뢰성 확보) |
| `MOMENTUM_DAYS` | `[5, 20]` | 5·20일 이동평균 돌파 기준 |
| `MAX_CANDIDATES` | `3` | 최종 선정 종목 수 (집중) |

## 분석 — 6섹션 리포트 (`analysis.py`)

원본 PRISM처럼 **기술·수급·재무·산업·뉴스·시장 6개 섹션**을 냅니다.
설계 원칙은 **"규칙으로 되는 건 규칙으로, 맥락 판단은 LLM으로"** 입니다.

| 섹션 | 담당 | 원천 |
|---|---|---|
| 수급·재무·산업·시장 | **규칙** | 실데이터 지표 템플릿 (거래량 프록시·PER/ROE·섹터·지수) |
| 기술·뉴스·리스크 서술 | **단일 구조화 LLM 호출** | 기술·뉴스 역할 프롬프트 (파트4 트랙B 교체 대상) |
| 추천·점수·목표가·손절가 | **규칙** | LLM이 올릴 수 없고 BUY→HOLD veto만 허용 |

| 설정 | 기본값 | 의미 |
|---|---|---|
| `LLM_MODEL` | `gpt-5.4-mini` | 분석용 모델 (`LECTURE_LLM_MODEL` 환경변수로 교체) |
| 판단 결과 | `BUY / HOLD / PASS` + 매수점수 `0~10` (목표가·손절가·손익비·투자기간 포함) | 점수가 매매 게이트로 연결됨 |

> 💡 수급(기관/외국인/개인)·재무 상세·지수는 KRX가 로그인을 요구해 무료로는 가져올 수 없습니다.
> 그래서 무료·무로그인 **yfinance**를 쓰고, 수급은 **실거래량 파생 프록시**로 정직하게 대체합니다.
> yfinance 뉴스는 영문 국제 기사라 LLM이 한국어로 해석합니다.

## 트레이딩 — 의사결정의 영역 (`trading.py`)

> 추세추종(윌리엄 오닐) 관점: **목표가는 '마일스톤'일 뿐, 수익은 트레일링 스탑으로 보호**합니다.
> 짧은 노이즈에 손절로 털리기보다, 추세가 살아있는 한 끌고 갑니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `MAX_SLOTS` | `10` | 최대 보유 종목 수 |
| `MAX_SAME_SECTOR` | `3` | 동일 섹터 최대 보유 수 (분산) |
| `CASH_RESERVE_RATIO` | `0.7` | 현금 70% 유지 (보수적 운용) |
| `BUY_SCORE_THRESHOLD` | `6` | root 데모에서 10점 만점 중 6점 이상이어야 매수 |
| `STOP_LOSS` | `-7%` (기본), 당일급등 진입 시 `-5%` | 진입 트리거별 손절폭 차등 |
| `TAKE_PROFIT` | `+15%` | 목표가 도달 = 청산 신호(마일스톤) |
| `TRAILING_STOP` | `-8%` | 고점 대비 8% 되돌림 시 청산 |

- **살 금액 계산(포지션 사이징)**: 가용현금 `= 총현금 × (1 − 0.7)` → 남은 슬롯에 **균등 배분**.
- **청산 점검 순서**: ① 손절 → ② 트레일링 스탑 → ③ 목표가 마일스톤.

`prism_core`의 상태 기반 고급 경로는 root 상수를 시장 국면별로 몰래 바꾸지 않습니다. 대신 `policy.py`가 regime별 후보 점수·손익비·손절폭·위험률·슬롯을 명시적으로 강제합니다. 기본 데모를 바꾸는 수강생은 이 표의 root 상수부터, classroom/paper/live 전략을 검증하는 수강생은 `docs/runtime-profiles.md`의 regime·policy 설명부터 확인하세요.

> ⚠️ **실제 PRISM-INSIGHT와의 차이**: lecture-prism은 이해를 돕기 위해 *현금비중 기반 균등배분*으로 단순화했습니다.
> 실제 운영 시스템은 종목당 **고정 단위금액**(`buy_amount_krw`)을 정해 `floor(금액 ÷ 현재가)`로 수량을 계산합니다.
> 둘 다 "한 종목에 과도하게 몰지 않는다"는 같은 목적이지만 구현 방식이 다릅니다.
