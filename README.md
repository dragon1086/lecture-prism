# lecture-prism

> 패스트캠퍼스 **「AI 네이티브 자동매매 시스템 구축 (실습 중심)」** 강의용 리포지토리
> [`prism-insight`](https://github.com/dragon1086/prism-insight) 본 시스템을 수업용으로 작게 줄이고, **처음 AI 코딩 에이전트를 쓰는 사람도 흐름을 이해하도록** 다시 정리한 버전입니다.

이 저장소의 목표는 “자동매매 완제품”을 바로 운영하는 것이 아닙니다.
수강생이 자신의 매매 전략을 **코딩 에이전트에게 설명하고**, 에이전트가 코드를 고치고 실행·검증하는 과정을 몸으로 익히는 것입니다.

![lecture-prism 학습 지도](docs/assets/readme/hero-learning-map.png)

## 이런 수강생을 위한 저장소입니다

- 자신의 매매 전략은 있지만 API 연동 경험을 쌓고 싶은 비전공자
- 바이브코딩을 해봤지만, 실제 프로젝트에서 어떻게 지시하고 검증하는지 배우고 싶은 입문자

그래서 이 문서에는 터미널 명령어를 직접 따라 치는 절차 대신, **코딩 에이전트에게 그대로 붙여넣는 프롬프트**를 넣었습니다.

## 0. 먼저 알아둘 것

강사가 리포지토리 다운로드 방법은 별도로 안내합니다.
이 README는 **이미 `lecture-prism` 폴더를 받은 뒤**, 그 폴더를 Claude Code·Codex 같은 코딩 에이전트에서 열었다는 전제로 시작합니다.

처음 온 수강생은 긴 설명을 다 읽기 전에 [`START_HERE.md`](START_HERE.md)의 **5분 루트**부터 따라가도 됩니다.

> 핵심 원칙: 수강생은 “무엇을 확인하고 싶은지”를 말하고, 코딩 에이전트가 필요한 설치·실행·검증 명령을 대신 수행합니다.

## 1. 처음 열었을 때: “돌아간다”를 먼저 확인하기

처음부터 패키지 설치·OAuth·Git을 한꺼번에 해결하려고 하지 마세요.
가장 먼저 확인할 것은 **API 키 없이 기본 파이프라인이 한 번 도는지**입니다.

![처음 5분 루트](docs/assets/readme/five-minute-start.png)

아래 프롬프트를 코딩 에이전트에게 그대로 입력하세요.

```text
이 lecture-prism 프로젝트가 내 컴퓨터에서 기본 데모로 실행되는지 먼저 확인해줘.

반드시 아래 순서로 진행해줘:
1. 지금 폴더가 lecture-prism 프로젝트 루트인지 확인해줘.
2. 내 컴퓨터에 Python 3.10 이상이 설치되어 있는지 확인해줘.
3. Python이 없거나 버전이 낮으면, 내 운영체제에 맞는 설치 방법을 안내하고 가능한 범위에서 설치까지 도와줘.
4. 외부 패키지 설치는 일단 하지 말고, 먼저 API 키 없이 main.py 데모가 실행되는지 확인해줘.
5. 기본 데모가 성공하면 그 다음에 대시보드·실데이터·실LLM 연동에 필요한 requirements.txt 설치를 진행해줘.
6. 패키지 설치가 실패해도 기본 데모가 이미 성공했는지 구분해서 설명해줘.
7. 마지막에 내가 다음에 입력할 수 있는 프롬프트 3개를 추천해줘.

내가 직접 터미널 명령어를 치지 않도록, 필요한 명령은 네가 실행하고 결과를 설명해줘.
```

### 성공 기준

코딩 에이전트가 마지막에 아래 내용을 확인해주면 첫 단계는 성공입니다.

- 현재 폴더가 `lecture-prism` 루트임
- Python 3.10 이상 확인
- `main.py` 데모 실행 성공
- 스크리닝 → 분석 → 시뮬레이션 매매 → 피드백 저장 순서 확인
- `prism.db`가 생성되고 분석·매매·교훈 데이터가 기록됨
- 선택 패키지 설치가 필요한 단계와 필요 없는 단계를 구분해서 설명

## 2. 프로젝트를 한 장으로 보기

![lecture-prism 파이프라인 지도](docs/assets/readme/pipeline-map.png)

lecture-prism은 **네 개의 파이프라인 단계와 하나의 확인 화면**으로 움직입니다.

1. **screening.py** — 많은 종목 중 후보를 추립니다.
2. **analysis.py** — 후보 종목을 AI 에이전트들이 순서대로 분석합니다.
3. **trading.py** — 분석 결과를 바탕으로 매수·청산·리스크 판단을 합니다. 기본은 시뮬레이션입니다.
4. **feedback.py** — 매매 결과와 교훈을 `prism.db`에 남깁니다.
5. **dashboard.py** — 저장된 결과를 웹 화면에서 보여줍니다.

더 자세한 그림은 [`docs/architecture.md`](docs/architecture.md)에 모아두었습니다.

## 3. 파일별 역할

![파일별 역할 지도](docs/assets/readme/module-guide.png)

| 파일 | 쉬운 설명 | 수강생이 주로 바꾸는 곳 |
|---|---|---|
| `screening.py` | “어떤 종목을 볼까?”를 정하는 필터 | 거래량, 시총, 모멘텀 같은 진입 조건 |
| `analysis.py` | “이 종목을 AI가 어떻게 해석할까?”를 정하는 분석 파이프라인 | 기술적 분석·뉴스 분석 프롬프트 |
| `trading.py` | “얼마나 사고, 언제 팔까?”를 정하는 매매 판단 | 매수 점수, 현금 비중, 손절·목표가·트레일링 스탑 |
| `feedback.py` | “이번 판단에서 무엇을 배웠나?”를 기록 | 교훈 추출 방식 |
| `db.py` | 모든 결과가 저장되는 SQLite 저장소 | 보통 수정하지 않음 |
| `dashboard.py` | 결과를 보는 로컬 웹 대시보드 | 표·카드·설명 추가 |
| `blank_pipeline.py` | 처음부터 직접 구현해보는 빈 뼈대 | 심화 실습 |

## 4. 가장 먼저 실행해보기

```text
lecture-prism 전체 파이프라인을 API 키 없이 데모 모드로 실행해줘.
스크리닝 → AI 분석 → 시뮬레이션 매매 → 피드백 저장 순서로 진행하고,
각 단계에서 어떤 파일의 어떤 함수가 호출됐는지 초보자도 이해할 수 있게 설명해줘.
마지막에는 prism.db에 무엇이 저장됐는지도 확인해줘.
```

예상 흐름:

- 데모 종목 후보가 선정됩니다.
- LLM 연결이 없으면 mock 분석 결과로 자동 폴백합니다.
- 실거래가 아니라 시뮬레이션 매매만 수행합니다.
- 분석 결과·매매 결과·교훈이 `prism.db`에 저장됩니다.

### 선택: 내장 ChatGPT OAuth 프록시로 실제 LLM 연결하기

원본 PRISM-INSIGHT처럼 이 리포지토리에도 **ChatGPT OAuth 프록시 기본형**이 들어 있습니다.
그래서 수강생이 프록시 코드를 처음부터 만들 필요는 없습니다. 기본 데모가 성공한 뒤, 실제 LLM 응답을 보고 싶을 때만 아래 프롬프트를 사용하세요.

![API 키와 선택 연동 안전 지도](docs/assets/readme/optional-integrations-safety.png)

```text
lecture-prism에 포함된 ChatGPT OAuth 프록시로 실제 LLM 분석을 연결해줘.

조건:
1. 프록시를 새로 만들지 말고, cores/chatgpt_proxy 안의 기본 구현을 사용해줘.
2. 필요한 패키지가 설치되어 있는지 확인하고, 부족하면 requirements.txt 기준으로 설치해줘.
3. ChatGPT Plus 또는 Pro 계정으로 최초 로그인이 필요한지 확인하고, 필요한 경우 브라우저 로그인 과정을 안내해줘.
4. 프록시가 localhost:18741에서 정상 응답하는지 health check로 검증해줘.
5. 그 다음 analysis.py로 005930을 분석해서 실제 LLM 응답인지 mock 폴백인지 구분해줘.
6. 실패해도 기본 데모 모드는 망가뜨리지 말고, 실패 원인과 다음 행동을 설명해줘.

내가 직접 터미널 명령어를 치지 않도록 필요한 실행과 검증은 네가 해줘.
```

API 키 준비가 궁금하면 [`docs/api-keys.md`](docs/api-keys.md)를 먼저 보세요. 강의 기본 실습에는 필수 키가 없습니다.

수강생이 KIS가 아니라 키움증권·토스증권·다른 증권사 API를 준비해 왔다면 [`docs/broker-adapters.md`](docs/broker-adapters.md)를 보세요. `trading.py`를 갈아엎지 않고 `.env`의 `LECTURE_BROKER` 값으로 브로커 어댑터를 바꾸는 구조를 제공합니다.

```text
analysis.py로 삼성전자 005930을 분석해줘.

대시보드에서 매매현황, AI 분석 근거, 축적된 교훈이 어디에 보이는지 설명해줘.
```

## 5.5 기본 설정값 & 매매 철학

각 모듈에는 미리 정해둔 **기본값(디폴트)**이 있습니다. 파트4에서 이 값을 바꾸기 전에,
**"왜 이 값인지"**를 먼저 이해하면 본인 전략으로 바꿀 때 길을 잃지 않습니다.
모든 값은 코드 상단 상수로 모여 있어 한 줄만 고치면 동작이 실제로 바뀝니다.

### 스크리닝 — 알고리즘의 영역 (`screening.py`)
규칙이 명확하고 대량(약 2,700종목)을 빠르게 걸러야 하므로 **LLM이 아니라 규칙**으로 처리합니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `VOLUME_SURGE_RATIO` | `5.0` | 거래량이 5일 평균의 5배 이상 |
| `MIN_MARKET_CAP_KRW` | `5000억` | 시가총액 하한 (유동성·신뢰성 확보) |
| `MOMENTUM_DAYS` | `[5, 20]` | 5·20일 이동평균 돌파 기준 |
| `MAX_CANDIDATES` | `3` | 최종 선정 종목 수 (집중) |

### 분석 — LLM 에이전트의 영역 (`analysis.py`)
맥락·뉘앙스 판단이 필요한 영역이라 **여러 전문 에이전트로 분리**합니다(Prompt Chaining).

| 설정 | 기본값 | 의미 |
|---|---|---|
| `LLM_MODEL` | `gpt-5.4-mini` | 분석용 모델 (`LECTURE_LLM_MODEL` 환경변수로 교체) |
| 에이전트 순서 | 기술적 분석 → 뉴스 → 투자전략 | 앞 단계 결과가 다음 단계로 전달 |
| 판단 결과 | `BUY / HOLD / PASS` + 확신점수 `1~5` | 점수가 매매 게이트로 연결됨 |

### 트레이딩 — 의사결정의 영역 (`trading.py`)
> 추세추종(윌리엄 오닐) 관점: **목표가는 '마일스톤'일 뿐, 수익은 트레일링 스탑으로 보호**합니다.
> 짧은 노이즈에 손절로 털리기보다, 추세가 살아있는 한 끌고 갑니다.

| 상수 | 기본값 | 의미 |
|---|---|---|
| `MAX_SLOTS` | `10` | 최대 보유 종목 수 |
| `MAX_SAME_SECTOR` | `3` | 동일 섹터 최대 보유 수 (분산) |
| `CASH_RESERVE_RATIO` | `0.7` | 현금 70% 유지 (보수적 운용) |
| `BUY_SCORE_THRESHOLD` | `4` | 5점 만점 중 4점 이상이어야 매수 |
| `STOP_LOSS` | `-7%` (기본), 당일급등 진입 시 `-5%` | 진입 트리거별 손절폭 차등 |
| `TAKE_PROFIT` | `+15%` | 목표가 도달 = 청산 신호(마일스톤) |
| `TRAILING_STOP` | `-8%` | 고점 대비 8% 되돌림 시 청산 |

- **포지션 사이징**: 가용현금 `= 총현금 × (1 − 0.7)` → 남은 슬롯에 **균등 배분**.
- **청산 점검 순서**: ① 손절 → ② 트레일링 스탑 → ③ 목표가 마일스톤.

> ⚠️ **실제 PRISM-INSIGHT와의 차이**: lecture-prism은 이해를 돕기 위해 *현금비중 기반 균등배분*으로 단순화했습니다.
> 실제 운영 시스템은 종목당 **고정 단위금액**(`buy_amount_krw`)을 정해 `floor(금액 ÷ 현재가)`로 수량을 계산합니다.
> 둘 다 "한 종목에 과도하게 몰지 않는다"는 같은 목적이지만 구현 방식이 다릅니다.

### 피드백 — 메모리 & 자기개선 (`feedback.py`)
인간 투자자의 **매매일지와 동일한 구조**입니다. 교훈을 추출해 다음 매매 판단에 반영합니다.

| 메모리 계층 | 담는 것 |
|---|---|
| 단기 (당일) | 오늘 매매 패턴, 체결 이슈 |
| 중기 (주간) | 섹터 트렌드, 반복 패턴 |
| 장기 (월간) | 시장 체제 판단, 전략 수정 이력 |

> 💡 이 값들은 모두 **출발점**일 뿐입니다. 파트4에서 본인의 매매 이론(진입/청산/리스크)에 맞게
> 자유롭게 바꿔보세요 — 바꾼 뒤 데모 모드로 실행하면 결과가 어떻게 달라지는지 바로 확인할 수 있습니다.
> 값을 실제로 바꾸는 실습은 [`lecture/exercises/part4_실습가이드.md`](lecture/exercises/part4_실습가이드.md)를 참고하세요.

## 6. 내 전략을 넣는 방법

> 이 리포지토리에는 **Strategy Harness Lite**가 들어 있습니다. 수강생이 전략을 두루뭉술하게 말해도 코딩 에이전트가 진입·분석·청산·리스크 중 어디를 바꿀지 정리하고, 가장 안전한 한 파일부터 수정·검증하도록 돕는 간단한 하네스입니다. 자세한 내용은 [`docs/harness-lite.md`](docs/harness-lite.md)와 [`MY_STRATEGY.md`](MY_STRATEGY.md)를 참고하세요.
>
> 만약 코딩 에이전트가 하네스를 모르는 것처럼 답하면 이렇게 말하세요: “`docs/harness-lite.md`와 `MY_STRATEGY.md`를 먼저 읽고 Strategy Harness Lite 방식으로 진행해줘.”

가장 쉬운 시작 프롬프트:

```text
MY_STRATEGY.md를 읽고 내 전략을 lecture-prism에 반영해줘.
내 설명이 부족하면 네가 먼저 합리적으로 정리하고,
진짜 꼭 필요한 질문만 하나만 해줘.
처음에는 Part 4 트랙 A/B/C/D 중 가장 안전한 것 하나만 골라서 수정해줘.
수정 후에는 API 키 없이 데모 모드로 실행 검증하고,
수정 전후 차이를 초보자도 이해하게 설명해줘.
실거래는 절대 하지 마.
```

![Strategy Harness Lite 흐름](docs/assets/readme/strategy-harness-lite.png)

처음부터 전부 바꾸려고 하지 마세요. 아래 네 트랙 중 **하나만** 골라도 성공입니다.

| 트랙 | 내가 가진 전략 | 바꿀 파일 | 예시 프롬프트 |
|---|---|---|---|
| A | 진입 조건 | `screening.py` | “RSI 30 이하 + 거래량 3배 이상만 후보로 남겨줘.” |
| B | 분석 관점 | `analysis.py` | “기술적 분석 에이전트를 볼린저밴드 하단 반등 관점으로 바꿔줘.” |
| C | 청산 규칙 | `trading.py` | “목표가 +20%, 손절 -5%, 트레일링 -10%로 바꿔줘.” |
| D | 리스크 관리 | `trading.py` | “최대 5종목, 현금 50% 유지, 매수 점수 3 이상으로 바꿔줘.” |

### 추천 프롬프트 템플릿

```text
내 전략을 lecture-prism에 반영해줘.

내 전략:
- 진입 조건: [여기에 내 진입 조건]
- 청산 조건: [여기에 내 청산 조건]
- 리스크 관리: [여기에 내 리스크 원칙]

오늘은 위 전략 중 하나만 구현하고 싶어.
초보자에게 가장 안전한 수정 범위를 추천한 뒤,
해당 파일을 수정하고,
수정 전후 실행 결과가 어떻게 달라졌는지 검증해줘.
함수 시그니처는 유지하고, API 키 없이 데모 모드에서 검증해줘.
```

## 7. Git 제출도 명령어 대신 프롬프트로

![제출 전 보안 체크](docs/assets/readme/submission-security.png)

GitHub 제출은 **선택**입니다. 수업 중 성공 기준은 먼저 “내 전략이 데모 모드에서 실행되는 것”입니다. 제출이 막히면 화면 공유나 결과 캡처로 대체해도 됩니다.

실습 결과물을 본인 이름 브랜치에 올릴 때도 직접 Git 명령어를 칠 필요가 없습니다.

```text
내 실습 결과를 제출할 수 있게 Git 작업을 도와줘.

조건:
1. 현재 변경 파일을 먼저 보여주고, API 키·토큰·DB 파일 같은 민감한 파일이 포함되어 있지 않은지 확인해줘.
2. main 브랜치가 아니라 내 이름 브랜치에서 작업하게 해줘. 브랜치 이름은 [본인이름-영문] 으로 해줘.
3. 변경 내용을 커밋해줘. 커밋 메시지는 "내 전략 적용"으로 해줘.
4. 원격 저장소에 내 이름 브랜치를 push해줘.
5. push가 실패하면 collaborator 권한 문제인지, 로그인 문제인지, 원격 저장소 문제인지 구분해서 설명해줘.

위 과정에서 필요한 Git 명령은 네가 실행하고, 각 단계 결과를 나에게 확인시켜줘.
```

> 푸시가 안 되면 강사에게 collaborator 초대를 받았는지 확인하세요. GitHub는 공개 저장소라도 write 권한이 있어야 push할 수 있습니다.

## 8. 보안: 절대 올리면 안 되는 것

이 리포지토리는 강의용으로 공개될 수 있습니다. API 키·인증 파일은 절대 커밋하면 안 됩니다.

커밋 전에는 아래 프롬프트를 사용하세요.

```text
커밋하기 전에 보안 점검해줘.

확인할 것:
1. Git에 올라갈 파일 목록을 보여줘.
2. .env, secrets yaml, token, prism.db, KIS 인증 파일이 포함되어 있지 않은지 확인해줘.
3. trading/trading/config/kis_devlp.yaml 같은 실제 인증 파일이 Git에서 제외되는지 확인해줘.
4. 문제가 있으면 커밋하지 말고, 어떤 파일을 제외해야 하는지 설명해줘.
5. 안전하면 그때만 커밋을 진행해줘.
```

## 9. 막혔을 때 바로 쓰는 프롬프트

| 상황 | 코딩 에이전트에게 입력 |
|---|---|
| 에러가 났을 때 | “이 에러가 났어: `[에러 메시지]`. 원인을 초보자 기준으로 설명하고, 고친 뒤 같은 실행을 다시 검증해줘.” |
| 코드가 이해 안 될 때 | “`_decide_position` 함수가 어떤 순서로 매수 여부와 수량을 정하는지 예시 숫자로 설명해줘.” |
| 내 전략이 반영됐는지 궁금할 때 | “내 전략 3줄과 현재 코드를 비교해서 정확히 반영된 부분과 아직 반영 안 된 부분을 표로 정리해줘.” |
| 다음에 뭘 할지 모르겠을 때 | “현재 프로젝트 상태를 보고 다음 실습으로 할 만한 것 3가지를 난이도와 함께 추천해줘.” |
