# lecture-prism Fluent Korean

snflkd/fluent-korean의 출력 원칙을 lecture-prism 문서와 산출물에 맞게 적용합니다. 목표는 멋있게 꾸민 문장이 아니라, 수강생이 한 번 읽고 뜻과 다음 행동을 이해하는 문장입니다.

## 적용 범위

- 한국어 설명, 강사 스크립트, 수강생 프롬프트, 보고서, HTML의 화면 문구에 적용합니다.
- 변수명, 함수명, 파일명, 로그 원문, 코드 블록, 인용문은 원형을 유지합니다.
- 기술 용어는 널리 쓰이는 표현을 우선하고, 필요한 경우 처음 한 번만 쉬운 설명을 덧붙입니다.
- 사용자의 말투를 흉내 내지 말고, 수강생에게 예의 있고 자연스러운 존댓말을 사용합니다.

## 문장 원칙

- 조사와 어미를 생략하지 않습니다. 명사만 이어 붙인 문장 대신 주어와 서술어가 있는 문장을 씁니다.
- 문장 성분을 줄여 의미를 숨기지 않습니다. `그러면 경고가 붙습니다`보다 `그러면 이미 작업 중인 파일에도 경고 표지가 추가됩니다`처럼 씁니다.
- 통용되는 단어를 사용합니다. 꼭 필요하지 않다면 비유적 표현, 번역투, 낮은 사용 빈도의 단어를 피합니다.
- 영어를 섞어 권위 있어 보이게 만들지 않습니다. 기술 용어·고유명사·코드가 아니면 자연스러운 한국어로 씁니다.
- 한 문단에 한 가지 핵심만 둡니다. 긴 결과는 요약을 먼저 보여 주고 상세 근거를 뒤에 둡니다.
- 같은 길이의 문장을 반복하지 않습니다. 불필요한 접속사와 강조 부사를 줄입니다.
- 엠대시(`—`)와 기계적인 대조 표현을 피하고, 필요한 관계는 문장으로 풀어 씁니다.

## 프롬프트를 쓸 때

- 실제 사용자가 부탁하듯 시작합니다. `아래 열다섯 단계를 반드시 수행해`보다 `이 부분을 한번 살펴보고, 결과를 이해하기 쉽게 정리해 줘`를 우선합니다.
- 안전·시크릿·실거래 경계처럼 빠지면 안 되는 내용은 분명하게 씁니다. 나머지 구현 세부는 저장소를 읽고 에이전트가 판단하게 둡니다.
- 출력은 `요약 → 근거 → 다음 행동` 순서로 요청합니다.
- 긴 표나 설명이 예상되면 `docs/lecture-prism-output-style.md`를 따르고 `reports/interactive/`에 HTML을 만들도록 요청합니다.
- 확인하지 않은 결과는 성공이라고 쓰지 말고 `확인 필요`, `폴백`, `추정`을 구분하게 합니다.

## 마지막 점검

출력 직전에 다음을 확인합니다.

- 주어·목적어·서술어가 빠져 뜻이 흐려지지 않았는가?
- 기술 용어와 코드가 아닌 영어가 불필요하게 섞이지 않았는가?
- 비슷한 문장과 목록이 반복되지 않는가?
- 독자가 첫 화면에서 결과와 다음 행동을 알 수 있는가?
