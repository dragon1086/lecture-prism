# System Completion Lane 검증 지도

이 단계는 Track E가 아니다. A/B/C/D 중 한 트랙을 데모로 검증한 뒤, 같은 실행의 사실이 알림·주문·대시보드에서 일치하는지 확인한다.

## 진행 게이트

- 선택한 전략 트랙과 변경 파일이 하나인지 확인한다.
- 관련 데모와 API 키 없는 전체 mock 파이프라인이 성공한 뒤에만 시작한다.
- System Completion Lane에서는 전략 파일을 추가로 넓혀 고치지 않는다.

## 실행 진실

| 증거 | 확인 기준 |
|---|---|
| `run_id` | 이벤트·알림·주문·분석·교훈이 같은 값을 사용 |
| `sequence` | 시작부터 완료 또는 실패까지 증가하며 중복되지 않음 |
| `data_as_of` | 실제 데이터 기준일. 휴장일이면 최근 영업일을 오늘로 꾸미지 않음 |
| `market_status` | 장중·장외·휴장·확인 불가를 구분하고 분석 가능 여부와 주문 허용 여부를 분리 |

## 알림 전달

- Discord는 3주차 필수 준비 채널이다. 로컬 `.env`에 설정된 경우 단계별 전달 상태를 확인한다.
- Telegram은 선택 채널이다. 설정된 경우 Discord와 동일한 `run_id`와 `sequence`를 확인한다.
- 한 채널의 실패는 `failed`로 남기고 파이프라인을 멈추지 않는다.
- 웹훅 URL, 봇 토큰, chat id 원문은 로그·답변·제출물에 노출하지 않는다.

## 주문 진실

| 상태 | 쉬운 뜻 | 포트폴리오 반영 |
|---|---|---|
| `accepted` | 주문 접수 | 반영하지 않음 |
| `partial_fill` | 일부 체결 | 실제 `filled_qty`만 반영 |
| `filled` | 전량 체결 | 실제 `filled_qty` 반영 |
| `blocked` | 휴장·설정·안전 조건으로 주문 전 차단 | 반영하지 않음 |
| `live_blocked` | 실전 주문 안전 차단 | 반영하지 않음 |

모르는 현금 잔고·평가액은 추정하지 않는다. KIS 모의투자 호출도 외부 요청이므로 사용자가 `LECTURE_ENABLE_LIVE_BROKER=1`을 명시적으로 선택한 경우에만 실행한다. 실전 허용 플래그는 수업에서 켜지 않는다.

## 대시보드 완료 증거

- 선택한 `run_id`와 `data_as_of`가 상단에 보인다.
- 파이프라인 단계와 Discord·Telegram 전달 결과가 순서대로 보인다.
- 주문 접수와 체결이 분리되고 실제 체결 수량만 포지션에 보인다.
- 기술·수급·재무·산업·뉴스·시장 6섹션과 교훈이 같은 실행에서 왔다.
- 빈 DB나 실패 상태를 샘플 숫자로 꾸미지 않는다.
