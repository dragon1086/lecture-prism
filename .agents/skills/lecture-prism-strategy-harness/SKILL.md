# lecture-prism Strategy Harness Lite

이 스킬은 `revfactory/harness`의 “도메인별 에이전트/스킬로 작업을 안전하게 구조화한다”는 아이디어를 lecture-prism 강의용으로 줄인 것이다.

목표는 수강생이 개떡같이 말해도 다음 흐름이 자동으로 일어나게 하는 것이다.

1. 말에서 전략 의도를 뽑는다.
2. Part 4 트랙 A/B/C/D 중 가장 안전한 1개를 고른다.
3. 최소 파일만 수정한다.
4. API 키 없이 데모 모드로 실행 검증한다.
5. 초보자에게 “무엇을 바꿨고 왜 결과가 달라졌는지” 설명한다.

## 언제 사용하나

다음 표현이 있으면 이 스킬을 사용한다.

- “내 전략 반영해줘”
- “MY_STRATEGY.md 읽고 바꿔줘”
- “하네스 써서 알아서 해줘”
- “과매도 반등 전략으로 바꿔줘”
- “손절을 좀 타이트하게”
- “현금 비중을 더 남기고 싶어”
- “수강생 실습 도와줘”
- “뭘 바꿔야 할지 모르겠는데 알아서 추천해줘”

## 기본 원칙

- 수강생에게 명령어를 치라고 하지 않는다. 필요한 실행은 에이전트가 한다.
- 질문은 최대 1개만 한다. 합리적 기본값으로 진행 가능하면 묻지 않는다.
- 한 번에 1개 트랙만 구현한다. 욕심내서 전부 바꾸지 않는다.
- 전략이 여러 트랙에 걸치거나 수강생이 “전부 반영해줘”라고 해도 한 번에 다 수정하지 않는다. 트랙 순서를 먼저 제안한 뒤, **[한 트랙 수정 → 데모 검증 → 전후 비교 보고] 사이클을 트랙별로 반복**한다. 한 사이클에 한 트랙.
- 실거래 금지. KIS 실제 주문, `--live`, 실제 인증 파일 수정 금지.
- API 키 없이 데모 모드에서 검증 가능해야 한다.
- 함수 시그니처를 유지한다.
- 새 의존성을 추가하지 않는다.
- 시크릿, token, `prism.db`는 커밋 대상으로 만들지 않는다.

## 트랙 선택 규칙

| 트랙 | 파일 | 선택 조건 | 난이도 |
|---|---|---|---|
| A | `screening.py` | RSI, 거래량, 시총, 이동평균, 신고가 등 정량 진입 조건 | 쉬움 |
| B | `analysis.py` | 피터 린치, 그레이엄, 오닐, 뉴스/재무/모멘텀 관점 등 분석 프롬프트 | 쉬움 |
| C | `trading.py` `_decide_exit` | 목표가, 손절, 트레일링 스탑, 절반 청산 등 청산 규칙 | 보통 |
| D | `trading.py` 상수 | 최대 종목 수, 현금 비중, 매수 점수, 손절폭 등 리스크 원칙 | 쉬움 |

판단이 애매하면 아래 우선순위를 따른다.

1. 숫자가 있는 진입 조건이면 A
2. 철학/관점/스타일이면 B
3. 언제 팔지 이야기하면 C
4. 얼마나 살지/현금/종목 수 이야기하면 D
5. 정말 불명확하면 B를 추천하되, 구현 전 수강생에게 “분석 관점부터 바꿔볼까요?”라고 1개 질문

## 작업 흐름

### 1. 전략 입력 수집

먼저 아래를 읽는다.

- 사용자 메시지
- `MY_STRATEGY.md`가 있으면 그 내용
- `README.md`의 하네스 안내
- `lecture/exercises/part4_실습가이드.md`의 트랙 설명

### 2. 전략 정리

내부적으로 다음 구조로 정리한다.

```text
진입:
분석 관점:
청산:
리스크:
모호한 점:
추정한 기본값:
추천 트랙:
```

### 3. 최소 수정

선택한 트랙에 해당하는 파일만 우선 수정한다.
여러 트랙이 필요한 전략이면 이번 사이클에서는 첫 트랙만 수정하고, 나머지 트랙은 보고의 “다음에 바꾸면 좋은 것”에 순서대로 남겨 다음 사이클에서 처리한다.

- A: `screening.py`
- B: `analysis.py`
- C: `trading.py`
- D: `trading.py`

수정 전후 비교를 위해 가능하면 변경 전 실행 결과를 먼저 확보한다.

### 4. 검증

트랙별 검증 기준:

- A: 스크리닝 단독 실행 + 전체 파이프라인 데모 실행
- B: 단일 종목 분석 실행 + 가능하면 전체 파이프라인 데모 실행
- C: 청산 데모 실행
- D: 시뮬레이션 매매 실행

공통 검증:

- 변경 파일 Python compile 통과
- 실거래 경로가 실행되지 않았는지 확인
- 시크릿 파일이 변경되지 않았는지 확인

### 5. 보고

수강생에게는 전문 용어보다 쉬운 말로 설명한다.

```markdown
## 이번에 반영한 전략
-

## 바꾼 파일
-

## 왜 이 트랙을 골랐나
-

## 검증 결과
-

## 다음에 바꾸면 좋은 것
-
```

## “개떡같은 말” 해석 예시

| 수강생 표현 | 해석 | 추천 트랙 |
|---|---|---|
| “너무 오른 건 말고 눌렸다가 튀는 애들” | 과매도/반등 진입 조건 | A 또는 B |
| “손절 좀 빨리” | 손절폭 축소 | C |
| “겁나게 몰빵하지 말고” | 종목 수/현금 비중/포지션 크기 제한 | D |
| “뉴스 좋은 애만” | 뉴스 분석 프롬프트 강화 | B |
| “거래량 터진 애” | 거래량 급등 조건 | A |
| “가치투자 느낌” | 분석 프롬프트를 가치/재무 관점으로 변경 | B |

## 에이전트 역할

이 하네스는 다음 로컬 에이전트 정의와 함께 쓰면 좋다.

- `lecture-strategy-interviewer`: 애매한 전략을 트랙 요구사항으로 정리
- `lecture-strategy-implementer`: 최소 파일 수정 및 데모 검증
- `lecture-strategy-verifier`: 의도 반영, 안전, 검증 결과 확인

Codex 환경에서는 필요할 때 이 역할 이름의 서브에이전트를 사용할 수 있다. Claude Code 환경에서는 같은 역할 설명을 프롬프트로 전달해도 된다.

## 금지

- 실거래 주문 실행
- 수강생에게 터미널 명령어를 직접 치라고 안내
- 한 번에 여러 트랙을 동시 수정 (여러 트랙 요청은 한 트랙씩 순차 사이클로)
- API 키 없이는 아무것도 못 한다고 중단
- 검증 없이 “완료”라고 말하기
