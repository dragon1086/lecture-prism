에이전트 기초 · 도구 호출

에이전트가 바깥 정보를 읽으려면 도구가 필요합니다

이 프로젝트에서는 LLM 호출도 입력을 보내고 결과를 받는 하나의 도구 사용입니다.

도구 호출은 거창한 기능이 아닙니다. 필요한 입력을 보내고, 돌아온 결과가 약속한 모양인지 확인하는 과정입니다.

에이전트 기초 · 오케스트레이션 패턴

여러 에이전트는 일을 연결하는 방식에 따라 패턴이 달라집니다

그림 · 클릭해 확대 패턴 연결 방식 lecture-prism에서는
Sequential / Pipeline [A][M][O] 앞 결과를 다음 단계의 입력으로 전달 주 패턴 · screening → analysis → buy → trading → feedback
Concurrent / Fan-out·Fan-in [A][M][O] 독립 작업을 동시에 실행한 뒤 결과를 합침 분석 내부 · 병렬 전문가 6명 → 편집, asyncio.gather
Routing / Handoff [A][M][O] 입력·맥락에 맞는 전문가를 고르거나 통제권을 넘김 기본 실행에는 없음 · 트랙 선택은 사람의 선택
Orchestrator–Workers [A][O] 관리자가 문제를 동적으로 쪼개고 작업자 결과를 종합 코딩 에이전트 작업에는 활용 가능 · 기본 파이프라인은 고정
Maker–Checker [A][M][O] 만들기 → 평가 → 피드백 반영을 통과할 때까지 반복 Strategy Harness Lite의 구현자 → 검증자에 가까움
Magentic / Adaptive planning [M] 실행 중 작업 장부와 다음 계획을 계속 갱신 기본 실행에는 없음 · 복잡하고 열린 문제에 쓰는 상위 패턴
lecture-prism의 중심은 예측 가능한 순차 파이프라인이며, 분석 단계 안에 병렬 전문가 패턴을 중첩합니다.
