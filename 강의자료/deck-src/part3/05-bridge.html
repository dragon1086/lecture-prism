원본은 청산이 끝난 뒤 계획과 결과를 비교하고, 반복 교훈과 재진입 제한을 다음 판단에 전달합니다.

원본 PRISM의 닫힌 피드백 루프

기억은 저장만 해서는 다음 판단에 영향을 주지 못합니다

청산 완료
매매일지
진입 근거, 매도 이유, 수익률, 당시 상황을 함께 남깁니다.
회고
교훈 추출
잘한 점, 놓친 신호, 다음 행동을 구조화합니다.
선별
원칙·직관
반복 횟수와 신뢰도를 붙여 약한 기억을 걸러 냅니다.
재사용
다음 진입
같은 종목·섹터·트리거 이력과 장기 원칙을 프롬프트에 넣습니다.
원본은 과거 기록을 참고했는지와 이후 성과도 따로 비교합니다. 기억 역시 검증 대상입니다.

모듈 4 · 실제 운영 배치

실제 운영에서는 매주 기록을 압축합니다

실제 서버의 일요일 03:00 배치와 2026-07-26 로그를 바탕으로 만든 설명 그림입니다. 압축은 성과 보장이 아닙니다.

33
운영 데이터에서 배운 점

기억을 참고했다고 성과가 자동으로 좋아지지는 않았습니다

최근 90일 관측

메모리 참조 거래와 비참조 거래를 나눠 평균 수익률·승률을 기록했습니다.

한국: 참조 70건 / 비참조 29건
미국: 참조 29건 / 비참조 45건

두 시장 모두 이 기간에는
참조 거래의 평균 성과가 더 낮았습니다.

이 숫자를 읽는 법

관찰 상관관계이지 메모리가 손실을 만들었다는 인과 증명은 아닙니다.

표본 선택이 다를 수 있음
시장 국면이 다를 수 있음
어려운 거래에서 기억을 더 자주 봤을 수 있음

→ 기억도 성과로 검증하고 정리한다

원본과 강의용 축소판 비교

feedback.py와 memory.py가 작은 피드백 루프를 만듭니다

청산 뒤 생성

단기 교훈

BUY 직후에는 결과 교훈을 만들지 않습니다. SELL이 끝난 뒤에 판단 기록을 남깁니다.

API 키 없음

결정론적 압축

7일 뒤 중기, 30일 뒤 반복 장기 원칙으로 옮기고 활성 장기 원칙을 20개로 제한합니다.

다음 진입 참고

최대 5개 전달

같은 종목의 최근 기록과 반복 장기 원칙을 BUY 결정 기록에 함께 남깁니다.

강의판에는 LLM 회고, 섹터·트리거 성과 보정, 신뢰도 재계산, 재진입 쿨다운이 없습니다.

모듈 4 · 구조 질문과 보조 작업 실행

메인 파이프라인 밖의 작업도 하나씩 확인합니다

아래 문장을 코딩 에이전트에게 그대로 붙여넣습니다.

1. feedback.py, memory.py, operations.py의 역할을 나눠 설명해줘.

2. python3 feedback.py와 python3 operations.py compress를 실행해줘.

3. python3 operations.py monitor로 보유종목 점검을 시뮬레이션해줘.

4. python3 operations.py reconcile --broker kis는 새 주문 없이 조회만 하는지 확인해줘.

5. 예약 시각과 실제 주문 설정은 바꾸지 마.

6. 원본과 비교해 어떤 보조 시스템이 더 필요한지 세 가지로 정리해줘.

schedule은 구조를 읽는 용도입니다. 수업 중에는 켜지 않고 한 번 실행하는 명령만 사용합니다.
