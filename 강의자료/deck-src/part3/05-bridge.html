실제 운영에서는 매주 기록을 압축합니다

실제 서버의 일요일 03:00 배치와 2026-07-26 로그를 바탕으로 만든 설명 그림입니다. 압축은 성과 보장이 아닙니다.

운영 데이터에서 배운 점

기억을 참고했다고 성과가 자동으로 좋아지지는 않았습니다

최근 90일 관측

메모리 참조 거래와 비참조 거래를 나눠 평균 수익률·승률을 기록했습니다.

한국: 참조 70건 / 비참조 29건
미국: 참조 29건 / 비참조 45건

두 시장 모두 이 기간에는
참조 거래의 평균 성과가 더 낮았습니다.

이 숫자를 읽는 법

관찰 상관관계이지 메모리가 손실을 만들었다는 인과 증명은 아닙니다.

표본 선택이 다를 수 있음
시장 국면이 다를 수 있음
어려운 거래에서 기억을 더 자주 봤을 수 있음

→ 기억도 성과로 검증하고 정리한다

AI 회고와 기억 시스템을 기록·압축·예약 작업의 작은 루프로 줄였습니다

청산 결과가 교훈으로 저장되고, 기억 압축과 보조 작업을 거쳐 다음 판단에 다시 연결되는 위치를 봅니다.

모듈 4 · 구조 질문과 보조 작업 실행

메인 파이프라인 밖의 작업도 하나씩 확인합니다

아래 문장을 코딩 에이전트에게 그대로 붙여넣습니다.

1. feedback.py, memory.py, operations.py의 역할을 나눠 설명해줘.

2. python3 feedback.py와 python3 operations.py compress를 실행해줘.

3. python3 operations.py monitor로 보유종목 점검을 시뮬레이션해줘.

4. python3 operations.py reconcile --broker kis는 새 주문 없이 조회만 하는지 확인해줘.

5. 예약 시각과 실제 주문 설정은 바꾸지 마.

6. 원본과 비교해 어떤 보조 시스템이 더 필요한지 세 가지로 정리해줘.

schedule은 구조를 읽는 용도입니다. 수업 중에는 켜지 않고 한 번 실행하는 명령만 사용합니다.
