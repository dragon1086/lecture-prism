# 강사용 실습 진행 키워드

- 용도: 슬라이드 발표 중 빠른 확인용
- 운영: 파트 3·4 각각 120분 = 핵심 90분 + 질문·오류·개별 지원 30분
- 진행: 슬라이드 → 키워드 → 프롬프트 번호 → 실행 증거
- 수강생: 프롬프트 파일에서 강사가 부른 블록 하나만 복사
- 발표 원칙: 추천 종목 맞히기보다 판단 생성·검증·기록

## 강사용 에이전트 설정 카드

- 모델: `gpt-5.6 luna`
- 추론: `extra high`
- 속도: `fast`
- 한국어: `fluent-korean`
- 긴 결과: `docs/lecture-prism-output-style.md` → `reports/interactive/`

## 공통 안전선

- `mock`: API 키 없는 첫 성공
- `simulation`: 실제 주문 없음
- `real_data`: 실패 시 `mock` 폴백
- `research`: 선택 연결, 실패 시 기본 보고서
- BUY 의견 ≠ 주문
- 점수·목표가·손절가: 코드 규칙
- LLM: 정성 설명 + HOLD veto만
- 실거래: `LECTURE_ENABLE_LIVE_BROKER` + `LECTURE_ALLOW_REAL_BROKER` + 사람 승인 + 별도 E2E
- 오류·네트워크 실패·로그인 실패: 숨기지 않고 폴백 증거로 확인
- 시크릿·토큰·계좌번호·웹후크 URL: 화면·채팅·로그에 노출 금지

## 용어 카드

| 강의어 | 기술어 | 기억할 뜻 |
|---|---|---|
| 연습 데이터 | `mock` | 고정된 재현용 데이터 |
| 가상 체결 | `simulation` | 주문 없는 판단 기록 |
| 작업 흐름 | `pipeline` | 후보 → 분석 → 매매 → 피드백 |
| AI 작업 도우미 | `agent` | 조사·수정·검증 담당 |
| 글 읽는 AI | `LLM` | 뉴스·설명 요약 |
| 로그인 연결 | `OAuth` | API 키 대신 공식 로그인 |
| 실데이터 | `real_data` | 실제 자료, 실패 시 폴백 |
| 판단 알림 | `Discord` | 계좌 정보 없는 실행 요약 |
| 기본 경로 | `fallback` | 실패 뒤 연습 경로 복귀 |
| 매수 보류 권한 | `HOLD veto` | 불확실할 때 BUY를 HOLD로 낮춤 |

- 강사용 깨끗한 시연 폴더·Python 3.10+·프로젝트 `.venv`
- `requirements.txt` 설치 여부 확인
- P3-01: `005930`·`real_data + Discord + simulation` 한 번 점검
- 경로 분기: 실데이터·Discord까지 포함해 전체 흐름 / 준비되지 않은 수강생은 Discord 없이 연습 데이터
- 실패 전환: `mock + simulation`
- P3-M2: 실제 LLM 성공 결과와 읽기 전용 증거 준비
- KIS: 가격·일별 투자자 수급만 읽기, 주문 계열 호출 0회
- 첫 화면: 실데이터·Discord 증거 또는 mock 증거
- 실제 전송 성공 건수와 실패 원인 기록
- 수업 중 설치·로그인·대기 금지

### 리허설 프롬프트 1 · 강사와 수강생의 첫 전체 실행 경로 점검

```text
컨텍스트: 강사용 깨끗한 시연 폴더에서 P3-01 첫 전체 실행을 점검하는 리허설이야. 준비 상태와 mock 폴백만 확인해.

lecture-prism 강사용 시연 폴더에서 P3-01 첫 전체 실행을 수업처럼 한 번 점검해 줘.

조건:
1. API 키·증권사 인증 파일·기존 계좌 설정은 읽거나 만들거나 바꾸지 마. `.env`가 있더라도 웹후크 주소는 화면이나 답변에 출력하지 마.
2. 패키지를 설치하거나 설정 파일을 바꾸지 말고, yfinance와 기존 Discord 설정이 모두 준비되어 있는지만 확인해 줘.
3. 둘 다 준비되어 있으면 Yahoo Finance와 Discord에 필요한 범위 제한 네트워크 승인을 먼저 요청해 줘. 전역 샌드박스를 끄거나 권한을 통째로 우회하지 마. 별도 DNS·HTTP 점검을 반복하지 말고, 승인된 뒤에만 `real_data` 프로필, `005930 한 종목`, `dry-run`으로 `main.py` 다섯 단계 전체 흐름을 한 번 실행해 줘. 후보 확인 → 종목별 분석 → 매매 판단 → 판단 요약 → 피드백 저장 알림이 이어지는지 확인해 줘.
4. 네트워크 권한 미승인·DNS 실패·Yahoo 429·Discord 실제 전송 실패가 나면 자동으로 다시 시도하지 마. 실패 원인을 하나로 구분한 뒤 `LECTURE_PROFILE=mock`, `LECTURE_NOTIFY_DISCORD=0`으로 외부 연결을 끈 mock + simulation 경로를 한 번 완주해 줘.
5. 스크리닝 → 분석 → 매수 시나리오 → 시뮬레이션 매매 → 피드백·저장이 모두 끝나는지 확인해 줘.
6. 데이터 원천이 `실데이터(yfinance)`인지 `mock`인지, Discord 실제 전송 성공 건수와 실패 원인, 실제 주문·브로커 API 호출이 0회임을 로그로 확인해 줘. 예정된 알림 순서와 실제 도착을 같은 뜻으로 말하지 마.
7. 성공하면 선택한 경로, 후보 종목, 추천·점수, 시뮬레이션 체결 수, Discord 실제 전송 성공 건수만 짧게 정리해 줘.
8. 실패하면 .env·시크릿·브로커를 건드리지 말고 mock으로 전환한 이유와 수업에서 읽을 증거만 알려 줘.
```

### 리허설 프롬프트 2 · 강사 전용 선택 연구 확인과 첫 화면 증거 만들기

```text
컨텍스트: 강사가 수업 전에 research와 공식 Codex OAuth 결과를 준비하는 리허설이야. 한 종목만 보고 성공·폴백·실패를 구분해.

lecture-prism 강사용 시연 폴더에서 실데이터와 공식 Codex OAuth 분석을 수업 전에 안전하게 점검해 줘.

조건:
1. 실제 주문·브로커 API·KIS/키움/토스 설정은 절대 읽거나 호출하거나 바꾸지 마. 모든 매매는 simulation으로 유지해.
2. 먼저 Yahoo Finance 연결에 필요한 범위 제한 네트워크 승인을 요청해 줘. 전역 샌드박스를 끄거나 권한을 통째로 우회하지 마. 승인이 끝난 뒤 삼성전자 005930 한 종목만 real_data로 한 번 분석해 줘. yfinance 실제 데이터 성공인지 mock 폴백인지 source와 기준일·현재가를 구분해 알려 줘.
3. 그 다음 공식 Codex CLI의 로그인 상태만 사용해 research + oauth로 같은 종목을 한 번 분석해 줘. 이 단계는 `codex exec`가 기존 로그인 상태를 읽을 수 있도록, 코딩 에이전트가 이번 research + oauth 실행에만 쓰는 **승인된 외부 실행**을 한 번 요청한 뒤에 진행해. 전역 샌드박스를 끄거나 권한을 통째로 우회하지 마. `codex exec`를 따로 점검하거나 여러 번 실행하지 말고, main.py의 단일 종목 흐름 안에서만 쓰게 해. 토큰·인증 파일은 읽거나 출력하거나 복사하지 마. Perplexity와 Firecrawl은 사용하지 마.
4. Yahoo 429·네트워크 권한 미승인·DNS·Codex CLI 호출 오류가 나면 자동으로 다시 시도하지 말고, 실제 LLM 호출 성공인지 규칙 폴백인지 로그로 구분해 데이터 원천·추천·매수점수·목표가·체결 수를 정리해 줘. 응답 형식 불일치나 섹션별 규칙 폴백은 호출 실패가 아니므로, 그 사실만 기록하고 실행을 다시 시작하지 마.
5. 실제 LLM이 정량 점수·목표가·손절가를 올릴 수 없고 HOLD veto만 할 수 있는지 결과와 코드 경계를 함께 확인해 줘.
6. yfinance 데이터 조회 또는 Codex CLI 호출 자체가 실패했을 때만 원인을 짧게 기록한 뒤 .env를 남기지 않는 mock 시뮬레이션으로 즉시 한 번 완주해 줘. 응답 형식 불일치나 규칙 폴백만으로는 mock을 추가 실행하지 마. 이 경우 실데이터 research 결과를 그대로 기록하고, 강사용_첫화면_연구증거.txt에 실제 LLM 호출 성공과 섹션별 규칙 폴백을 나눠 적어 줘. mock을 실행했을 때만 생성된 mock 보고서 옆에 강사용_첫화면_mock증거.txt를 만들어, mock 데이터·규칙 폴백·추천·매수점수·목표가·체결 수만 8줄 이내로 적어 줘.
7. 성공한 research 보고서는 강사용 로컬 reports/에만 남기고 Git에 추가하지 마. 같은 폴더에 강사용_첫화면_연구증거.txt도 만들어, 데이터 원천·실제 LLM 성공 또는 규칙 폴백·추천·매수점수·목표가·체결 수만 8줄 이내로 적어 줘. 토큰·계좌·긴 로그는 넣지 마.
```

```text
- 이동평균·수익률 같은 결정적 계산은 Python 규칙, 주도 업종·뉴스 위험 같은 문맥 설명만 AI에 두고, 강세·횡보·약세 fixture로 진입 문턱과 최대 보유 수 차이를 검증해.
- P4-D3.md의 market_condition 경로 표에는 생성 파일·반환 필드·전달 함수·소비 지점을 적고, 강세·횡보·약세별 실제 fixture 결과를 붙여.

P4-D4 · DART RSS
- DART는 추가 데이터 소스를 검토하는 예시다. API 키가 필요하지 않은 회사별 공시 RSS를 읽고, 외부 응답을 그대로 LLM에 넘기지 않는 가장 작은 품질 게이트를 만든다. 수집 목적은 `최근 공시 가운데 시연 종목의 실적·자금조달·지배구조 판단에 직접 필요한 사실 확인`이다.
- 새 패키지 없이 `urllib.request`로 HTTPS GET을 딱 한 번만 보내고 타임아웃은 5초로 둬. `xml.etree.ElementTree`로 title·link·pubDate만 파싱해. 자동 재시도, 로그인, 임의 크롤링, 유료 본문 저장, OpenDART API와 API 키는 범위 밖이다.
- HTTP 실패·타임아웃·XML 파싱 실패와 `Service Unavailable` 같은 통신 오류 문구는 자료가 아니다. 실제 RSS가 실패하거나 항목이 달라졌다면 자동 재시도하지 말고 `lecture/fixtures/dart-samsung-company-rss.xml`로 같은 검토 과정을 재현해. 결과에는 `실제 RSS / 재현용 fixture` 중 어느 경로를 썼는지 표시해.
- 후보는 최대 10건까지만 읽고 다음 순서로 거른다. ① 대상 회사 일치 ② 수집 목적과 관련 있는 제목 ③ 작성일·공식 출처 존재 ④ 유효기간 안 ⑤ 같은 link 또는 정규화한 title 중복 제거. 관련성이 애매하면 LLM에 넘기지 말고 `needs_review`로 분리해.
- RSS 제목을 핵심 주장으로 꾸며내지 마. title·link·pubDate로 확인되는 사실만 적고, 원문 확인이 필요한 해석은 `needs_review`로 남겨. 확인된 주장이 없으면 LLM에 넘긴 자료가 0건이어도 성공이다. 최종 분석 입력은 관련도 높은 최대 3건, 건별 구조화 요약 300자 이내로 제한하고 원문 전체는 넘기지 마.
- P4-D4.md에는 `사용 경로 / 수집 건수 / 정상 응답 건수 / 포함 / 제외 / 검토 필요 / LLM에 넘긴 자료 수`를 먼저 적어. 이어 각 항목을 왜 포함하거나 제외했는지, 무엇을 더 확인해야 하는지 표로 남겨.

마지막에는 D1~D4별 상태를 `완료 / 폴백으로 검증 / 다음 작업`으로 나누고, 바꾼 파일·수정 전후 결과·실행한 검증을 한 표로 요약해.
```
