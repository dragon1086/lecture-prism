# 강사용 실습 진행 스크립트

> 파트 3·4는 각각 120분입니다. **핵심 90분 + 질문·오류·개별 지원 30분**으로 운영합니다.
> 이 문서는 강사 전용 로컬 자료입니다. 수강생은 [파트 3 프롬프트](../lecture/exercises/수강생_붙여넣기_프롬프트_파트3.md), [파트 4 프롬프트](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md)에서 강사가 부르는 번호 하나만 복사합니다.

## 이 강의의 한 문장

> 비전공자도 **내 투자 북극성을 한 문장으로 말하고, AI에게 한 파일의 한 규칙으로 구현하게 한 뒤, 바뀐 결과의 근거를 읽을 수 있다.**

이 수업은 수익률 경연이나 실계좌 연결 수업이 아니다. 사람은 전략과 책임을 정하고, 코딩 에이전트는 조사·수정·검증을 돕는다. 수강생은 명령어 암기 대신 아래의 학습 루프를 반복한다.

1. **질문한다.** “내 북극성에서 지금 무엇을 검증하려는가?”
2. **예측한다.** “이 프롬프트가 무엇을 바꾸고, 무엇은 건드리지 않을까?”
3. **작게 실행한다.** 한 번에 프롬프트 하나, 파일 하나, 규칙 하나만 다룬다.
4. **증거를 읽는다.** 로그·표·바뀐 코드 차이(diff)·테스트 중 하나를 찾는다.
5. **회고한다.** “내 전략 → 바꾼 파일 → 달라진 결과”를 한 문장으로 말한다.

이 다섯 단계를 매번 소리 내어 짧게 반복한다. “이해되셨죠?” 대신 “이걸 내 전략의 어디에 쓸 수 있을까요?”, “실행 전 무엇이 나올 것 같나요?”를 묻는다.

## 말부터 쉽게 맞추기

| 강의에서 먼저 쓰는 말 | 필요한 경우의 기술 용어 | 강사 설명 |
|---|---|---|
| 연습 데이터 | mock | 오늘 시장이 아니라, 같은 결과를 다시 확인하도록 준비한 고정 연습 재료 |
| 가상 체결 | simulation | 증권사에 주문을 보내지 않고 ‘이 조건이면 샀을 것’을 남기는 연습 |
| 작업 흐름 | pipeline | 후보 찾기 → 자료 읽기 → 가상 판단 → 기록 남기기의 순서 |
| AI 작업 도우미 | agent | 조사·코드 수정·검증을 역할별로 돕는 AI |
| 글과 자료를 읽는 AI | LLM | 뉴스·설명처럼 정답 하나가 없는 문맥을 요약하는 AI |
| 구독 계정 로그인 | OAuth | API 키 대신 공식 도구의 로그인 상태를 쓰는 선택 연결 방식 |
| 기본 경로로 돌아감 | fallback | 선택 연결이 실패해도 연습 데이터 경로로 수업을 계속하는 설계 |
| 매수 보류 권한 | HOLD veto | LLM이 불확실하면 BUY를 HOLD로 낮출 수만 있는 안전 권한 |

## 강사가 계속 지킬 안전 문장

다음 세 문장을 파트마다 한 번씩 반복한다.

> 매수 에이전트의 BUY는 실제 주문이 아닙니다. 오늘 모든 매매는 가상 체결입니다.
>
> 점수·목표가·손절가는 코드 규칙이 정합니다. LLM은 설명을 보태고 불확실하면 HOLD를 제안할 수만 있습니다.
>
> 오류·실데이터 실패·로그인 실패는 감출 일이 아닙니다. 연습 데이터로 돌아가는 것도 설계가 제대로 작동한 증거입니다.

## 수업 전 공통 준비

### 수강생 사전 준비

수업 시작 10분 전에 [수업 시작 전 안내](수업_시작_전_안내.md)를 LMS와 강의 채팅에 배포한다. 수강생은 Codex 또는 Claude Code 로그인 뒤에 안내의 프롬프트로 공개 `lecture-prism` 저장소를 복제한다. GitHub 계정은 공개 저장소 복제에 필요하지 않으므로, 계정 생성·GitHub 로그인·Python 실행·패키지 설치를 수업 시작 조건으로 만들지 않는다.

수업이 시작되면 수강생의 작업창에는 이미 `lecture-prism`이 열린 상태여야 한다. 복제가 막힌 수강생은 오류 화면을 그대로 두고, 강사가 순회하며 사전 안내 프롬프트를 다시 쓰게 한다.

1. 강사용 시연 폴더는 수강생과 같은 깨끗한 복사본으로 준비한다. 기본 상태는 `.env` 없이 연습 데이터(mock)가 돌아가는 상태다.
2. 강사용으로만 `real_data`와 공식 Codex OAuth `research`를 수업 전에 한 번 점검한다. 실패하면 mock 결과로 즉시 전환할 수 있게 한다.
3. KIS 실제 키·계좌번호·로그인 세션은 강의 화면 및 공유 자료와 분리한다. 수업에서는 외부 주문을 보내지 않는다.
4. 강사용 첫 화면에는 research 성공 증거 또는 mock 증거 하나만 준비한다. 수업 중에는 OAuth·패키지 설치를 기다리지 않는다.

```text
조건:

3. 스크리닝 → 분석 → 시뮬레이션 매매 → 피드백·저장이 모두 끝나는지 확인해줘.
4. 데이터 원천이 mock이고, 실제 주문·브로커 API 호출이 0회임을 로그로 확인해줘.
5. 성공하면 후보 종목, 추천·점수, 시뮬레이션 체결 수, 보고서 저장 여부만 짧게 정리해줘.
6. 실패하면 .env·시크릿·브로커를 건드리지 말고 원인과 mock으로 돌아가기 위한 최소 조치만 알려줘.
```

### 리허설 프롬프트 2 · 강사 전용 실데이터·OAuth 확인과 첫 화면 증거 만들기

```text
lecture-prism 강사용 시연 폴더에서 실데이터와 공식 Codex OAuth 분석을 수업 전에 안전하게 점검해줘.

조건:

2. 먼저 삼성전자 005930 한 종목만 real_data로 분석해줘. yfinance 실제 데이터 성공인지 mock 폴백인지 source와 기준일·현재가를 구분해 알려줘.
3. 그 다음 공식 Codex CLI의 로그인 상태만 사용해 research + oauth로 같은 종목을 한 번 분석해줘. 토큰·인증 파일은 읽거나 출력하거나 복사하지 마. Perplexity와 Firecrawl은 사용하지 마.
4. research에서 실제 LLM 호출 성공인지 규칙 폴백인지 로그로 구분하고, 데이터 원천·추천·매수점수·목표가·체결 수를 정리해줘.
5. 실제 LLM이 정량 점수·목표가·손절가를 올릴 수 없고 HOLD veto만 할 수 있는지 결과와 코드 경계를 함께 확인해줘.
6. real_data 또는 OAuth가 실패하면 원인을 짧게 기록한 뒤 .env를 남기지 않는 mock 시뮬레이션으로 즉시 한 번 완주해줘. 생성된 mock 보고서 옆에는 강사용_첫화면_mock증거.txt를 만들어, mock 데이터·규칙 폴백·추천·매수점수·목표가·체결 수만 8줄 이내로 적어줘.
7. 성공한 research 보고서는 강사용 로컬 reports/에만 남기고 Git에 추가하지 마. 같은 폴더에 강사용_첫화면_연구증거.txt도 만들어, 데이터 원천·실제 LLM 성공 또는 규칙 폴백·추천·매수점수·목표가·체결 수만 8줄 이내로 적어줘. 토큰·계좌·긴 로그는 넣지 마.
```

### 선택 준비 · 강사용 Discord 판단 알림

Discord 알림은 수강생 준비물이 아니다. 강사가 원본 운영 흐름을 보여 주고 싶을 때만 비공개 테스트 채널에서 시연한다. 이 알림에는 계좌번호나 잔고가 아니라, 방금 실행한 스크리닝 결과와 AI 판단 근거만 나온다.

1. Discord에서 강의용 서버의 **서버 설정 → 연동 → 웹후크**로 들어간다.
2. **새 웹후크 만들기**를 누르고, 메시지를 받을 비공개 채널을 고른다. 채널 이름은 `#prism-test`처럼 수업 시연용이라는 사실이 드러나게 정한다.
3. **웹후크 URL 복사**를 누른다. 이 주소만 있으면 채널에 메시지를 보낼 수 있으므로, 강의 채팅·슬라이드·화면 공유·Git에 노출하지 않는다.
4. 강사용 `lecture-prism` 폴더의 로컬 `.env`를 직접 열어 아래 두 줄을 넣는다.

```env
LECTURE_NOTIFY_DISCORD=1
DISCORD_WEBHOOK_URL="복사한 웹후크 주소"
```

5. 주소는 코딩 에이전트에게 붙여넣지 않는다. `.env`에 넣은 뒤 아래 프롬프트만 전달한다.

```text
lecture-prism의 Discord 판단 알림을 mock으로 한 번 점검해줘.

조건:
1. .env의 DISCORD_WEBHOOK_URL 값을 읽어서 화면이나 답변에 출력하지 마.
2. 실제 주문·브로커 API·실데이터·OAuth는 사용하지 말고 mock + simulation으로만 실행해.
3. 이번 확인에서는 새 보고서 파일을 만들지 마.
4. 스크리닝 → 종목별 분석 → 매매 판단 → AI 판단 요약 순서로 Discord에 도착하는지 확인해.
5. 메시지와 로그에 계좌번호·잔고·브로커 인증값·웹후크 주소가 들어가지 않는지 확인해.
6. Discord 전송이 실패해도 파이프라인 4단계가 끝까지 실행되는지 함께 확인해.
7. 검증이 끝나면 실제 주문 0건, Discord 성공·실패 건수, 파이프라인 완료 여부만 짧게 알려줘.
```

기본 연습 데이터에서는 후보 세 종목이 나온다. 정상이라면 스크리닝 1건, 종목별 분석 3건, 매매 판단 3건, 마지막 요약 1건이 차례로 도착한다. 기존 매매일지가 있으면 매매 판단이 BUY가 아니라 ‘이미 보유 중, 추가 매수 보류’로 나올 수 있다.

**강사가 읽을 말**

> Discord에 온 것은 계좌 알림이 아니라 이번 실행의 판단 기록입니다. 후보를 왜 골랐는지, 종목별로 무엇을 봤는지, 마지막에 BUY·SELL·HOLD·PASS 중 어떤 판단을 했는지만 보냅니다.
>
> 알림이 꺼지거나 전송에 실패해도 분석과 매매 판단은 멈추지 않습니다. 반대로 알림이 왔다고 실제 주문이 나간 것도 아닙니다. 판단, 주문, 알림은 서로 다른 경로입니다.

```text
진행 방식:

3. 위 두 파일이 없거나 증거가 불충분하면 research를 새로 실행하지 마. 미리 준비한 mock 보고서와 강사용_첫화면_mock증거.txt를 찾아 열고, 없으면 “첫 화면용 자료 준비가 필요하다”고 짧게 알려줘.
4. 화면에는 ① 데이터 원천, ② 실제 LLM 성공 또는 규칙 폴백, ③ HOLD/BUY/PASS·매수점수·목표가, ④ 체결 수만 남겨. 토큰·인증 파일·계좌 정보·긴 로그는 보이지 않게 해.
5. 화면 준비가 끝나면 강사가 40초 안에 읽을 수 있는 멘트를 써줘. 반드시 “점수·목표가·손절가는 규칙이 정하고, LLM은 정성 설명과 HOLD veto만 맡는다”, “수강생은 지금 로그인하거나 계좌를 연결하지 않는다”를 포함해.
```

# 파트 3 · 원본을 해체하고, 강의용 축소판을 직접 돌린다

- PRISM Insight의 스크리닝·종목분석·매매·피드백을 서로 다른 책임으로 설명한다.
- `lecture-prism`에서 각 책임을 맡는 파일을 찾아 단독 실행한다.

- 자동매매에는 본체 외에도 예약 실행·보유종목 감시·주문 대사·메모리 압축이 필요하다고 설명한다.
- 모든 실습을 연습 데이터와 가상 체결로 끝낸다.

## 0–5분 · 왜 자동매매를 배우려는지 연다

**화면:** P3-S01–S03. 계좌·로그인 화면은 열지 않는다.

## 25–40분 · 모듈 1 — 시장을 읽고 후보를 세 종목으로 줄인다

**화면:** P3-S07–S13.

**문제 먼저**

> 어제는 강세장, 오늘은 약세장입니다. 후보를 같은 기준으로 골라도 될까요?

**20초 예상:** ‘같은 기준으로 고른다 / 기준을 바꾼다’ 중 하나를 고르고 이유를 한 문장으로 적게 한다.

**그림 출처:** P3-S07–S11은 `PIPELINE_ARCHITECTURE_ko.md`의 스크리닝
원본 그림이다. P3-S12–S13에서만 Lecture-prism의 축소 구현과 실행 방법을
설명한다.

**설명 순서**

1. 3상태 Market Pulse와 분산일 상태 전이
2. 분석 배치용 3상태와 후보 재정렬용 5상태의 차이
3. 오전·오후 여섯 트리거
4. 공통 하한과 시장별 재점수
5. 원본과 `screening.py` 비교

**읽을 말**

> 원본은 종목부터 보지 않습니다. 대표지수와 분산일로 만든 3상태 Market Pulse는 오전·오후 분석 배치를 실행할지 정합니다. 이 판단과 별도로 5상태 시장 체제는 후보 점수 비중과 주도 업종 자리를 정합니다. 오전에는 거래량 급증·갭 상승·집중 자금, 오후에는 일중 상승·마감 강도·거래량이 늘어난 횡보를 찾습니다.
>
> 후보를 합친 뒤에도 끝이 아닙니다. 처음 발견한 조건 점수, 예상 손익비, 후보군 상대강도, 20일선 과열도를 시장 체제별 비중으로 합쳐 보통 최대 세 종목을 남깁니다.
>
> 강의용 `screening.py`는 연습 종목 일곱 개에서 거래량·시가총액·상승 여부를 검사하고 등락률 순으로 세 종목을 남깁니다. 시장 상태와 여섯 트리거는 아직 없습니다. 복제품이 아니라 ‘넓게 찾고 규칙으로 좁힌다’는 핵심을 남긴 축소판입니다.

**수강생 행동:** 프롬프트 파일에서 [P3-M1](../lecture/exercises/수강생_붙여넣기_프롬프트_파트3.md#p3-m1--screeningpy-구조를-묻고-실행하기)의 코드 블록 전체를 복사해 한 번 붙여넣는다. 원본 PRISM 비교는 시키지 않는다.

**증거 공개:** 연습 종목 7개 가운데 현대차는 등락률이 +4.2%로 가장 높지만 거래량이 평소의 3.6배라 5배 기준을 통과하지 못한다. 삼성전자·SK하이닉스·NAVER 세 종목이 남는다. 많이 오른 종목과 내 규칙을 통과한 종목은 다르다는 예시다.

**60초 짝 대화:** P3-M1 마지막 질문 세 개 중 하나를 골라 자기 전략에 대입해 말한다. 시간이 부족하면 전체 공유는 생략해도 짝 대화는 남긴다.

**수강생 판단 뒤 lecture-prism 기준선**

> 우리 연습 코드는 거래량 5배·시가총액 5,000억·상승 여부를 함께 봅니다. 이 조건을 통과한 종목은 등락률이 높은 순서로 최대 세 종목만 남깁니다. 거래량 기준처럼 전략에 가까운 숫자는 바꿔 볼 수 있지만, 후보 수 제한과 연습 데이터 폴백은 안전장치로 남겨 두는 편이 좋습니다. 수강생의 답이 이 기준과 달라도 오답은 아닙니다. 무엇을 바꿀지 말할 수 있으면 적용이 시작된 것입니다.

**강사가 선을 그을 말**

> 오늘은 구조 확인과 단독 실행까지만 합니다. 숫자를 바꾸는 실험은 파트 4에서 전후 결과를 비교하며 진행합니다.

**읽을 말**

>

**수강생 행동:** 프롬프트 파일에서 [P3-M2](../lecture/exercises/수강생_붙여넣기_프롬프트_파트3.md#p3-m2--여섯-보고서-에이전트를-묻고-실행하기)의 코드 블록 전체를 붙여넣는다. 이 시점에는 보고서가 어떻게 나뉘는지만 확인한다.

## 55–75분 · 모듈 3 — 진입·증액·청산을 별도 매매 책임으로 둔다

**화면:** P3-S21–S30.

**그림 출처:** P3-S22–S27은 `PIPELINE_ARCHITECTURE_ko.md`의 매매·보호
원본 그림이다. Lecture-prism의 전체 보조 운영 그림은 파트 3을 닫는
P3-S37에서 한 번만 보여 준다.

**문제 먼저**

> AI가 사라고 하면, 그대로 주문해도 될까요?

**20초 예상·A/B 투표:** P3-S21의 `BUY 8점`, 현재가 70,000원, 목표가 77,000원, 손절가 63,000원, 손익비 1.0을 보여 준다. 코드의 최소 손익비는 1.5다. `A 주문한다 / B 보류한다` 중 하나에 손을 들게 하고, 이유는 아직 받지 않는다.

**읽을 말**

> 이제 CAN SLIM이 나옵니다. 원본 매매 시나리오는 기업·수급·주도주·시장 조건을 확인하고, 가격과 거래량이 함께 맞을 때 신규 진입을 허용합니다. 수익이 난 뒤에는 한 번에 몰아 사지 않고 피라미딩 조건으로 증액합니다.
>
> 청산은 순서가 중요합니다. 기계적 손절과 트레일링 스탑을 먼저 확인하고, 그다음 시나리오 판단을 참고합니다. 목표가는 수익을 보장하는 버튼이 아니라 점검할 이정표입니다.
>
> 강의용 `buy_agent.py`가 완성된 보고서를 읽고 Enter / No Entry, 점수, 목표가, 손절가를 포함한 시나리오를 만듭니다. LLM은 규칙 숫자를 바꾸거나 미진입 후보를 억지로 올릴 수 없습니다. 그 뒤 `trading.py`가 가격 배열·손익비·보유 수·현금 한도를 다시 확인하고 수량을 계산합니다.
>
> 자동매매는 장 시작 때 한 번 실행했다고 끝나지 않습니다. `operations.py`가 분석 배치, 보유종목 감시, 미체결 주문 대사를 각각 한 번씩 실행할 수 있게 했습니다. 수업에서는 예약 실행을 켜지 않고, 안전한 일회성 명령만 봅니다.

**수강생 행동:** 프롬프트 파일에서 [P3-M3](../lecture/exercises/수강생_붙여넣기_프롬프트_파트3.md#p3-m3--tradingpy와-운영-루프를-묻고-실행하기)의 코드 블록 전체를 붙여넣는다. 이제 처음으로 `buy_agent.py`의 의견과 `trading.py`의 주문 전 안전 조건을 함께 확인한다.

**증거 공개:** 테스트에서는 BUY 8점이어도 손익비가 1.0이면 주문을 만들지 않는다. HOLD라면 점수가 10점이어도 주문을 만들지 않는다. `trading.py --exit`은 손절·트레일링 스탑·목표가 도달을 서로 다른 청산 결과로 보여 준다.

**내 안전선 한 문장:** 주문 0건을 확인한 뒤 “내 전략에서는 AI가 사라고 해도 ___이면 주문하지 않는다”를 각자 채우게 한다. 두세 명에게 한 문장만 읽어 달라고 한다.

**수강생 판단 뒤 lecture-prism 기준선**

> 우리 코드의 진입 기준은 BUY 의견, 6점 이상, 목표가 > 현재가 > 손절가, 손익비 1.5 이상입니다. 여기에 남은 현금과 자리, 이미 보유한 종목인지, 끝나지 않은 주문이 있는지도 확인합니다. 청산은 손절 → 트레일링 스탑 → 목표가 순서입니다. 체결 상태가 불분명하면 같은 종목의 새 주문을 만들기 전에 `reconcile`로 기존 주문 상태부터 다시 읽습니다.

**안전 확인**

- 모든 체결은 `simulation`
- `operations.py reconcile`은 조회만 하며 주문을 만들지 않음
- 예약 루프는 `LECTURE_ENABLE_SCHEDULER=1` 없이는 시작되지 않음

## 75–90분 · 모듈 4 — 결과를 교훈으로 만들고, 기억을 압축한다

**화면:** P3-S31–S38.

**문제 먼저**

> 어제 손절한 종목이 오늘 다시 떴습니다. 다시 사도 될까요?

**20초 예상:** `바로 다시 산다 / 하루 더 본다 / 조건을 다시 확인한다` 중 하나를 고르고 이유를 한 문장으로 적게 한다.

**그림 출처:** P3-S31은 원본 PRISM의 매매일지·교훈·재진입 흐름이다.
P3-S33은 실제 서버의 압축 배치와 Lecture-prism의 메모리 계층을 함께
설명하기 위해 새로 만든 보조 그림이다.

**읽을 말**

> 매수 직후에는 아직 성공도 실패도 알 수 없습니다. 그래서 강의용 피드백은 BUY 기록만으로 억지 교훈을 만들지 않습니다. SELL로 결과가 닫혔을 때 분석과 체결을 연결해 교훈을 남깁니다.
>
> 교훈을 계속 쌓기만 하면 프롬프트가 길어지고 오래된 예외가 판단을 방해합니다. `memory.py`는 최근 교훈을 단기 기억으로 두고, 시간이 지난 교훈을 중기로 옮기며, 반복된 패턴만 장기로 승격합니다. 장기 기억도 개수를 제한합니다.
>
> 실제 운영 서버에서는 한국 시장 분석이 평일 오전 9시 30분과 오후 2시 46분에 돌고, 메모리 압축은 일요일 새벽 3시에 실행됩니다. 강의용은 이 아이디어를 표준 라이브러리와 SQLite만으로 작게 재현했습니다.
>
> 기억은 많이 쌓는 것보다 쓸 만하게 유지하는 게 중요합니다. 같은 종목의 최근 교훈은 먼저 참고하고, 서로 다른 거래에서 반복된 교훈만 장기 원칙으로 압축합니다. 오래된 기록은 중기 요약으로 옮기고, 한도를 넘는 약한 장기 원칙은 다음 판단에서 빼둡니다.

**수강생 행동:** 프롬프트 파일에서 [P3-M4](../lecture/exercises/수강생_붙여넣기_프롬프트_파트3.md#p3-m4--피드백과-메모리-압축을-묻고-실행하기)의 코드 블록 전체를 붙여넣는다. 거래 결과가 닫힌 뒤의 기록과 압축만 확인한다.

**증거 공개:** BUY 체결은 거래 기록만 남기고 결과 교훈을 만들지 않는다. SELL로 거래가 끝나야 단기 교훈이 생긴다. 서로 다른 두 종목에서 같은 교훈이 반복되면 하나의 장기 원칙으로 압축한다.

**재진입 선택 공유:** 세 선택지별로 한 명씩 이유를 읽게 한다. 그다음 P3-M4 마지막 질문 가운데 반복 실수 기준이나 버릴 일회성 상황 하나를 자기 전략에 대입해 적게 한다.

**수강생 판단 뒤 lecture-prism 기준선**

> 강의용 구현은 BUY 직후에는 교훈을 만들지 않고 SELL로 거래가 닫힌 뒤 단기 교훈을 남깁니다. 같은 실행에서 방금 청산한 종목은 다시 사지 않지만, 어제 손절했다는 이유만으로 다음 날 자동으로 매수를 막는 규칙은 아직 없습니다. 단기 교훈은 7일이 지나면 중기로 옮기고, 30일이 지난 중기 교훈 가운데 같은 내용이 두 번 이상 반복될 때 장기 원칙으로 만듭니다. 장기 원칙은 최대 20개만 유지하고 다음 판단에는 관련 기억을 최대 5개만 넣습니다. 다만 아직 처음 계획과 실제 수익률과 청산 사유까지 깊게 비교하지는 않습니다. 일회성 상황을 뜻으로 판별하는 기능도 없습니다. 이 질문들은 현재 기능을 외우라는 뜻이 아니라, 수강생이 다음에 보완할 기준을 정해 보라는 질문입니다.

**마지막 적용**

> 내 전략에서 ___을 먼저 바꿔 보고 싶다. 이유는 ___이다.

후보 조건·분석 역할·진입과 청산·기록과 운영 중 하나를 고르게 한다. 이 문장을 한 번 입으로 말한 뒤 질문을 받는다.

**강사 행동:** [P4-00](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-00--먼저-시스템-지도를-ai에게-묻기)를 부른다. 실행 전에는 코드를 바꾸지 않는 프롬프트임을 강조한다.

## 20–32분 · 원본 운영에서 배울 것은 ‘정답’이 아니라 추적 가능성이다

**화면:** `시장 펄스`, `진입 게이트`, `AI 코드 안전장치` 이미지.

**읽을 말**

> 원본 시스템은 시황을 보고 후보를 다시 정렬하고, 여러 게이트를 통과시키고, AI가 만든 코드에도 안전장치를 둡니다. 비전공자에게 중요한 것은 이 수식을 전부 외우는 것이 아니라, ‘어떤 입력이 어떤 판단을 바꿨는지’와 ‘막혔을 때 어디를 볼지’를 아는 것입니다.

**강사 예시:** Q5(시장 상태별 위험), Q16·Q17(지표가 많아도 최종 게이트가 필요함), Q23(분업)을 연결한다.

## 45–55분 · 강사 작업 예시: 한 파일, 한 규칙, 전후 증거

**화면:** `진입 게이트`, `피라미딩`, `청산`, `매도 메시지` 이미지.

**읽을 말**

**선택 1 — Q3, 트랙 A:** [P4-03](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-03--트랙-a-후보-선별-규칙)으로 `screening.py`의 후보 조건만 본다. “기준을 낮추면 후보는 늘어날까?”를 먼저 예측하고, 전후 후보 표를 본다.

## 85–95분 · 강사 시연: 오전·오후 예약은 ‘24시간 떠 있는 프로그램’이 아니다

**화면:** `시장 펄스`, `후보 재정렬`, `피드백 재진입` 이미지.

**읽을 말**

> ‘24시간 돌린다’는 말은 main.py가 24시간 화면에 떠 있다는 뜻이 아닙니다. 컴퓨터나 서버가 켜져 있고, 운영체제의 예약 기능이 오전 한 번·오후 한 번 main.py를 새로 시작하는 것입니다.
>
> 한 번 실행은 사람이 시작합니다. 배치는 정해진 일을 한 번 묶어 실행합니다. 스케줄은 그 배치를 정해진 시각에 시작합니다. 대시보드는 결과를 읽는 화면이고, 서버는 이 실행과 기록을 계속 가능하게 하는 컴퓨터입니다.

**수강생 행동:** 강사 화면에서 [P4-08](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-08--오전-1회오후-1회-연습-배치-설계하기)의 설계 결과만 읽는다. 실제 예약 등록은 수업 중 하지 않는다. 수강생 개인 실행은 시간이 남을 때만 한다.

**핵심 질문:** “예약이 실패했을 때, 다시 실행하기 전에 무엇을 확인해야 할까요?”

**정답 방향:** 실행 시각, 로그, 중지 방법, 중복 실행 방지, 재시작 뒤 확인, 그리고 연습 데이터·실제 주문 없는 예행 실행 여부.

## 95–103분 · 운영 2: 다음 AI 세션에 남길 기억과 인수인계

**읽을 말**

> 기억은 한 종류가 아닙니다. MY_STRATEGY.md는 내 전략입니다. AGENTS.md나 도구별 지침은 프로젝트 공통 안전 규칙입니다. 자동 memory는 도구·컴퓨터마다 다를 수 있어 보안 규칙을 대신하지 못합니다. handoff.md는 다음 세션이 첫 5분에 읽을 작업 인수인계입니다.
>
> handoff에는 이번에 한 일, 왜 그렇게 정했는지, 확인한 증거, 남은 문제, 다음 첫 세 단계를 남깁니다. API 키·계좌·로그인 세션 같은 비밀을 적는 파일이 아닙니다.

**수강생 행동:** [P4-09](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-09--다음-ai-세션에-넘길-기억과-인수인계-만들기)를 실행한다.

## 103–110분 · 운영 3: 프레이밍을 바꾸되, 안전 규칙은 바꾸지 않는다

**읽을 말**

> LLM은 평균적인 언어 모델이라, 우리가 강조한 목표와 위험을 우선해서 설명하려 합니다. ‘손실을 피하라’만 강조하면 HOLD가 많아질 수 있습니다. 그렇다고 ‘기회를 놓치면 안 된다’로 점수·손절 규칙을 무너뜨리는 것은 아닙니다.
>
> 우리는 두 문장을 비교합니다. 하나는 손실 회피만 강조한 문장, 하나는 기회비용도 설명하되 같은 안전장치를 유지한 문장입니다. AI가 어디에 갇혔는지 진단하고, 정성 설명을 더 정확하게 만드는 연습입니다.

**수강생 행동:** [P4-10](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-10--ai가-어떤-프레이밍을-받고-있는지-진단하기)을 실행한다.

**질문:** “바뀌어도 되는 것은 설명인가요, 점수 규칙인가요? 왜인가요?”

## 110–115분 · 강사 확장: 오전 관찰과 오후 확인의 시간대 전략

**읽을 말**

> 오전에는 오늘 거래량과 일봉이 아직 만들어지는 중입니다. 그래서 오전 수치를 종가 확정값처럼 읽으면, 그럴듯하지만 잘못된 결론을 만들 수 있습니다. 오후에도 원천·기준 시각·일봉 완성 여부를 확인하지 못하면 HOLD나 다음 실행으로 미룹니다.
>
> 이것은 ‘아침에는 매수하지 말자’라는 감각 규칙이 아닙니다. 시간대를 테스트 가능한 입력으로 만들고, 오전용과 오후용 검증 예시에서 미완성 데이터를 종가로 오해하지 않는지 확인하는 설계입니다.

**수강생 행동:** 수업에서는 [P4-11](../lecture/exercises/수강생_붙여넣기_프롬프트_파트4.md#p4-11--오전-관찰과-오후-확인을-분리하는-전략-예시)의 **설계·테스트 계획만** 읽는다. 승인 없는 코드 수정이나 예약 변경은 하지 않는다.
